# Vietnamese ASR (open source) - RTX 3060 12GB + Apple Silicon, timestamps
Date: 2026-10-01. Method: HF API + raw model cards, arXiv, gh. All WER = vendor/self-reported, NOT comparable across cards (different normalization/test sets).

## Verdict (TL;DR)
- Published numbers: ChunkFormer-RNNT-Large-Vie and nvidia/parakeet-ctc-0.6b-Vietnamese (Jan 2026) beat PhoWhisper-large and whisper-large-v3 on Vietnamese. Nobody published a head-to-head vs whisper-large-v3-TURBO (only v3). v3 is the proxy: VIVOS 8.81 / CV 15.45 / VLSP20-T1 20.41 (turbo likely similar or slightly worse).
- No independent benchmark on long-form, clean-studio, dubbed podcasts. MUST test on own 10-20 min of data.
- Forums (Viblo/VOZ/Facebook): no useful signal found (see Noise).

## Candidates

### 1. nvidia/parakeet-ctc-0.6b-Vietnamese [GEM]
https://huggingface.co/nvidia/parakeet-ctc-0.6b-Vietnamese (created 2026-01-15, upd 2026-02-07)
- FastConformer-CTC 600M, ~2000h vi (CV20, VietMed, LSVSC, FLEURS, InfoRe, FOSD, VAIS, VLSP2020, VSV-1100). PnC (punct+case) generated by Qwen3 for training text -> outputs punctuation/caps.
- WER: blind AVG 9.30 (GigaSpeech2 11.23, VLSP21-T2 8.99, ViMD 11.02, VIVOS 5.96); in-domain AVG 9.73 (MCV20 8.58, FOSD 9.67, LSVSC 5.15, FLEURS 6.86, VLSP21-T1 13.60, VietMed 14.52). Card says WER excludes PnC errors.
- Timestamps: YES native (`transcribe(..., timestamps=True)` -> char/word/segment). Optional 4-gram KenLM.
- License: NVIDIA Open Model License (commercial OK), GATED (click-through, "2-3 days" text; approval may be auto). Linux-oriented, NeMo 2.6.
- Speed: CTC FastConformer = very fast (hundreds-1000x RT class on GPU; not measured for vi). 0.6B bf16 fits 3060 easily.
- Long-form: card says max length depends on GPU memory; NO built-in chunking claim. Needs own VAD/chunking (or NeMo local-attention/buffered inference). Podcast 1-5h => chunk by VAD ~30-60s.
- Ports: giangndm/parakeet-ctc-0.6b-vietnamese-bf16 (HF transformers `ParakeetForCTC`, no NeMo; upd 2026-08), OpenVoiceOS/nvidia-parakeet-ctc-0.6b-vietnamese-onnx (onnx-asr, fp32+int8, 2026-07), leakless/parakeet-ctc-0.6b-Vietnamese-coreml (CoreML, cc-by-4.0 label, validated 100% argmax agreement, 2026-02; Apple Neural Engine; community, downloads 23).
- Downloads low (292) = young, little community validation.

### 2. khanhld/chunkformer-rnnt-large-vie [GEM]
https://huggingface.co/khanhld/chunkformer-rnnt-large-vie (upd 2025-10-08) ; CTC variant khanhld/chunkformer-ctc-large-vie
- 113M params, ~3000h public vi data. ICASSP 2025 paper "ChunkFormer: Masked Chunking Conformer for Long-Form Speech Transcription" https://arxiv.org/abs/2502.14673 ; repo https://github.com/khanld/chunkformer (`pip install chunkformer`).
- WER (own table, normalized): RNNT: VIVOS 2.49, CV 5.18, VLSP20-T1 12.75, VLSP20-T2 20.47, avg 10.22. CTC: 4.18 / 6.66 / 14.09 / 25.81. PhoWhisper-large: 4.67 / 8.14 / 13.75 / 26.68. whisper-large-v3: 8.81 / 15.45 / 20.41 / 68.61 (T2 = long, noisy-ish).
- Long-form: BUILT FOR IT. README: up to 16 h audio, low-VRAM, masked batching; `total_batch_duration`, `return_timestamps=True`; 24GB = 240 min batch => 12GB ~ 120 min batch. Output example `[00:00:02.500] - [00:00:03.700]: text` (segment-level).
- License: RNNT = CC-BY-4.0 (OK commercial); CTC = CC-BY-NC-4.0 (non-commercial).
- No punctuation/casing shown in card (normalized text; assume lowercase unpunctuated - UNVERIFIED).
- Apple: PyTorch/WeNet-style; MPS/CPU works? UNVERIFIED. No CoreML/MLX port found.
- Issue: https://github.com/khanld/chunkformer/issues (VAD segmentation question closed; RNNT release issue #, high priority). Active (RNNT Oct 2025).

### 3. hynt/Zipformer-30M-RNNT-6000h (sherpa-onnx) [GEM for speed/CPU/Mac]
https://huggingface.co/hynt/Zipformer-30M-RNNT-6000h ; sherpa-onnx packs csukuangfj2/sherpa-onnx-zipformer-vi-30M-int8-2026-02-09 (and csukuangfj/sherpa-onnx-zipformer-vi-2025-04-20)
- 30M params, 6000h. VLSP 2025 winner (paper https://aclanthology.org/2025.vlsp-1.4.pdf). WER own table: VLSP20-T1 12.29, VLSP23 pub 10.40/priv 11.10, VLSP25 pub 7.97/priv 8.10, GigaSpeech2 7.56 vs ChunkFormer-110M 14.09/16.15/17.12/15.55/16.07/10.35, PhoWhisper-large 13.75/16.83/17.10/16.14/16.31/10.00. (Author's own comparison; strongest numbers on newer VLSP sets.)
- Speed: 12 s audio in 0.3 s on CPU (~40x RT CPU); <0.1 s on RTX 3090. Runs via sherpa-onnx on Mac (CPU/CoreML EP), tiny.
- Timestamps: sherpa-onnx transducer gives token-level timestamps (word via BPE merge) - known sherpa feature, not in card.
- License: CC-BY-NC-ND-4.0 (non-commercial, no derivatives). Personal use OK; check conversions.
- No PnC (plain text) - needs punctuation restoration (e.g., vibert-capu used by https://github.com/welcomyou/sherpa-vietnamese-asr, MIT, updated 2026-09-26: Windows app, diarization; useful reference for pipeline).
- Long-form: streaming-capable arch but offline use needs VAD chunking.

### 4. vinai/PhoWhisper-{tiny..large} [MEH - established baseline]
https://huggingface.co/vinai/PhoWhisper-large ; paper https://arxiv.org/abs/2406.02555 (ICLR 2024 tiny papers); repo https://github.com/VinAIResearch/PhoWhisper (active, last push 2026-10-01 but model last updated 2024-11)
- Whisper large-v2 arch fine-tuned on 844h. WER: VIVOS 4.67, CV 8.14, VLSP20-T1 13.75, T2 26.68 (ChunkFormer card). Better than whisper-large-v3 on vi; large is NOT turbo-sized (32 dec layers, 1.55B, ~half the speed of turbo-class on batched CUDA; whisper-large-v3-turbo has 4 decoder layers).
- Timestamps: Whisper-style (HF word timestamps via cross-attn; CT2: kiendt/PhoWhisper-large-ct2, vudang449/PhoWhisper-large-ct2; WhisperKit CoreML for medium: aoiandroid/whisper-vi-phowhisper-medium-whisperkit-coreml-ios; ONNX base). Drop-in with faster-whisper => lowest integration cost. Output has punctuation/case (Whisper style).
- Long-form: inherits Whisper 30s windowing + hallucination/repetition on silence; trained on short clips.
- License BSD-3-Clause.
- Apple: mlx-whisper conversion straightforward (not verified for PhoWhisper), CT2 on Mac = CPU only.

### 5. Qwen/Qwen3-ASR-1.7B / 0.6B [MEH for vi - timestamps blocker]
https://huggingface.co/Qwen/Qwen3-ASR-1.7B ; https://github.com/QwenLM/Qwen3-ASR ; paper https://arxiv.org/abs/2601.21337 ; Apache-2.0
- Vietnamese supported (ASR + LID). Paper Appendix: Fleurs vi / MLS vi tables exist (my parse of table columns ambiguous: rows "vi 8.52 5.55 3.64" (Fleurs) and "vi 17.67 14.92 13.11" (MLS) - likely per-model columns; do NOT quote without checking). Reddit snippet claims vi 5.1 vs whisper-v3 9.8 (unverified source) https://www.reddit.com/r/LocalLLaMA/comments/1qrbel2/
- TIMESTAMPS: Qwen3-ForcedAligner-0.6B supports only 11 langs: zh, en, yue, fr, de, it, ja, ko, pt, ru, es. NO VIETNAMESE. => no timestamps for vi from the official stack. (Could pair with external aligner e.g., wav2vec2 vi CTC forced alignment / MFA - extra surface.)
- vLLM batch inference + long audio claims; decoder 1.7B bandwidth-bound (Reddit: ~half speed of whisper-large; ~8x turbo decoder) .
- Fine-tunes Toan2408/qwen3-asr-1.7b-vietnamese(-lora) tiny, 2026-08, no cards [NOISE].
- Newer: Qwen-Audio-3.0-ASR tech report https://arxiv.org/html/2609.07549v2 (30 langs incl. vi) - weights status not checked.

### 6. nvidia/nemotron-3.5-asr-streaming-0.6b [MEH]
https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b (created 2026-05-15, upd 2026-09-10; license OpenMDW-1.1; 1.19M downloads)
- 40 locales; Vietnamese "transcription-ready". FLEURS vi WER 13.41 (80ms) -> 11.18 (1.12s chunk) w/ LangID; auto-detect 13.59->11.22. Much worse than Parakeet-vi-CTC FLEURS 6.86 (different normalization, caveat card note). Cache-aware RNNT streaming, PnC native. Offline mode exists. Wide Apple ports: mlx-community/nemotron-3.5-asr-streaming-0.6b (+8bit), CoreML (aufklarer/..., BarathwajAnandan/...), GGUF, ONNX int4. Good for Mac ecosystem but worse vi accuracy; no timestamps verified in card.
- This is the "Parakeet multilingual update" the user asked about: vi YES now (unlike Parakeet v3).

## Speed / hardware notes (UNVERIFIED unless stated)
- RTX 3060: Parakeet-vi CTC (0.6B bf16) and ChunkFormer (113M) fit trivially; ChunkFormer 12GB ~ 120 min batch by README scaling (24GB=240 min). Zipformer-30M runs on CPU at ~40x RT.
- Baseline faster-whisper turbo 55-64x RT (user). CTC/RNNT FastConformer models are typically far faster than whisper-turbo; not measured for vi here.
- Apple Silicon: Zipformer sherpa-onnx (easy), Parakeet-vi CoreML community port (ANE), onnx-asr int8 port, Nemotron MLX/CoreML (worse vi). ChunkFormer: no native Mac port found.

## Ranked recommendation (Vietnamese long-form podcasts)
(a) RTX 3060 12GB
1. khanhld/chunkformer-rnnt-large-vie (CC-BY-4.0): best published avg WER (10.22 vs PhoWhisper 13.31 vs whisper-v3 28.32 on same table), long-form + timestamps are native features, small. Con: no PnC (verify), segment-level timestamps (word-level unverified), pip package not NeMo/faster-whisper.
2. nvidia/parakeet-ctc-0.6b-Vietnamese: PnC output + word timestamps + n-gram LM; needs VAD chunking; gated + NeMo dep (or giangndm bf16 HF transformers port / OpenVoiceOS onnx to avoid NeMo). Likely best readable output.
3. vinai/PhoWhisper-large via kiendt/PhoWhisper-large-ct2 (faster-whisper drop-in, BSD-3): safest integration, slower than turbo, whisper hallucination on long audio.
4. hynt/Zipformer-30M-RNNT-6000h (sherpa-onnx): fastest, strongest on VLSP23/25, but NC-ND + no PnC.
Fallback: keep whisper-large-v3-turbo.

(b) Apple Silicon
1. hynt/Zipformer-30M-RNNT-6000h via csukuangfj2/sherpa-onnx-zipformer-vi-30M-int8-2026-02-09 (CPU, trivial) - + punctuation restoration model.
2. leakless/parakeet-ctc-0.6b-Vietnamese-coreml (ANE; community, small) or OpenVoiceOS onnx-asr int8 port.
3. PhoWhisper via mlx-whisper conversion (self-convert) / WhisperKit CoreML.
4. chunkformer-rnnt-large-vie on PyTorch CPU/MPS (test).
Nemotron-3.5 MLX only if streaming matters.

Does anything beat whisper-large-v3-turbo on vi WER? Very likely yes: Parakeet-vi, ChunkFormer, Zipformer-30M, PhoWhisper-large all beat whisper-large-v3 (turbo ~ v3) in published tables. BUT evidence = authors' own tables on short, scripted-ish sets; zero direct turbo comparison; zero podcast data.
