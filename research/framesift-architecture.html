framesift Architecture

framesift becomes a time-indexed video library. GPU work runs as batch jobs when a video is ingested. The agent queries a small index on the Mac and looks at pixels only when a question needs them.

status: proposed, not built built and measured: v0.2 hardware: Mac M1 Pro 16 GB · Ubuntu box with RTX 3060 12 GB
What changes

From documents to an index

Today framesift writes documents the agent reads from top to bottom. For the 1 h 45 min podcast, storyboard.md is 188 KB. Two thirds of it is transcript, and 25% is segment headers and detector numbers the agent cannot use. A vision server also has to stay running for the meaning step. The proposal moves the GPU off the read path and gives the agent four small commands instead of a file.

System

What runs where

The library lives on the Mac, next to the agent. The Ubuntu box holds no state. When it is on, a one-shot job copies pending inputs over, runs each GPU stage in its own process so VRAM is freed between stages, and returns finished layer folders. When it is off, queries still work, and the Mac can run speech recognition with MLX.

Data flow

Layers and what re-runs when a model changes

Every stage writes a layer folder keyed by stage, model and settings, for example layers/asr@whisper-turbo-3f9a/. A layer records the hashes of the layers it was built from. Upgrade one model, and only that layer and the layers that depend on it are rebuilt. The same mechanism lets an interrupted job resume and records which on-demand results agents actually ask for.

Read path

What answering one question costs

The agent works down a ladder and stops as soon as it can answer. Every response carries fs1:<video>@<start>-<end> handles, so it can cite a time range or drop one level for more detail. find reports scores and says plainly when a match is weak, so a missing answer does not look like a confident one.

How we got here

The evidence trail

  • 30 Sep
    v0.1 built and tested on real footage. Real screen recordings showed a whole-frame average misses a new chat message, so changed-area detection was added. A dark stage fooled the screen detector, so it now counts identical frames.
  • 30 Sep
    The podcast exposed fragmentation. A 1 h 45 min interview produced 791 segments, and v0.1 spent most of its frame budget on the cold open. Camera-switch detection and a time-spread budget fixed coverage: 90.8% → 96.1%.
  • 30 Sep
    Ubuntu benchmarks. GPU decode lost on both machines. Batched Whisper turbo reached 55–64× realtime on the RTX 3060.
  • 30 Sep
    Meaning layer and a real failure. On-the-fly FP8 broke the vision model, which then wrote fluent nonsense. A vision self-test now refuses a model that cannot see. Whisper and the VLM could not share 12 GB reliably.
  • 1 Oct
    Model research. Six agents across English, Chinese, Taiwanese and Vietnamese sources: keep Qwen3.5-4B, change the text embeddings, test Vietnamese speech models, add SigLIP2 and TimeLens2 where they earn it.
  • 2 Oct
    Architecture brainstorm. Five lenses (agent consumer, home operator, first principles, minimalist, platform futurist) agreed on index over documents and no GPU on the read path. This design scored 77.5 on the decision rubric, ahead of the minimalist design (74.5) and today's v0.2 (57).
Decisions

Fix now, build in order, leave out

Fix now: these cannot change later

  • Citation format fs1:<video>@<start>-<end>, versioned from day one.
  • Time base: source timestamps normalised to start at 0, in seconds.
  • Keep audio.opus and 768 px keyframes for every video, about 15 MB per hour.

Build in this order

  1. Question-answering eval: correct answers per agent token.
  2. Vietnamese speech measurement on 20–30 checked minutes.
  3. Layer store and the five verbs, with the extractive card.
  4. One-shot GPU drain with keyed done-markers and a GPU lock.
  5. Eval: transcript plus look, against adding VLM text.

Leave out for now

  • Any model server that stays running.
  • An MCP server, a vector database server, a job queue service.
  • Two-way sync between the Mac and the Ubuntu box.
  • Segments or detector numbers in what the agent reads.
  • Speaker labels by default; a cross-video knowledge graph.

Open risk: retrieval can fail without anyone seeing it, because the agent cannot know what it did not find. The safeguards are scores and weak-match warnings in find, the entity list in the card, and a rule that the agent reads a span before it cites it.
