## Builds

### m02.r2.1 Seams with a named cause: edit, join, or recorder
Builds on: m02.r1.1 + m04.r1.1 + m06.r1.2
A seam is only evidence of editing if something else did not make it, and m06.r1.2 shows the other two makers: a recorder that stopped writing frames, and a join of crashed pieces like the owner's demo (m04.r1.1). Add the container's own frame and packet timestamps as a third witness, beside sound and picture, and print the cause: `seam 41:12 (join: timestamp gap 0.4 s + room jump)`, `gap 00:12-00:16 (recorder wrote no frames, room tone unbroken)`, `seam 01:12.4 (edit: sound + picture, timestamps continuous)`. An examiner's first question about a discontinuity is "who made it", and this answers it, so a fact-check never blames a re-encode on the person speaking and a bug report never blames a recorder stall on the app. The owner's three crash pieces label the join case for free, the scripted loaded-recorder clips label the recorder case, and the cut-word generator labels the edit case.

### m02.r2.2 The dub as a forgery that must pass: run the layer map on the owner's own re-voice
Builds on: m02.r1.2 + m05.r1.1 + m04.r1.3 + m05.6
Reverse the forensic goal. The re-voice job builds a deliberate forgery, so the detector becomes the quality check: a good Vietnamese dub is one that the layer map (m02.r1.2) and room continuity (m05.r1.1) would misjudge as recorded on location. `see DUB --against ORIGINAL` compares the two files' verdicts per voice and per cut: the bed and its room letters must match the original at every cut, the ducking depth must match m05.6's measured depth, and the new voice should carry the original voice's room rather than sit dry. It prints only the places where the forgery fails: `line 14: voice dry over room 2 (original voice was in room 2); bed resets at cut 00:41 (original carries)`. Neither parent had this: m04.r1.3 checks pace and bed presence, and m05.r1.1 tells on-screen from off-screen, but only together, pointed at the owner's own output, do they say why a dub sounds pasted on. The original file is the answer key, and degrading the dub on purpose (dry voice, ducking removed, bed cut) gives the test cases.

### m02.r2.3 One tamper generator for every forensic sense, calibrated per source
Builds on: m06.r1.3 + m02.r1.3 + m05.r1.6 + m02.r1.4
m06.r1.3 mints screen recordings whose answer key is the input log. Push the same idea ten times further for provenance. One offline generator takes any cached video and writes edited copies from a script: cut words, reordered spans, re-voiced lines (TTS and clones), spliced replays, mirrored B-roll, speed changes, then a re-encode chain like a TikTok re-post (9:16 crop, AAC 64k, 2 to 3 generations). The script is the answer key for seams, the layer map, `diff`, distinct counts and the generated-voice witnesses at once. The bolder step: run it on a sample of each source type in the 730-card cache, so every forensic line carries its measured false-alarm rate for that kind of file, as in `seam 01:12 (sound + picture; false on 1 in 60 re-encoded reels)`. The card then states how far to trust a flag on this file, which no single bench gives.
Runs: an offline script and regenerated media, as `bench/` does today; nothing in the `see` path.

### m02.r2.4 The counterview we least want: a silent card reads as "authentic", so print what was checked
Builds on: m05.r1.4 + m05.r1.6 + m02.r1.6 + m06.r1.2
The counterview: every forensic witness proposed here can be beaten by an edit made to pass (matched room tone, a cutaway, a fresh re-encode). Those are the edits that matter in a fact-check. And the agent will read "no seam" as "one take". If that holds, forensic senses make fact-checks worse, because silence becomes an endorsement. Accept it and build the version that survives it. Reverse the assumption that the card reports findings: on any fact-check run, the provenance header reports coverage. It prints which witnesses could run and which were blind on this file: `checked: seams (sound only; picture blind, 1 shot), layers (ceiling blind: AAC 64k re-encode), generated voice (1 of 3 witnesses usable). Not checked: anything a matched-room edit hides.` This extends m05.r1.4's blind ledger from "where ASR is deaf" to "where the examiner is deaf". The skill gains one rule: a missing flag is never evidence of an original. Judge: on the tamper generator's edits made to pass, the right card answer is "blind here", and scoring counts a confident "no seam" as wrong.

### m02.r2.5 Diff against intent: forensics for media the agent made itself
Builds on: m02.r1.3 + m04.5 + m04.r1.6
m04's evidence says most of the media the owner had to check by ear was generated by the agent, so its provenance is already known. `diff` (m02.r1.3) aligned a clip with another video. Align it with the generator's own intent instead. Every render the agent makes writes a manifest sidecar (label i should sound at t_i, slide k should hold from a to b), and `mediasift diff OUTPUT --intent manifest.json` checks the rendered file against it with the existing word times and cut events: `clip 7 heard "new word", label is "word 1" (matches label 8: shifted by one from clip 3)`, `slide 4 held 0.2 s, intended 2.0 s`. This turns the HSK off-by-one and the slide-timing complaints into failed diffs that the agent sees before it says done. The manifest is the answer key, so each case in m04.r1.6's "after done" bench becomes an automatic check with no human labels.

### m02.r2.6 Fresh: the screen's own clock and signature as splice witnesses
Builds on: m06.r1.4 + m07.2 + m02.6
m06.r1.4 matches screens by their lasting text, and m07.2 found that text present from the first frame is never read. To an examiner, that text is the strongest evidence a frame carries: a phone status-bar clock, a burned-in camera timestamp, a platform watermark with a username, and the battery level. Each one should move only one way through a single take. Read those regions once per shot letter and again at every seam candidate. When one moves the wrong way, print it: `status clock 9:41 -> 9:38 at 00:22 (picture from an earlier take)`, `watermark @userA until 00:15, then @userB (compilation of two posts)`, `battery 62% -> 71% (not one session)`. This adds a model-free picture witness that keeps working after re-encodes, where the sound witnesses fail. It costs one OCR pass per shot letter on regions already found. Judge: the tamper generator splices screen recordings and reels with known clocks and watermarks, and the bug-repro recordings serve as clean negatives.
