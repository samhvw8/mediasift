### m07.r2.1 My mistake last time: "already computed" was a premise I never checked. A premise ledger, and a persisted sidecar so that the checks run offline
Builds on: m07.r1.4 + m03.8 + m08.7 + m08.6
The answer to the provocation: m07.r1.4 said "running cost zero, over scores the pipeline already computes", and every cheapest observation I proposed had no decision rule written down before it was run. I checked the premises this time. `sound.tag` keeps only the top 12 of 527 CED classes per 0.5 s window (`top_k=12`), only in memory. `sensed.json` keeps 34 named sound runs and no class scores, and its `speech` entries hold only start, end, text and voice: `words_to_cues` drops the word times, as m08 said. So m03.8 ("mine the 527 scores"), my r1.4 and m08.6 can't be replayed over the 1,013 cached `see` runs today. Each one needs a fresh decode, and a quiet class such as "Speech synthesizer" under speech may never be in the top 12. The build has two parts. First, every idea carries a ledger row: its "already have" premise, a one-line check (grep or `python -c`) and a kill rule written before the check runs. Second, `see` writes a `scores.npz` sidecar (top-k float16 indices and values, plus the word times) into the existing cache folder. After that, every scores or words bench in this council replays offline against cached runs. Runs: a few hundred KB of disk per cached video, no compute.

### m07.r2.2 Abstention bench by ablation: the blind-spot ledger's judge writes itself
Builds on: m03.2 + m03.r1.3 + m07.r1.3
m03.2 needs questions whose right answer is "the card cannot know", but nobody has to write those by hand. Take a bench video with a question already keyed. Then damage the input at the span that holds the answer: mix in music at a known gain over the speech (m03.r1.3's ruler), darken the frames, or cut the audio. Rerun `see`. The right answer is now "cannot know" by construction, and the original key says what an invented answer would look like. Score three numbers per blind-ledger entry: the agent abstains when the span is damaged, still answers when it is intact, and never confidently states the original answer from a damaged card. Each `Blind:` line ships only when its abstention gain is larger than its false-abstain cost on the intact copies.

### m07.r2.3 One presence test decides two ideas: is the mains hum there at all?
Builds on: m08.r1.4 + m01.r1.1 + m02.1
ENF sync (m08.r1.4) and the hum phase-break splice witness (m01.r1.1) both assume the 50/60 Hz hum survives into the files this owner sees. The 16 kHz decode applies no high-pass (`decode.py` uses only `-ac 1 -ar`), so the decode is not the risk. The risk is earlier: phone microphones high-pass at about 80-100 Hz, and AAC drops the low band at reel bitrates. Before either detector exists, run one pass over the cached sources (and the URL cache). Measure the SNR of the narrow band at 50 Hz and at its 100/150 Hz harmonics against the neighbouring bins, and write the kill rule first: if fewer than 30% of the owner's reels carry a trace above 10 dB SNR in any harmonic, both ideas are parked together. If more do, the same per-file SNR becomes their shared confidence gate, so the sync and the splice witness never print a word on a file with no trace. Runs: nothing new (one script, run by hand).

### m07.r2.4 Demand that the skill text didn't cause: promotion counts only questions the human asked
Builds on: m08.r1.6 + m03.3 + m03.7 + m07.r1.1
m08.r1.6 promotes a `log` field when agents query it often, and m03.7 promotes a `look --with` lane the same way. But agents query what `SKILL.md` advertises, so the counts partly measure the skill's wording, not demand. Two meters remove that bias, and both are taken from session transcripts that already exist. Meter one is the user turn before each query, classed by question type (count, who-on-screen, edited?, room), which is demand before the agent chose a tool. Meter two is my correction census, which records when the owner corrected an answer that a field could have settled. A field earns a card line only when both meters point at it: humans ask that type of question, and answers given without the field get corrected more often than answers given with it. Usage counts alone never promote anything.

### m07.r2.6 A canary in every batch: the generator-as-key check has to fail on a known-bad item
Builds on: m01.r1.3 + m07.r1.6 + m04.5
My r1.6 and m01.r1.3 use the generating agent's own manifest as the answer key. The flaw I left in: when the manifest is wrong (the label list itself shifted by one), the output matches the key and passes. The fix keeps the key but adds two independent checks. First, compare the ASR text of each clip with the label text, not with the manifest's index, so a shifted list shows up as a run of neighbour matches whatever the manifest says. Second, `mediasift qc` splices one known-bad canary into every batch (a clip with a deliberately wrong word, played at 1.5x, with no head silence). If the canary passes, the checker is broken, and `qc` exits non-zero rather than printing an all-green table. This is crash rather than corrupt applied to the judge itself. The canary's expected failures also give a regression test for `qc` that sits in the repo.
