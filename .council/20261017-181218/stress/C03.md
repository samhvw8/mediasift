# Stress test: C03 "The dub as a forgery that must pass"

Checked on disk today, before the attack:

- **The four motivating faults are all fixed already, inside anydub, and three of the four were fixed by measuring.** anydub `.okf/log.md` lines 12-14: voice separation became the default, the original voice came back at a 0.3 duck, and the original track is now dropped by default (`--keep-original` restores it). anydub `decisions/timing-fit.md` gives the overrun table: 34/78 lines over slot, mean lag 3.67 s, then **1/78 and 0.01 s** after `trim_silence`. The concept says "Nobody measured them". That is false for timing: anydub measured the fault and fixed its root cause the same day.
- **Dub frequency.** `~/.cache/anydub/` holds 20 ids. Only 4 hold a finished dub (`bi23y0x-MhA`, `douyin-clip-38359`, `rMjVAnHmUeE`, `tDmjz6HB-yw`). All 4 date from 2026-09-25 to 09-27, which is anydub's build week. The other 14 are transcript-only (the 09-29 synthesis job). There has been **no dub for 3 weeks**. "A few times a month" is not observed.
- **anydub already knows most of the numbers exactly.** `cli.py` has `--orig-voice` (default 0.3) and `--bg`. `speak` records the speed factor per line. `mix` places each line at `max(start, previous end + 80 ms)`, so it knows every line's lag to the millisecond. The final mux knows the track list.
- **The bench reads anydub internals.** `forge.py` reads anydub's stems, TTS clip dirs and translation times. That is the same moving-format coupling the last council's stress test flagged for C07 (anydub has one commit plus uncommitted layout work).
- **Dub languages are not only Vietnamese.** `tDmjz6HB-yw` has `dub.en.wav` and `dub.ja.wav` as well as `dub.vi.wav`.
- **The 5.2 dB loudness gap** was measured on `douyin-clip-38359`. That cache has no `voice.wav`/`background.wav`, so it is a pre-separation dub from before the fixes.

## Fragile assumptions

Ranked from most fragile to least.

1. **Untested: the next faults the owner hears will be in the classes this check measures.** Every check targets a fault class that anydub has since fixed by a default change. Industry QA lists name other classes as the ones that ship: "a mistranslated product name, a line that runs long over a scene cut, or two characters sharing one voice" (https://ollang.com/partners/quality-control-for-ai-dubbing-building-an-ollang-review-loop-around-language-timing-and-voice). Viewers of YouTube auto-dubs complain about unnatural voices and mispronounced words (https://www.reddit.com/r/languagelearning/comments/1ow50hc/tired_of_automatic_dubbing_on_youtube_videos/ ; https://www.nemovideo.com/blog/ai-video-editing/why-does-dubbing-ai-sound-so-bad). None of the nine checks sees pronunciation, translation, voice identity or demucs artifacts. The bench cannot show this gap, because forged faults are drawn from the checker's own model: 0.9 recall on planted faults is recall on faults the author already chose to look for.

2. **Shaky: an outside DSP measurement is worth more than anydub reporting what it did.** For depth (gain set), pace (speed factor applied), timing (placement start) and track order, anydub holds the exact value. mediasift would re-derive it through ASR pairing, CED speech runs and alignment, adding error and a forged-media bench to estimate a number another program already printed. The outside view has real value in only three places:
   - **Projection catches what anydub does not know.** If demucs leaks the English voice into `background.wav`, that leak plays at the bed gain of 1.0. The projection then reads above the 0.3 target, and anydub's own number would still say 0.3. This is the strongest check in the concept, and it is already measured (0.30 read for 0.30 set, through AAC on both sides).
   - **Picture-aware timing.** Only mediasift has the cut list, so only it can flag a dub line that runs over a picture cut when the original line did not. The concept does not propose this.
   - **Dubs anydub did not make.** These are YouTube auto-dubs and third-party pairs. The owner has not used any.

3. **Shaky: a "passes" line will not be read as "done".** The concept copies the m02 counterview and prints "not checked: room". But a line that starts `passes: depth, bed, timing, pace, loudness` is exactly the token an agent in a hurry needs to say "done". The owner's listening is the only check that today covers pronunciation and translation. If the pass line replaces that listening, the check makes the result worse.

Lesser points:

- **Timing thresholds.** Brannon et al. found that "human dubbers appear more willing to break timing constraints than vary speaking rate" (https://arxiv.org/abs/2212.12137, §4.3). A fixed "late > 1 s" flag can therefore fire on dubs that a professional would accept. The threshold is the owner's taste, like `--voiceover`.
- **Voice band.** The 11.7 kHz edge comes from edge-tts's 24 kHz MP3 output (https://migushthe2nd.github.io/MsEdgeTTS/enums/OUTPUT_FORMAT.html). It fires on every edge dub forever. The only fix is the metered engine, which anydub's `no-metered-default` decision rules out. The line can never be acted on, so the agent learns to skip the block.
- **Pace reference.** A reference built from cached Vietnamese reels measures energetic phone speech, not read TTS, and it does not cover the `en`/`ja` dubs. The per-voice median plus anydub's own speed factor already answers "which lines are rushed".
- **Prior art.** "I found no tool that takes an original and a dub file" misses RAST (Disney Research and ETH Zurich, Interspeech 2024). RAST predicts the offset between an original and a dubbed track. It also reports that plain correlation reaches about 10 ms MAE on global offset (https://www.isca-archive.org/interspeech_2024/meyer24b_interspeech.pdf). This supports the concept's alignment step. It also shows that intermittent offsets (re-cut dubs) need more than one cross-correlation, which matters only for third-party pairs. File QC suites such as Telestream Vidchecker compare files for loudness and audio metrics (https://www.telestream.net/vidchecker/overview.htm). The per-line, agent-readable output is still new.

## Pre-mortem

It is 2026-10. `--against` shipped in November with depth, bed, timing, pace, loudness, voice band and track order, and all checks passed their forged bench.

What most probably happened: **it ran four times in a year, and once caught something real.**

The owner dubbed rarely after anydub's build week. When he did, the agent was in an anydub session, and the mediasift skill and hook did not fire. Nothing about "re-voice this into Vietnamese" says "video I can't watch". Nothing in anydub's agent file named `--against`. On the four runs that did happen, the agent was told to run it. Three runs printed `passes: depth, bed, timing, pace, loudness; not checked: room` plus the permanent `voice band ends at 11.7 kHz` line. The agent said "done, mix checks pass". The owner then heard a mispronounced guest name, an untranslated English phrase that the TTS read with Vietnamese tones, and once a watery demucs artifact over music. None of the checks could see these. The fourth run flagged real English under a music intro, because demucs leaked the voice into the bed. That was the projection check doing its job.

Meanwhile, anydub changed its cache layout twice. `forge.py` broke both times, and the bench silently stopped being re-run, because it is an offline script nobody calls. The anydub mix rule changed once, when a lead-in was added. The note "rerun the bench when anydub's mix changes" was in mediasift's okf, where nobody working in anydub reads it. The timing check then flagged every line as 1.5 s early for two months, until the owner turned the block off.

The roadmap items above it (Vietnamese ASR, the card header, speech integrity, burned-in captions) were the failures that already happen. Each of them waited a week longer.

## Who loses

- **anydub.** If mediasift owns dub QA, anydub's knowledge of its own mix (gains, speeds, placements) is copied into a second tool as "targets" and forged renders. Every anydub mix change becomes a mediasift bench change. Likely response: anydub stops caring and the bench rots, or the owner adds the exact report to anydub anyway. In that case mediasift's copy is dead weight.
- **The roadmap.** Items 2-6 are measured failures on the default card, which every job pays for. A dub-only mode serves one job that has not run for 3 weeks. Every week spent here delays them. The owner responds by deprioritising it again, as the last council's judges did.
- **The owner's ear.** It is the only check today for translation, pronunciation and voice quality. A pass line that the agent reports as "checks pass" weakens the listen that catches the faults this tool cannot see. The owner's response is to stop trusting "done", or worse, to stop listening.
- **mediasift's identity.** It is "a sensor for agents that cannot watch or hear any video". `--mix` and `--against` make it a QA harness for one sibling tool, with a second CLI surface for agents to learn. Every session that loads the skill pays for that surface in skill tokens, even on bug repros and TikTok checks.

## Fixes

| weakness | smallest fix |
|---|---|
| Fault classes are yesterday's (assumption 1) and the bench is circular | Add a **real-fault coverage test** next to the forged bench. The owner listens to the next 3 dubs and writes every fault he hears, with a time. Score the fraction of his faults that the block names. Seed it with the real pre-fix dub that still exists (`douyin-clip-38359/dub.vi.wav`, made before separation, so it has English under the dub). Print a check only if it covers a fault the owner actually logged. |
| Re-deriving numbers anydub knows exactly (assumption 2) | Move the exact half to anydub. Its `mix` step prints one summary: lines late > X s with times, lines sped up > 1.3x, gains used, audio tracks written. That is about 15 lines in anydub, with no DSP, no ASR pairing and no bench. Keep only the independent checks in mediasift: **projection depth** (it catches demucs leakage and mix bugs), **bed kept/cut** (once it has a music bench), and loudness **only against a target the owner names**. |
| Missing check that only mediasift can make | Add **line over cut**: a dub speech run that crosses a picture cut that the original line did not cross. It uses the cut list `see` already computes. Ollang names this exact fault class. |
| Pass line read as "done" (assumption 3) | Never print the word "passes". Print `measured: depth 0.31 (target 0.3), bed kept, loudness +0.8 dB` and always end with `not measured: translation, pronunciation, voice, separation artifacts`. Add one rule to the skill: a clean block is not "done"; report what was measured and ask for a listen. |
| Voice band can never be acted on | Keep it in `sensed.json` only. Print it only if the owner logs "sounds muffled" as a fault in the coverage test. |
| Timing threshold is taste (Brannon §4.3) | Make it a flag, as `--voiceover` is. If anydub reports lag itself, mediasift does not need it at all. |
| Vietnamese pace reference from reels | Drop it. Use the per-voice median only, or anydub's own speed factors. |
| The check never fires from anydub sessions (pre-mortem) | Add one line to anydub's AGENTS.md: "after a dub, run `mediasift see DUB --against ORIGINAL`". Without it, the mode is unreachable where the job happens. |
| `forge.py` reads anydub internals that are still moving | Record the anydub commit hash in the bench output. Make `forge.py` crash on a missing stem and not skip it. Beyond that: no fix, this is the price of a bench with keys. Keep it bench-only, so it never couples `see`. |
| Low frequency (no dubs for 3 weeks) | No fix: this is the price. Gate the build on use: start when the owner's next dub job begins, not before roadmap items 2-4. Running cost is $0 and default-card cost is 0, so a rarely used mode costs only bench upkeep. That is why the mode must stay small. |
| Third-party dubs (YouTube auto-dubs) may be re-timed | Keep the crash on offset > 50 ms or duration mismatch > 1 s. Do not build per-snippet alignment (RAST-style) until a real third-party pair is needed. |

## Verdict

**Survives with changes.** The core is sound and cheap. Projection of the original into the dub is measured (0.30 read for 0.30 set, and 0.005-0.983 across planted gains through AAC). It costs $0, adds nothing to the default card, and catches a leak anydub cannot see in itself. The rest of the concept does not survive as written. It re-measures numbers anydub already knows, targets faults anydub already fixed, and couples a forged bench to a sibling's moving cache.

Required changes:

1. Shrink `--against` to projection depth, bed kept/cut (once it has a music bench), loudness against an owner-named target, track order, and a new line-over-cut check.
2. Move per-line lag, speed factor and gain reporting into anydub's `mix` summary.
3. Never print "passes". Always list what was not measured, and add the skill rule that a clean block is not "done".
4. Add a real-fault coverage test from the owner's own listening notes. A check prints only if it covers a logged fault.
5. Put the invoke line in anydub's AGENTS.md.
6. Keep it below roadmap items 2-4. Start only when dub jobs resume.

Runs: `mediasift see ORIGINAL --mix` and `mediasift see DUB --against ORIGINAL` only, on dub jobs. anydub's `mix` summary prints on every anydub run. The bench is an offline script.
