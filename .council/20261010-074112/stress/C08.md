## Fragile assumptions

Ranked most fragile first.

1. **The strip image + a 1.5k-token text trailer carries motion, order and sound better than keyframes + transcript. Status: untested, and the most fragile.** The whole concept rests on it, and the author admits no code was run. Specific doubts:
   - A 128x72 tile is 15 visual tokens (the formula checks out: ceil(w/28) x ceil(h/28), https://platform.claude.com/docs/en/build-with-claude/vision). But the token count is low because the tile holds almost no detail. A model reading 40 thumbnails of 128x72 can see "a screen changed". It cannot read UI text, tell which button was pressed, or count a ball bounce from tile differences. Counting and cause-and-effect are the exact gap the user named, and tile-grid reading is the weakest case for a VLM.
   - The "sound rail" is a drawn bar under tiles. The model must decode a rendered waveform/class bar as sound. Nobody has shown that a model reads that reliably. The text pacing curve (12 numbers) and silence stretches are measurable, but they say "something loud at 3.2 s", not "an alarm" or "she laughed".
   - Speech/silence/other-loud is the only sound taxonomy proposed. Music change, laughter, tone of voice (named in the brief) stay out of reach; the "ear valve" is an off-by-default metered API.
   - The concept's own kill condition for this row says that if it fails, "the novelty is in the hook, not the strip". That is honest, but it means the sensing claim could collapse to "a receipt".
2. **A hook is the right trigger. Status: shaky.** I checked the hooks reference (https://code.claude.com/docs/en/hooks). Facts hold: UserPromptSubmit command-hook default timeout is 30 s; a sync hook that times out has its output including `additionalContext` discarded; additionalContext is capped at 10,000 characters, over that it is saved to a file with a 2,000-char preview. But:
   - The concept says "`async: true` hooks cannot add context". The current docs say the opposite: after an async hook exits, Claude Code delivers its `additionalContext` on the next turn. So a better design exists than the concept knows (see Fixes), and the doc claim the concept leans on is stale. (Async results arrive only on the next turn and are killed at teardown in `-p` mode.)
   - Hook behaviour is a moving contract with open bugs: context not injected in the VS Code extension (https://github.com/anthropics/claude-code/issues/49063); hard-coded 30 s timeout with silent drop (https://github.com/anthropics/claude-code/issues/66649); each prompt's injected block accumulates in history instead of being ephemeral (https://github.com/anthropics/claude-code/issues/40216); top-level `additionalContext` (wrong JSON shape) is silently dropped with no warning (https://claudeissues.com/issue/96193-hook-json-with-top-level-additionalcontext-is-silently-dropped-no-warning-contex); hooks not fired for mid-turn messages (https://github.com/anthropics/claude-code/issues/90296). "Crashing beats corrupting" is hard to keep when the host itself fails silently: the receipt the hook prints is exactly what a dropped injection never shows.
   - It is Claude-Code-only. The brief says "Claude Code and similar harnesses"; a UserPromptSubmit hook does not exist in most of the others, so the sensor is not portable.
   - Issue #40216 matters for the "constant cost" claim: if the block re-injects on every later prompt in the session (when the path is still mentioned, or the regex matches again), the cost is not 1.5k once but 1.5k per turn, and it stays in history.
3. **T0 finishes inline in under ~10 s on a 2 h file, and false triggers stay low. Status: untested, but cheap to measure and the author flagged it.** Decoding every frame at 128x72 for 1h45m (about 150k frames at 25 fps) plus mel novelty: the known full run was 8.2 min including ASR and index, so the T0 share is unknown. If it is more than ~25 s, the inline promise fails for exactly the long files that motivated it. Fallback (receipt only, `T0 pending`) is itself a thin product. Detection by regex over free prompt text (quoted paths, spaces, `~`, URLs that are not videos, a path mentioned but not meant to be watched) is a second source of surprise cost, and a mis-trigger spends T0 compute plus tokens on a prompt that did not want it.

Solid parts: no daemon and no cost on non-video prompts; atomic rename for layers; content-hash cache; image token arithmetic.

## Pre-mortem

A year later it is quietly dead, not on fire. Most probable story:

- The hook shipped and worked for two months on short screen recordings. T0 timing on long podcasts was over 30 s on the M1, so long files got `T0 pending`, and Sam stopped trusting the first answer for exactly the long videos.
- The agent rarely `Read` the strip. For the questions Sam actually asks ("what does the speaker say about X", "where does the bug appear"), grep on the transcript and the existing storyboard won, as the long-video bench already showed (agents grep rather than read). Only about one injection in five was followed by any sidecar read, so the block was waste and got shrunk to the 40-token one-liner; the sensing idea shrank with it.
- A Claude Code update changed hook output handling (one of the several bugs above, or a shape change), the receipt silently stopped appearing, and nothing flagged it for weeks. The `doctor` check that was supposed to pin the contract was the last thing built and never was.
- The cache grew to tens of GB (frames, sheets, YouTube downloads) and a detached ASR job died when the laptop slept, leaving `running` status that the next hook read as in-flight. Sam went back to typing `framesift analyze` by hand.
- The synthetic temporal/audio bench (the real proof) was always "next week". Nobody ever learned whether the strip beats the storyboard on counting and order.

## Who loses

- **Existing video MCP servers and Claude Code plugins** (popcorn, mcp-video-analyzer, media-context-mcp, claude-real-video, mcptube-vision, listed in the develop doc) are tool-invoked and already ship keyframes + transcript + OCR. If a zero-invocation hook works, they lose the "agent must decide to call me" step. Their likely response: add a hook/skill auto-trigger, add OCR and captions. They already have users and OCR, which framesift lacks. I could not verify their READMEs beyond the develop doc's note, so this is inference.
- **The harness vendor** loses nothing; its likely response is native video or audio input, which would make the whole sensor obsolete for the model-facing half. Treat this as the main existential risk, not a competitor.
- **Sam's own current workflow** loses: `analyze` / `find` / `look` as explicit verbs become secondary, and the 96-100% find/look bench results do not transfer to the hook path.
- No one else is hurt. Hosted-video-API vendors lose a sliver if the local path is good enough; their response is price cuts, which does not change Sam's cost since the local path is $0.

## Fixes

| Weakness | Smallest fix |
|---|---|
| Strip may carry nothing (assumption 1) | Run the synthetic bench (ball bounces, beep at 3.2 s, A->B->C UI, 5 s silence, reversed/muted controls) BEFORE building the hook. Compare strip vs current sheets at larger tile size. If tiles at 128x72 fail, render fewer, bigger tiles (e.g. 8 tiles at 320 px, still about 1.2k tokens on one image). Keep text-only sound facts (silences, loud spans with timestamps, loudness curve) and drop the sound-class labels, as the concept already allows. |
| Stale async claim | Use `async: true` for T1/T2 completion so results come back as `additionalContext` on the next turn, instead of relying on the next hook run to read `status.json`. Keep `status.json` as the fallback. Remove the "async cannot add context" line from the design. |
| Hook contract drift and silent drops | Make the hook emit a visible `systemMessage` plus the context; make `doctor` the FIRST thing built: one canary prompt that checks the injected codeword reaches the model, run on every Claude Code version change. No fix for the VS Code gap: this is the price, state that Claude Code CLI is the only supported surface. |
| Re-injection accumulating (#40216) | Inject the full block only on first sight of a key per session (store the session id + key in the cache dir); afterwards inject the one-line receipt. |
| T0 too slow on long files | Measure first (test 1). If over ~10 s on a 2 h file, always detach T0 for files over a duration threshold (derive from ffprobe, fixed, not a knob) and inject the one-line `T0 pending` receipt; the async delivery above brings the result next turn. |
| Regex false triggers | Require the path to exist and have a media extension; only match a YouTube URL if it is a bare token; test on past prompts as the concept says. |
| Agent never reads the strip | Accept; the concept's own kill condition (shrink to the one-liner) is the fix. Log use per injection from day one; decide at two weeks. |
| Cache growth, sleep-killed jobs | LRU cap with a hard default (GB figure), `framesift cache`; at start treat any `running` status older than the job's possible runtime, or whose pid is gone, as failed. |
| Non-portable to other harnesses | No fix: this is the price. Keep T0..T3 as plain files and a CLI so another harness can call it; the hook is just one launcher. |
| Host replaces the need (native video input) | No fix: this is the price. Files and CLI keep the work reusable as a fallback. |

## Verdict

**Survives with changes.** The zero-invocation, fixed-size, receipt-first idea is real and the cost model ($0, no daemon) is sound, and I found no existing tool doing the hook-plus-receipt shape. But the claim that makes it a "sense of video" (strip + sound rail beats keyframes + transcript on temporal and sound questions) has never been tested, and the delivery channel has several open silent-failure bugs. Required changes: (1) run the synthetic temporal/audio bench first and only then build the hook; (2) build the canary `doctor` first; (3) use async `additionalContext` for the slow tiers (the concept's async claim is out of date); (4) inject the full block once per session per video; (5) fix the strip's tile size by experiment rather than by token arithmetic alone.
