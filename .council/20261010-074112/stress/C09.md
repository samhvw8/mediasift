## Fragile assumptions

Ranked most to least fragile.

1. **Synthetic clips (PIL shapes, numpy tones, macOS `say`) predict how a packet behaves on Sam's real files. Shaky, leaning untested.**
   The concept names this itself as the biggest risk, then proposes two or three hand-keyed real clips as the check. Two or three clips cannot rank four or five packet formats. A rank agreement on 3 items is close to a coin flip, and a disagreement does not say which side is wrong.
   Local evidence: `bench/sense/clips/` has five clips with flat-colour lamps and tones. The existing bench already showed that its long-video questions "did not separate the arms" because they were guessable. Synthetic clips are the opposite failure: so clean that every packet that keeps a frame per event passes. A packet tuned on them can win by detecting a lamp flash (a large mean-pixel jump), which is exactly what the pixel-statistics front end is good at, and fail on a screen recording where the step is a small toggle.
   External: sim-to-real transfer of synthetic benchmarks is a known weak point. Synthetic-video pretraining transfers unevenly (SynAPT, https://proceedings.neurips.cc/paper_files/paper/2022/file/e8507db80464ced5658d16b49bd458b9-Paper-Datasets_and_Benchmarks.pdf), and the Lost in Time (TVBench) paper cites CLEVRER-style synthetic QA but moves to real video for its own benchmark (https://bmva-archive.org.uk/bmvc/2025/assets/papers/Paper_857/paper.pdf). I did not find a direct study of synthetic-to-real for an agent-packet harness; that part is my inference.

2. **Reversal and shuffle are valid controls for the packet, not just for the model. Shaky.**
   The concept lists the label-leak risk (tile timestamps let an agent pass `rev` without perceiving anything) and offers a stripped-label variant. The sharper problem is the opposite one. For a tool that emits a static storyboard, the reversed clip produces a storyboard that is a plain reordering of the same cues and tiles with new timestamps. The agent answers `rev` correctly by reading text, so "carries time" measures "carries timestamps". With labels stripped, nearly every sheet-based packet fails, and the result is that the bench certifies nothing is good, which is a true but unhelpful finding. The control only separates packets that were designed to show motion (event pairs, chronophoto), which do not exist yet. So the bench's discriminating power is tested against ideas that are not built.
   Also: shuffling one-second blocks injects hard cuts. The segmenter reads cuts as events, so `shuf` changes the packet's boundary count and not just order. That confounds "order vs content". The concept does not mention this.
   External support for the control itself is real: TVBench reports text-only, single-frame and shuffled inputs near chance and that temporal models drop on reversed video (https://github.com/daniel-cores/tvbench, https://arxiv.org/html/2410.07752v2). That backs the design of the control for models. It says nothing about packets.

3. **Agent answers are stable and cheap enough to read 10-point differences with about 30 questions, and "cheap" holds across model changes. Untested.**
   Thirty questions across four or five packet types and five variants, three runs each, is several hundred `claude -p` calls. Each call carries the 63-65k fixed overhead unless the harness is stripped (the concept says the overhead is "excluded and stated once", but a `claude -p` call still pays it in real money and time; only the reported metric excludes it). That is the Infra axis Sam weights highest, and the "cents" estimate is not measured. Binomial noise at n=30 is about plus or minus 9 points at 50% accuracy, so the concept's own "under 10 points is noise" leaves almost no resolvable gaps. Tier B results also expire when the agent model changes, so the bench is a recurring spend, not a one-off.

Lesser: Tier A diffs `manifest.json` against the script, but the manifest has no counted-event or sound-event fields. The `count` clip is 2 segments and 1 keyframe, so Tier A can only say "one event claimed, eight scripted", which is a fail with no diagnostic value. Tier A is a regression test of segment boundaries and transcript cues, i.e. of what the tool already does well.

## Pre-mortem

A year later: `bench/sense/` exists and ran well twice. The first run produced the headline the concept predicted: `count` and non-speech audio fail, `shuf` equals `fwd` for sheets. That was useful and Sam acted on it. Then three things drifted.

- The packet ideas that the bench was built to judge were each built, scored on the synthetic set, and passed, because flash-and-beep clips are easy for any format that keeps an event frame. Rankings looked fine, nothing was killed, and the real-file complaint ("it still misses the thing in my repro") did not go away. Nobody ran the real-clip check after the first three clips, because hand-keying a real clip costs an hour each.
- The generator's `say` voice and Pillow/ffmpeg versions changed on a macOS update. The SHA-pinned clips stopped matching, doctor's cached clips were regenerated, and doctor flapped near thresholds on the 6 s ASR clip. Sam stopped trusting the exit code, and then stopped running it; the "once per N days header" line became noise.
- The `doctor` command was meant to be an install self-test, but the install it protects is a Python wheel plus models. The real daily-use failures (output folder, flags, minutes of runtime on a 1-2 hour podcast, ASR choice) were never in doctor's scope, so the brief's second outcome ("run every day without thinking") did not move at all. The bench became a hobby project next to the tool.

Most probable quiet failure: the bench stayed accurate about what it measured and did not measure what the brief asked. The tool Sam uses daily did not change.

## Who loses

- **Existing contact-sheet and storyboard path (framesift as built).** A bench that says "sheets carry no time" argues against the code that took the v0.2 work. Response: the author keeps the bench but rescopes questions until sheets pass, or declares synthetic "regression only". Both are quiet ways to neutralise a negative result; the concept's `kill ideas` clause only works if Sam commits to the kill rule before looking.
- **The simpler alternatives.** Sending a raw uniform contact sheet, or paying a native video API (Gemini at roughly 258-263 video tokens per second, 25-32 audio, per the concept's cited calculator and page), looks cheap against a month of bench maintenance. If the bench shows a native model wins on temporal questions at a tolerable price, the whole local pipeline loses its reason. Response: the bench's own scoring excludes that arm by design (it scores "packets", not models), so that comparison is never run. I did not independently verify Google's per-token numbers; the concept's own caveat applies.
- **Daily-use effort.** Time on the bench is time not spent on the packet or a one-command wrapper. Not a third party, but the real competitor for the same week.

No outside vendor is hurt; this is an internal tool.

## Fixes

| Weakness | Smallest fix |
|---|---|
| Synthetic does not predict real | Make the real-clip set 8-10 short clips cut from Sam's own files, keyed with 3 questions each in ten minutes per clip (answers he already knows). Label the synthetic set "regression only" in the README unless rank agreement holds on that larger set. Cost: an afternoon. Do not use synthetic to select a design. |
| `rev` measures timestamps | Run `rev` and `shuf` with tile and cue timestamps stripped as the default, not an extra variant. Report `fwd` with and without labels. For `shuf`, shuffle on scene-safe boundaries or insert the same cut into `fwd` (a no-op shuffle) so the cut confound cancels. |
| Bench has no packet that can pass | Build the bench's first run as a pure measurement of what exists (the concept's step 1), and do not add `empty`, `decoy`, `doctor` or the event-list refactor until at least one packet change (e.g. an event-pair still) is on the table. Otherwise the refactor has no consumer. |
| Tier B noise and spend | Fix n before running: 12 questions per type, 3 runs, use `claude -p` with a minimal system prompt and record real tokens per run. Report intervals. If the first pass costs more than about 1M tokens, cut to the two questions types that matter (counting, non-speech sound) and stop. |
| Tier A can't see counts | Have `analyze` emit `events[]` in `manifest.json` only when a packet format claims them. Until then, scope Tier A to boundary and cue regression and say so. |
| Doctor flaps / macOS-only | Drop ASR from default doctor (use `--deep`). Replace `say` with a committed 3 s WAV fixture so the clip does not depend on OS voice. Never auto-run on `analyze`; keep it a manual command. |
| `order: not carried` header on real files | No fix: this is the price. Reversing analysis arrays on talking-head footage will often match, so false alarms are likely. Cut it, as the concept already suggests. |
| Brief's daily-use outcome unaddressed | No fix inside this concept: it is a test harness, not the one-command experience. It needs to be paired with a separate concept that changes the CLI. |

## Verdict

**Survives with changes.**

The first move (score the existing five clips with `claude -p`, add `rev`/`shuf` to `count` and `motion`) is cheap, honest, and produces a number the brief asks for. Keep that. Change these:

1. Treat synthetic as regression-only until a larger real keyed set (8-10 clips) agrees on ranking.
2. Strip timestamps in the default `rev`/`shuf` runs, and control for the cut that shuffle adds.
3. Stop after step 2 of the first move unless a packet format exists to be judged. Defer `empty`, `decoy`, the event-list refactor, `doctor` and the real-file header.
4. Fix question counts and token spend before the first pass, and record the model ID.
5. Do not present this as progress on the daily-use goal; it is not.
