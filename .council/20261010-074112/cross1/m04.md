## Builds
### m04.r1.1 Ledgered motion stills: every image carries a coverage receipt
Builds on: m04.1 + m05.3 + m03.2
The slit-scan strip and motion history image get a ruler and a "declared blind spot" track printed under them: bars for stretches where frames were thinned, where audio was unclassified, where ASR confidence was low, each labelled with a ready `look A-B` command. The agent reads a motion image and, in the same glance, sees which parts of the x-axis the image cannot be trusted on. Neither parent had this: the strips show motion but not their own limits, and the ledger stated gaps but only as text the agent might skip.
### m04.r1.2 Synchresis facts table: perception arithmetic on audio-visual coincidences
Builds on: m04.3 + m05.5 + m03.6
Run the coincidence detector (audio onset within ~80 ms of a visual change) and put the result in the facts table as numbers, not frames: "click-like onset 12.41 s + modal appears 12.46 s (lag 50 ms)", "7 coincidences, period 1.9 s, count 7". The sound-score text lines hang off the same rows (laughter tag, silence 4 s), so one row answers "did the sound come before the dialog" and "how many times" with the backing frame handle. Parents gave the detector, the arithmetic and the sound score separately; together the facts table is one text-only structure that answers order, count and lag for the audio half the bench never measured.
### m04.r1.3 The fovea chooses between a pair and a burst: dual-mode look
Builds on: m04.4 + m03.7 + m05.4
`look --at T` returns one of two layouts, picked by the entry's own type in the timeline. A discrete event (UI change) returns the m03.7 before|after pair with changed-region crop and the words spoken in the window. A continuous event (scroll, drag, camera move) returns the m04.4 native-rate burst with difference masks. Each timeline line already says which kind it is, so the agent never chooses a mode, and the fallback for camera footage is the burst instead of evenly spaced frames, which the pair design lacked.
### m04.r1.4 Retina subagent with a trailer: the main context never holds a pixel
Builds on: m04.2 + m05.6 + m03.5
Ten times larger than any parent: a hook injects only the constant ~2k-token trailer text (pacing curve, sound bar, event list, ledger) when a video path appears, and no image at all. Any image work, the gist strip included, is handed by name to a viewing subagent with the question, which returns about 300 tokens. The main session's cost per video is fixed text plus the answers it asked for, however long the video is. The test is the crossover count of images at which the subagent's own overhead pays off, measured per question batch.
### m04.r1.5 Reverse-and-shuffle controls on synthetic clips, scored per 1,000 tokens
Builds on: m04.8 + m05.7 + m03.8
The generated-video bench gets m05.7's arrow-of-time, shuffle and muted-clip controls built into the generator: every scripted clip is also rendered reversed, and its packet is scored on whether the answer flips. The result is a single table, correct answers per 1,000 tokens, per packet type, with a "carries time" check (shuffle equals ordered means it does not) and a "carries sound" check (muted equals unmuted means it does not). Parents had either exact keys or the controls; this makes the key flip automatically, so no new labelling is ever needed.
### m04.r1.6 Question echo: the packet answers the questions the last session asked
Builds on: m04.2 + m03.4 + m04.1
Fresh idea. Each time an agent asks a question, the tool appends one line to a per-video question log (hash-keyed, next to the cache): the question, the window `look` was pointed at, and whether the agent later asked a follow-up there. The next packet for the same file opens with "last asked about: 3:10-3:40 (UI order), 8:02 (laughter)" and weights those spans in the ledger as already-checked or still-open. Ask-first (m03.4) sets the budget from the question; this makes the second visit smarter from the first, at the cost of one text file and no daemon.
