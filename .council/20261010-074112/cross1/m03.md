## Builds
### m03.r1.1 The fact-backed ledger: every claim carries a handle, every gap carries a number
Builds on: m04.1 + m04.3 + m03.7
Merge the blind-spot ledger with perception arithmetic and event pairs. Each fact in the packet (count, period, duration, order) is a row with a confidence and a handle to its before|after pair, and each hole is a row with the same shape: a time range, the signal that was thinned, and the command to fill it. What this adds: the ledger becomes machine-checkable, because the tool can count rows with and without a backing frame, so "how much of this video did the agent actually perceive" is one number printed on the first line of the packet.
### m03.r1.2 Three facts, one packet: the packet schema derived from what the agent can consume
Builds on: m03 first principles + m02.7 + m04.5
Take the fixed-budget card (m02.7) and the one-line-per-minute sound strip (m04.5) and fix the card layout from my three facts: only text and stills, sound must become text, motion is a computable difference. The card has exactly four zones, each with a hard token cap: header (what, how long, tier reached), timeline (events and sound together, one line each), facts table, ledger. Anything that cannot be assigned to a zone is deleted, which removes the stat lines and repeated cues by rule rather than by cleanup, and a long podcast and a 90 s repro get the same shape at different line counts.
### m03.r1.3 Slit-scan as the screen-recording action strip
Builds on: m03.2 + m04.6 + m04.4
Use the action script from cursor and click detection as the tick marks on a kymograph strip: the x-axis is time, the slice is the changed region, and the detected clicks, scrolls and page changes are drawn as numbered markers on it. The strip is the wide view and `look --at T --span S` (foveated burst) is the narrow one, and each marker number is the argument to the narrow call. What this adds: the numbered script gets a picture where a reader can verify order and count at a glance, and the picture gets a legend that makes it readable, which neither a bare strip nor a bare script had.
### m03.r1.4 The sidecar as a scripted-answer file: ground truth lives next to the code that produces it
Builds on: m02.1 + m03.8 + m04.8
The synthetic bench generators already know what they put in each clip, so make them write the same sidecar format a real run produces (`clip.mp4.fs/`), with the true events as the expected card. Then the bench is a diff of two sidecars, produced card against scripted card, with no agent and no token cost, and the agent QA run is only needed for the last mile. What this adds: a free, deterministic regression test of every perception claim in seconds in CI, and the sidecar schema gets its first real consumer before the hook (m02.1) is built.
### m03.r1.5 The hook with a token meter: every prompt injection is priced and capped
Builds on: m03.5 + m02.1 + m02.8
Turn the UserPromptSubmit hook into the place where cost is enforced: it injects only the header and ledger-count line (about 150 tokens) and never the images, and writes one log line with tokens injected, tier reached and whether the agent later opened a deeper layer. Ten times larger version of m02.8: the log is also the training signal, so after two weeks the hook sets its own injection size per content type from what the agent actually used, with no knob left for Sam. The first-principles reason is that the only meter that matters is tokens per answered question, so the log records exactly that.
### m03.r1.6 The person next to you, answered from the cache: ask-first over a sidecar
Builds on: m03.4 + m04 provocation + m02.2
The ask-first verb takes a question, but instead of sensing from scratch it reads whichever tiers the sidecar already holds (T0 change curve, T2 transcript, T3 vectors), then spends the budget on the missing rung that the question needs: ASR only if the question is about speech, dense frames only if it is about motion. The answer comes back as the sentence a viewer would say plus the handles to check it. What this adds: the tier ladder is picked per question instead of per file, so a 2 h podcast asked a visual question never pays for ASR, and an agent that asks twice pays once.
