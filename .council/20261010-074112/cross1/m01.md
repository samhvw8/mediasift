## Builds
### m01.r1.1 Audio-visual coincidence drawn as one chronophoto with a spectrogram ruler
Builds on: m05.5 + m01.2 + m01.3
m05.5 finds audio onsets within ~80 ms of a visual change; I render each such moment as a single image: the motion-history frame on top, and beneath it a 3-second spectrogram slice aligned to the same x-axis, with a vertical line at the onset and the visual-change time. The agent reads "sound came first / together / after" and the motion direction in one 1-1.5k-token image, with no audio tagger vocabulary. Neither parent had a picture that carries both channels and their lag.

### m01.r1.2 The sidecar is a lazy ledger: the hook writes only a card, every later `look` appends to it
Builds on: m02.1 + m01.4 + m02.2
The UserPromptSubmit hook (m02.1) runs only T0 (ffprobe, I-frame map, ~5 s) and writes the card. Everything deeper is stateless `look --at --span` (m01.4), but each answer is appended to the sidecar as a hash-keyed layer, so the ledger grows only with real questions. The video's analysis becomes a record of what was ever asked, which makes m02.8's "what earns its keep" log free: the ledger is the usage data. Neither parent had a sidecar whose contents are demand-driven instead of pre-computed.

### m01.r1.3 Event-boundary pairs as the stateless unit of `look`
Builds on: m05.4 + m01.4 + m01.7
Instead of a grid for `--at T --span S`, `look` returns before/after pairs at each detected boundary with a changed-region crop (m05.4), plus a one-line delta written by a small VLM from that pair only (m01.7). Because the unit is a pair, no whole-video segmentation is needed and a range can be answered cold. It adds a causal log that is built lazily per range rather than for the whole file.

### m01.r1.4 Ten times larger: record-time capture for every video the agent itself produces, with the pixel pipeline as the legacy path
Builds on: m05.1 + m01.1 + m02.1
m05.1 tracks the cursor; I go further and say the agent's own tools make most of the repro videos (Playwright, bsk, cua-driver). Each of those tools can emit a timeline sidecar (action, target, DOM/console/network delta, timestamp) at the moment it drives the browser, and the hook (m02.1) attaches it the same way as a video card. The video file then becomes optional evidence, and the pixel pipeline serves only third-party footage. This removes the hardest ML from the user's most common video with no new daemon.

### m01.r1.5 Reverse-and-shuffle bench run on synthetic videos whose truth we wrote
Builds on: m05.7 + m01.8
m05.7 gives pass/fail controls (reverse, shuffle, mute) and m01.8 gives generated clips with known answers. Combined, a script renders clips (door opens, form fills, tone rises, clap at t=7.3), builds each candidate output (tiles, chronophoto, spectrogram strip, delta log), and scores an agent with the original and the reversed/shuffled versions. The gap between ordered and shuffled is a single number per format for "does this carry time", at zero labeling cost and cents of tokens per run.

### m01.r1.6 Fresh: an honest "ask a model that can hear" escape valve, triggered by the card's own footer
Builds on: m02.7 (new angle)
m02.7's footer already says what the local stack could not tell ("no non-speech audio read"). Make that footer carry one line, `ear: gemini --span 41:10-42:00 "what is the sound?"`, with the printed estimated cost, run only when the agent chooses. Local stays the default and the metered API is reached only for the narrow audio spans the local spectrogram strip could not settle, so the running cost scales with real doubt, not with video count.
