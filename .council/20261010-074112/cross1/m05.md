## Builds
### m05.r1.1 Chronophoto with a sound rail: one image, both clocks
Builds on: m01.2 + m01.3 + m05.3
Compose one image per segment: m01.2's ghosted motion-history picture on top, and m01.3's spectrogram strip directly beneath it, with a single shared time ruler. Add the film-perception piece neither had: a thin vertical "sync line" for each audio onset that falls within about 80 ms of a visual change (m05.5), drawn across both panels. The model then sees "this ghost trail ends where this click line sits", so cause and effect across the two senses is read off one picture at one image's token cost.

### m05.r1.2 The audio-description budget rule applied to the foveated look
Builds on: m04.4 + m05.2 + m04.5
Make `look --at T --span S` (m04.4) pick its own density by audio redundancy: where m04.5's tag strip says "speech" the burst is 2 frames and the transcript carries the span, and where it says "silence", "music" or "typing" the burst is the full 6-8 frames plus a difference mask. The rule comes from audio description craft (describe the picture only where sound does not carry it). It adds what m04.4 left to the agent by hand, a principled default for how many images a span deserves, so the same command costs 1k tokens on a lecture and 1.5k on a silent UI step.

### m05.r1.3 Ledger lines written as SDH captions
Builds on: m04.1 + m05.2 + m04.5
Turn m04.1's blind-spot ledger into captions an LLM already knows how to read: `[14:02-14:40 · no sound · screen busy · 3 frames kept · look 14:02-14:40]`, `[low-confidence speech 22:10-22:31]`, `[music, then silence 31:05]`. The ledger and the audio strip become one stream in SDH bracket style, with the "what I did not perceive" lines in the same format as the "what I heard" lines. This adds a second function to the ledger: the agent gets both the declared holes and the non-speech audio in one grep-friendly text file, and a hole never reads as "nothing happened".

### m05.r1.4 Reverse-and-shuffle controls inside the synthetic bench
Builds on: m04.8 + m01.8 + m05.7
Extend the scripted ffmpeg clips with each pair of controls: every clip is also rendered reversed and with frames shuffled, and the question set includes an arrow-of-time item (does the box move left to right, does the counter go up or down) next to the ordinary ones. Ground truth is still the script, but now each packet format is scored on whether its answer flips when the clip is reversed. A packet that scores the same on forward, reversed and shuffled clips has proved it carries no time, and that check needs no labels and runs in CI.

### m05.r1.5 Action script with measured lag, anchored on sound
Builds on: m04.6 + m01.1 + m05.1 + m05.5
Take m04.6's pixel-derived action script (and m01.1's recorder sidecar where it exists) and add a latency column: for each step, "click at 0:03.2 → modal at 0:03.5 (+300 ms)", with the click time taken from the audio click or keystroke sound when the recording has system audio, since audio is the finer clock. Michotte's launching effect puts perceived causation inside roughly 150 ms of contact, so the script can tag a step "reacted" or "late" or "unrelated". That turns "did the click cause the banner" from a judgement into a measured number, and it is the same script whether the source was a sidecar or a pixel guess, with the source named on each line.

### m05.r1.6 The ten-times version of the retina subagent: a viewer that returns a film-style shot list
Builds on: m04.2 + m01.7 + m05.4
Run m04.2's subagent viewer on every event boundary pair (m05.4, the state before and the state after) and have it write m01.7's one-line delta, but constrain its output to a shot-list grammar: shot number, time, what entered, what left, what moved, what sound was under it. A 1-hour video becomes a few hundred such lines, produced in throwaway contexts, with zero image tokens in the main session. What it adds is a fixed vocabulary borrowed from continuity editing, so the main agent can grep "left" or "entered" and the lines can be compared across runs for the bench.

### m05.r1.7 Fresh idea: a "two-speed" index so 2x viewing is the default
Builds on: m05.6 + m01.4 + m04.4
Reading m01.4's stateless look made me see that people already watch at 2x with no loss of gist, because gist survives at roughly 13 ms per image and low detail. So the first reply from the stateless command is a constant-size trailer (m05.6) of tiny tiles at 10 to 20 times speed, and `look` is the slow lane. The trailer is computed from a single fast decode pass at 128x72 that framesift already does, never touches ASR or embeddings, and caches by content hash, so the daily cost is seconds and the deep passes only run where the agent points.
