## C04 Make sound legible: spectrogram strip, sound score and SDH captions

## The concept

The agent has no ears, and the bench never measured sound. Today audio reaches it only as a transcript, plus one number (audio novelty) that is used to place cuts and then thrown away. C04 turns every non-speech property of the soundtrack into something the agent can already read: bracketed text lines in the style of subtitles for the deaf and hard of hearing (SDH), and, only where text cannot carry it, one picture of the sound on the same time axis as the frames.

What stays from the pitch, and is the surprising part:

- **The agent is treated as a deaf viewer, and a mature craft is borrowed.** SDH has written rules for what to caption (W3C: captions include "non-speech information conveyed through sound, including meaningful sound effects"), and audio description has the matching spend rule (WCAG: if everything important in the picture is already in the audio, no description is needed). LLMs have read a great deal of both formats, so no new vocabulary has to be learned. The storyboard's stat lines ("visual 1.51 · audio 0.63") are replaced by captions.
- **Spend follows audio redundancy.** Where speech carries the scene (lecture, podcast), the agent gets text only. Where sound is silent, musical or mechanical (a silent repro, a UI with clicks), it gets images. This is the budget rule, not a style choice.
- **The unit is a podcast map in under a minute.** A 1-2 hour episode gets one line per minute with an energy sparkline, speaker turns, silences over 3 s, music/laughter/applause tags, and pace and loudness shifts, with a hard cap of about 1.5k tokens. This is the case where frames carry nothing.

What changes after developing it (honest correction to the pitch): the pitch says a vision model reads a spectrogram "well enough". The evidence says that is weak for naming sounds and plausible for timing and shape. So the design splits the job:

- **Text tags do the naming** (a small tagger decides "laughter", "music", "alarm").
- **The picture does what tags cannot:** onset timing relative to a visual change, rhythm and repetition (count of beeps), pitch or loudness contour (rising, falling), and "something is there that no tag covers". It is optional and must pass a test (below) or be dropped.

Who it is for: the agent harness (Claude Code), operated by Sam on the M1 Pro. Primary cases are 1-2 h English and Vietnamese podcasts and lectures (the map), and screen recordings with system audio (clicks, errors, notification sounds, cause and effect with the picture).

## How it works

**Stage 0, free: signals framesift already computes.** `audio.py` already builds 50 ms RMS, 40-band log-mel, silent runs and pauses over 16 kHz PCM, on the buffer ASR also reads. From this alone, with no model: loudness curve, silence list (the pauses over 3 s), an energy sparkline per minute, onset times (for the later coincidence check), and speech/non-speech split from the ASR cue spans.

**Stage 1, one small model: a general audio tagger on the same PCM.** Candidate: CED (distilled AudioSet tagger, 16 kHz, 64-band mel, ONNX export in the repo, 10M-parameter model at 49.0 mAP on AudioSet per its paper). Fallback candidate: YAMNet (521 AudioSet classes, MobileNetV1, 3.7M weights, but only 0.306 balanced mAP, i.e. noisier). Alternative that costs nothing extra if it works: Whisper-AT reports audio tags from the Whisper backbone for under 1% extra compute, but it is tied to the PyTorch Whisper, not to faster-whisper/parakeet-mlx that framesift uses, so it is a swap-in only if the ASR backend is changed anyway. I have not run any of these; picking the tagger is step one of the first move.

Raw 521-class output is not shown. It is collapsed to a short vocabulary (speech, music, laughter, applause, alarm/beep, click/typing, silence, noise, other) with hysteresis and a minimum duration, so one line per event, not one per frame. Anything the tagger scores low but the energy curve shows (a transient) is printed as `[unclassified sound]`, never dropped.

**Stage 2, the sound score (text).** One stream, SDH bracket style, merged with the ledger of what was not perceived (this is cross2/m02's receipt idea, m05.r1.3):

```
[ep.mp3 · 1h45 · en · sound score · 61 min lines · 1.4k tokens · 3 holes]
00 ▂▃▃▅▃▂▂▃  2 speakers, host leads; [music intro 0:00-0:22]
07 ▃▃▅▇▅▃▃▂  [laughter 7:41] [speaker 2 louder, faster 7:30-8:10]
14 ▁▁▁▁▂▃▃▃  [silence 4.2 s 14:02] (only one speaker, other muted?)
31 ▂▂▂▂▂▂▁▁  [low-confidence speech 31:05-31:40 · look 31:05-31:40]
```

Tone of voice is approximated by loudness and pace relative to that speaker's own baseline, and the footer says so. Low-ASR-confidence stretches and unclassified sounds are written as holes with a ready command, so a hole is never read as "nothing happened".

**Stage 3, the strip (picture, only where earned).** `look --at T --span S` returns, in addition to frames, one image: log-mel spectrogram (about 3-30 s), loudness line, silence shaded, ASR words on top, tick marks shared with the frames, and a vertical line at each audio onset that falls within about 80 ms of a visual change (m05.5 coincidence). That makes "sound came first / together / after" readable in one 1-1.5k-token image. The audio-description rule sets density: in speech spans the burst is 2 frames and no strip; in silence/music/typing spans it is 6-8 frames plus the strip (m05.r1.2).

**Stage 4, escape valve (optional, agent-triggered).** The footer prints one line, e.g. `ear: <command> --span 41:10-42:00`, for the narrow spans the local tagger and strip could not settle, with the estimated cost printed. Gemini's API documents 32 tokens per second of audio and non-speech sound understanding, so 50 s is about 1.6k audio tokens. This is a manual path for doubt only, never run by default (m01.r1.6).

**Where it fits in the code:** a new `tagger.py` (about 150 lines: load ONNX, window, collapse, hysteresis), a `soundscore` writer in `render.py` replacing the stat lines, and a strip renderer using `matplotlib`-free numpy/PIL (logmel is already in `signals.npz`). The `[audio]` extra gains `onnxruntime`.

## First move

This week, in order, each step a gate for the next:

1. **Write the synthetic-clip generator (about 60 lines, ffmpeg + numpy).** Clips with a known key: beep at 3.2 s, 5 s silence, 7 beeps at 1.9 s period, a rising tone vs a falling tone, a clap on a visual flash, a music bed that starts at 40 s, a laughter-track segment (use a licensed sample). Render each also reversed and muted (the controls from m05.r1.4 / m04.r1.5).
2. **Run Stage 0 only** (silence list, onsets, sparkline) on the clips and on one real 1h45 podcast already in the bench. Score the sound score on the clips' key with a script, no agent. Zero new dependencies.
3. **Add CED (ONNX) on the same clips and the podcast**; measure tag accuracy against the key, seconds per hour of audio on the M1 Pro, and the vocabulary collapse. Decide CED vs YAMNet here.
4. **Only then** run the agent bench: 20 audio questions (when does the music change, how many beeps, did the sound come before the dialog, is the second tone higher), four arms: transcript only, + text sound score, + strip only, + both. The arm "strip only vs text score" decides whether Stage 3 is built at all.

## What must be true, and the cheapest test

| Claim that must hold | Cheapest test | Kill / adjust rule |
|---|---|---|
| The agent answers non-speech audio questions from text tags far better than from the transcript | Step 4 arms 1 vs 2 on the synthetic key plus 10 questions on one real podcast and one repro with system audio | If arm 2 is not clearly above arm 1 (transcript-only will be near chance on these), the tagger is wrong or the vocabulary is, not the idea |
| The tagger is accurate enough on speech-dominant long audio, where music and laughter sit under or between voices | Compare tags to hand-labelled 10 minutes of the real podcast; count false music/laughter per hour | More than a few false tags per hour makes the score worse than silence (an invented `[laughter]` is a lie); then print only high-confidence tags and call the rest holes |
| A strip image adds information over the text tags | Arm 3 vs arm 2 on rhythm, pitch-direction and lag questions only | If the strip does not beat tags on those, drop Stage 3 (the parents said the same: test the spectrogram still and drop it if it does not pay) |
| Vision models read spectrograms for timing and shape even though they name sounds poorly | The same arms, with the mel scale and time ticks labelled | Published results are mixed: GPT-4o reached 73.75% on 10-class ESC-10 with 10 examples in the prompt (human experts 72.5%), 59% cross-validated, and 14% on 50 classes. So zero-shot naming from a picture should be expected to fail; only the timing/shape role is on trial |
| The sound score fits the budget at 2 h | Token count of the output for the 1h45 podcast (target at most 1.5k for the map, about 60 lines) | If larger, raise the merge threshold; never show every event |
| Non-speech audio matters enough for Sam's daily videos to pay for any of this | Count, in the last month of Sam's real videos, questions he would ask about sound; if almost none, ship Stage 0 (free) only | This is an assumption about use, not a measurement. I did not have this data |

Stated limits I could not close: I did not run any model, so tagger accuracy, speed and the strip's value are all unmeasured. Vietnamese speech is the case I am least sure of: tag models are trained on AudioSet (YouTube, mostly English-region), and laughter/music tags should transfer, but speaker-turn and pace baselines come from ASR and diarisation, which framesift does not have today (no diarisation exists in the code; "who speaks" would need a new component, so v1 prints turns by pause and ASR cue only, not by person).

## Prior art (with URLs)

Close things that exist, plainly:

- **Speechmatics Audio Events** already detects and labels music, laughter and applause inside an ASR job, as a paid API. https://docs.speechmatics.com/speech-to-text/features/audio-events . Same output idea; differs by being hosted and metered, and not designed for an agent budget or paired with frame selection.
- **Whisper-AT** puts audio tagging on the Whisper backbone for under 1% extra compute. https://arxiv.org/abs/2307.03183 . Closest to "free tags with the ASR pass"; the catch is the backbone (PyTorch Whisper, not framesift's backends).
- **CED, YAMNet** are the practical local taggers. https://github.com/RicherMans/CED (10M parameters, 49.0 mAP, ONNX export, per https://huggingface.co/papers/2308.11957), https://github.com/tensorflow/models/tree/master/research/audioset/yamnet (521 classes, 3.7M weights, balanced mAP 0.306 via https://github.com/antonyharfield/tflite-models-audioset-yamnet).
- **VLMs reading spectrograms:** https://arxiv.org/html/2411.12058v1 . Few-shot spectrogram classification works for few classes (GPT-4o 73.75% on ESC-10 first fold vs 72.5% for ensembled human experts) and collapses with many (59% on ESC-10 cross-validated, 14% on a 50-class subset). Also an informal demo of a vision model naming barking from a spectrogram: https://www.llmrumors.com/news/astra-spectrogram-sound-identification (weak source, a news blog). This is the evidence for "tags name, picture shows shape".
- **Audio-capable LLMs (a different route, not local-text):** Gemini documents 32 tokens per second of audio and understanding of non-speech sound, up to 9.5 h per prompt. https://ai.google.dev/gemini-api/docs/audio . This is the "ask a model that can hear" valve, and also the strongest competitor to this concept: if the harness gains native audio input, Stages 1-3 become less necessary, though the 0-cost map for 2 h audio would remain cheaper than 2 h x 1,920 tokens per minute (about 230k tokens).
- **Accessibility craft the format borrows:** W3C on captions including meaningful non-speech sound https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded , and on audio description being unnecessary when the audio carries the information https://www.w3.org/WAI/WCAG21/Understanding/audio-description-prerecorded.html .

I found no tool that outputs SDH-style text plus a same-axis spectrogram strip as input for a text-and-image agent with a token budget and a declared-gaps footer. I searched briefly, not exhaustively, so "none found" is not "none exist". What is still different: the budget rule (spend by audio redundancy), the ledger of unperceived stretches in the same bracket format, and the onset-lag check across the two senses.

## What it costs to run

- **Infra ($/mo):** nothing recurring. Local CPU only; no API in the default path. The optional `ear:` valve costs money only when the agent chooses it (about 1.9k audio tokens per minute at Gemini's documented rate), so spend scales with real doubt.
- **Operational:** no daemon, no server. One extra model file (CED ONNX, tens of MB; I did not verify the exact size) downloaded once and pinned by hash. What can break: a wrong tag silently misleading the agent. Mitigation is part of the design: confidence floor, `[unclassified sound]` rather than guessing, a footer naming what the tagger cannot tell, and the synthetic-clip check run as a self-test (a `doctor` run that fails if the beep at 3.2 s is not reported).
- **Per-run time and tokens (estimates, not measured):** Stage 0 is seconds (the log-mel is already computed in the existing 8.2 min for a 1h45 podcast); the tagger adds CPU time that must be measured in step 3 and should be well below ASR time, since the model is small; the output is about 1.4-1.5k tokens for a 2 h episode versus 207 KB storyboard / 78.7k session tokens measured today for the long-video arms. Strips cost about 1-1.5k tokens each, only when `look` is called on non-speech spans.
- **Maintenance:** one new module and one dependency (`onnxruntime`); one vocabulary-collapse table (the only knob, kept inside the code, not a flag); one more bench set (the synthetic generator doubles as the regression test for time and sound claims). No sync steps, no cache protocol beyond the existing outputs.
- **Biggest hidden cost:** false positives in tags on speech-heavy audio, and Vietnamese. If the first real-podcast check shows many, the cost is trust, not money, and the fix is to print fewer tags, not more.

**Runs:** adds one small local ONNX model and one Python dependency (`onnxruntime`); nothing else new, no daemon, no hosted service by default.
