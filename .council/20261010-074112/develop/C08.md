## C08 Zero invocation: hook-made tiered sidecar with a fixed-size trailer and receipt

## The concept

**For:** Sam, on the M1 Pro, in Claude Code, who drops a video path or YouTube link into a prompt several times a week and today has to remember `framesift analyze VIDEO -o OUT --asr --index`, pick an output folder, wait 1 to 8 minutes, then find the right file.

**What it is:** Nobody invokes the sensor. The hook sees the video, does the cheap 5 to 20 seconds of work inline, starts the expensive work detached, and replaces "run a pipeline" with "read a receipt". The surprising core, which must survive development, is four things together:

1. **No invocation.** The only trigger is the prompt Sam already types. No daemon, no CLI to remember.
2. **A trailer whose size does not depend on the video.** A 90 s repro and a 2 h podcast produce the same-shaped first answer (about 1.5k tokens of text, plus one small image file the agent may open). The agent's per-video cost is a constant, not a function of length.
3. **A receipt as the first line of everything.** It states tier reached, tokens spent, and the holes (what was not perceived). It turns "crashing beats corrupting" into a visible line. A hole never reads as "nothing happened".
4. **Layers are files named by content hash, each stamped with tool and model versions.** So heavy work can be done later or elsewhere (home GPU box over rsync) and stale evidence is relabelled instead of silently mixed in.

**Honest limit, stated first:** a hook injects text only (`additionalContext` is a string). It cannot push an image into context. So "trailer" means a text block injected by the hook, plus an image file (tile strip with a sound rail) whose path is in the block; the agent chooses to `Read` it. This is a feature: the 150 to 1.5k tokens the hook spends are all text and fully metered.

## How it works

**Trigger.** A `UserPromptSubmit` command hook. Facts from the Claude Code hooks reference (https://code.claude.com/docs/en/hooks): the default timeout on this event is 30 s; a hook that times out has its output (including `additionalContext`) discarded and the prompt goes through without it; `additionalContext` is capped at 10,000 characters (over that, it is saved to a file and replaced by a path plus a 2,000-char preview); `async: true` hooks run in the background and cannot add context. So the design is: inline T0 must finish in well under 30 s (target under 10 s), and everything else is a detached process the hook starts with `setsid`/`nohup` and returns.

**Detection (no flags).** Regex over the prompt for an existing path with a video/audio extension, a `~`-expanded path, or a YouTube/URL pattern. No match: hook exits silently and prints nothing (zero tokens on every non-video prompt). Match: compute key = `sha256(first 1 MiB + size + duration)` for files, or `yt:<video-id>` for YouTube. Sidecar dir: `~/.cache/framesift/<key>/` (cache, not next to the file, so Downloads and screen-recording folders stay clean; the pitch said "next to the file", but a cache dir avoids polluting synced folders and lets the GPU-box rsync use one root). A symlink `clip.mp4.fs -> cache dir` is optional, off by default.

**The ladder (each rung is a separate file with a header: `tool=framesift@0.3 model=... made=...`):**

| Tier | Made by | When | Contents | Budget |
|---|---|---|---|---|
| T0 trailer | hook, inline | 5 to 20 s | ffprobe facts; I-frame/packet-size map; existing 128x72 pass; log-mel novelty; **trailer text** (duration, language guess from first 20 s, pacing curve as ~12 numbers, sound bar as one char per slice: speech/silence/other-loud, silence stretches over 3 s listed, saliency peaks as candidate chapters); **one strip image** (tiny tiles on a shared time axis with the sound rail beneath; a 128x72 tile is ceil(128/28) x ceil(72/28) = 5 x 3 = 15 visual tokens per the vision doc formula, so even 40 tiles is under about 1k tokens before packing) | text 1.5k tokens max, fixed |
| T1 | detached | minutes | sparse keyframes by drift, contact sheets, motion stills for the segments the question or the log points at | 12-tile sheets |
| T2 | detached | minutes | ASR (profile picks model: Vietnamese -> whisper large-v3-turbo; English -> faster-whisper small; YouTube -> captions first, see below), words printed against the strip | text |
| T3 | detached or GPU box | later | embeddings index, VLM delta log per event pair | text/index |

**Profile by content type, no flags, choice printed in the receipt.** Screen recording (no or little audio, low colour variance, UI-like pixel stats) -> image-heavy density, speech skipped unless audible; lecture/podcast (speech fraction high, little pixel motion) -> sound score and chapters first, images capped at a handful; film/explainer -> default. The rule is the audio-redundancy rule (describe pictures only where sound does not carry them; parent m05.r1.2), written as a 3-row table in code, not as knobs.

**The question steers only the slow lane (parent m02.r2.2).** T0 is a pure function of the file and is shared across prompts. The hook also sees Sam's sentence and may use it only to choose which spans T1/T2 work on first and which `look` spans the digest lists. A second prompt about the same video costs almost nothing.

**The receipt (first line, always):**
`[clip.mp4 · 1h45 · en · TALK · tier 0 of 3 (T1,T2 running) · sound score ready · 3 frames kept · holes: 4 · 1.4k tokens · last asked: 8:02]`
Holes are SDH-style bracket lines under the trailer, each with a ready command: `[14:02-14:40 · no sound · screen busy · 3 frames kept · look 14:02-14:40]`, `[low-confidence speech 22:10-22:31]`. The packet is assembled against one constant budget with a drop order (facts and sound score last to go; ledger strips and echo first), and the footer prints `dropped: ...` so a cut is labelled (parent m04.r2.1).

**YouTube.** Captions first via yt-dlp (`--skip-download --write-subs --write-auto-subs`, https://github.com/yt-dlp/yt-dlp), which gives a transcript in seconds with no ASR. Caveat: auto-subs are not guaranteed present and are lower quality than whisper, so the receipt says `captions: auto` or `captions: none -> ASR queued`. Video download for frames is a lazy T1 step with a cache size cap and LRU eviction (parent m02.6), never done inline.

**Heavy layers on the home GPU box (parent m02.r1.6).** A T2/T3 layer is a hash-named folder. When `ssh gpu-box` answers within 2 s, a detached job rsyncs the source (or only the audio), runs the heavy model there, and rsyncs the folder back. When it does not answer, nothing happens and the receipt says `tier 2 pending: GPU box off`. The Mac never waits. No daemon on either side: the box runs the job over ssh and exits.

**Staleness (parent m04.r2.6).** Each layer header carries tool and model ids. On read, a mismatch relabels the line `made by older version, re-run tier N` (or recomputes if cheap). One version string per file, no job to watch.

**Failure rules.** Hook timeout, ffprobe error, unreadable file, full disk: the hook prints one line `[clip.mp4 · sensor failed: <reason> · nothing injected]` and exits 0 so the prompt still goes through; a crash never silently produces a thinner card without a label. Detached jobs write `status.json` (`running|done|failed:<reason>`), and the next hook run reads it and reports it in the receipt. That is the entire monitoring story.

**Details taken from the parents that the pitch dropped:**
- Priming guard (m05.r2.4): inject only a plain-fact block (duration, language, sound events, ledger counts; no adjectives or cause words); the interpretive block (shot list, "reacted", chapter titles) is a file, never pushed.
- "order: not carried" check (m05.r2.6): on each real file, build the T0 event line forward and on the reversed decode and compare; if identical, the header says so instead of letting the agent assume order is carried. Cost: one extra seconds-long pass on the 128x72 data.
- Exact vs inferred label (m02.r1.3, m04.r2.4): the card says `events: exact` when a recorder/agent-tool sidecar exists next to the file, `events: inferred from pixels` otherwise. One row schema with a `source` column.
- Lazy ledger (m01.r1.2, m02.r2.5): every `look` answer is appended to the sidecar as a hash-keyed layer, and the per-video question log promotes asked-about spans to the next tier on the next run. Usage data comes free.
- The ear valve (m01.r1.6, m03.r2.4): the footer prints `ear: <command> (est. cost)` for non-speech audio spans the local strip cannot settle; metered API only when the agent chooses, with a visible monthly cents budget in the sidecar header. Default is off.
- "Yesterday" digest (m02.r2.6): the hook can list the three newest videos in Downloads/screen-recording folders with their T0 receipts so Sam can say "the repro from this morning". Optional and last.
- Handoff line (m03.r2.6): when the perceived fraction is low or a hole sits where the question points, the last line is `watch: 14:02-14:12 <clip path>` cut with existing `split`.
- Doctor (m02.r2.3, m03.r2.5): `framesift doctor` renders synthetic clips forward/reversed/shuffled/muted plus empty and decoy clips, runs the real pipeline and diffs the card against the scripted expected sidecar. Prints "carries time: yes/no", "carries sound: yes/no", false-claim rate.

**Drop from the pitch (kept as optional, not core):** the retina-subagent default (m02.r2.4). Parent m04.r2.2 already showed a viewing subagent starts with its own ~60k fixed overhead, so it likely costs more than a direct look below a measured crossover. Keep the plain card as the default.

## First move

This week, in order, each step a day or less:

1. **Measure the hook before building anything.** Write a 30-line `UserPromptSubmit` hook (shell + Python) that regex-detects a video path, runs `ffprobe` and the existing 128x72 decode plus audio novelty on it (framesift already has `decode`, `visual`, `audio` modules), and prints `additionalContext` with duration, silence stretches and a 12-number pacing curve. Time it on the 2:23 explainer, the 1h45m podcast and one screen recording. The pass/fail number: **T0 text under 10 s wall on the 1h45m podcast, and under 1.5k tokens.** Check that a non-video prompt costs 0 tokens and under about 100 ms of added latency.
2. Render the T0 strip image (tiles + sound rail on one axis) and have a fresh Claude Code session `Read` it for three questions it has never been asked in the bench.
3. Add the receipt line and `status.json`; start the detached T2 (ASR) job from the hook and confirm a second prompt on the same file gets `tier 2 ready` without redoing T0.

Do not build GPU rsync, YouTube cache, profiles or the digest yet; they are only worth building if steps 1 to 3 show the hook is stable.

## What must be true, and the cheapest test

| # | Must be true | Cheapest test | Kill condition |
|---|---|---|---|
| 1 | T0 (no ASR, no embeddings) finishes inline in under about 10 s on a 2 h file | Time the existing decode+audio passes on the 1h45m podcast (framesift already decodes every frame at 128x72; the earlier full run was 8.2 min including ASR and index, so the T0 share is unmeasured: this is the unknown to measure first) | If T0 alone is over about 25 s on a 2 h file, the 30 s hook timeout makes inline unsafe: make T0 detached for long files and inject only the receipt `T0 pending`, which weakens the "instant first answer" claim |
| 2 | The trailer carries information that beats "keyframes + transcript" on temporal and sound questions | Use the planned synthetic-clip bench (ball bounces 7 times, beep at 3.2 s, A->B->C UI, 5 s silence), ~20 questions, two arms: trailer+strip vs current storyboard+sheets. Score correct answers per 1,000 tokens and run the reversed/shuffled/muted controls. Costs cents of tokens and zero labelling because the script is the key | If the trailer does not beat the baseline on counting/order/sound by a stated margin, T0 should be only the receipt and holes, and the novelty is in the hook, not the strip |
| 3 | The agent actually uses the injected block and the file paths | Log one line per injection: tokens injected, and whether the session later `Read` a sidecar layer or ran `look` (the hook-with-token-meter, m03.r1.5). Two weeks of Sam's real use | If under about 1 in 4 injections is ever followed by use, the injection is waste: shrink it to the one-line form ("video: 41:20, speech, 3 layers cached", ~40 tokens) per parent m01.r2.4 |
| 4 | Detection has low false positives | Run the regex over 100 of Sam's past prompts from `~/.claude/projects/*.jsonl` and count wrong triggers | More than about 2 percent false triggers means require an explicit marker or an exact-extension-plus-exists check only |
| 5 | Detached jobs are reliable without a daemon | Kill the Mac mid-ASR and confirm `status.json` plus a content hash lets the next hook run resume or restart cleanly with a labelled receipt | A stale half-written layer that is read as complete: fix by writing to temp name and `rename` (atomic), never skip the check |
| 6 | The sound bar is not wrong in ways that mislead (speech vs music vs silence) | Doctor's muted/decoy/empty clips; false-claim rate printed | If the cheap sound classifier mislabels often, print only silence stretches and loudness, which are measurable, and drop the type labels |

Unknowns I could not settle from local files or the web: the T0 timing on a 2 h file (test 1), and whether an agent can read a strip with tiny 128x72 tiles well enough to answer motion questions (test 2). I did not run any of this; no code was executed for this document.

## Prior art (with URLs)

Close things exist; plainly:

- **Video-to-agent MCP servers and plugins already exist.** `popcorn` (scene detection, local transcription, keyframes, all local, as a Claude Code MCP plugin): https://github.com/haithamelmengad/popcorn . `mcp-video-analyzer` (transcript, key frames, OCR, timeline, metadata for local files and many platforms, with a `/video` plugin): https://github.com/guimatheus92/mcp-video-analyzer . `media-context-mcp` (frames, transcription, OCR): https://github.com/vishalguptax/media-context-mcp . `claude-real-video` (scene-aware keyframes + timestamped transcript as a skill): https://github.com/HUANGCHIHHUNGLeo/claude-real-video . `mcptube-vision` (YouTube to a searchable knowledge base with vision): https://github.com/0xchamin/mcptube . `vidlens-mcp`: https://github.com/thatsrajan/vidlens-mcp . A YouTube transcript MCP: https://mcpservers.org/servers/github-com-kimtaeyoon83-mcp-server-youtube-transcript . I read only the repository landing pages (the READMEs were truncated in my fetch), so I cannot say how each handles timing or hooks; from their descriptions, all are invoked as tools or commands by the agent and return keyframes plus transcript, which is the shape framesift already has.
- **What is still different here:** (a) invocation by hook on the prompt the user already types, with the sidecar and receipt, rather than an MCP tool the agent must decide to call; (b) a size that does not grow with video length; (c) a visible receipt of holes; (d) content-hash layers with version stamps and an optional remote fill; (e) the planned time and sound controls (reverse, shuffle, mute). I did not find a tool doing (a) through (c); my search was shallow (one web search plus landing pages), so treat that as "not found", not "does not exist".
- **Hook facts relied on:** https://code.claude.com/docs/en/hooks (UserPromptSubmit 30 s default timeout, output discarded on timeout, `additionalContext` 10,000-char cap, `async` hooks cannot add context).
- **Image token arithmetic relied on:** https://platform.claude.com/docs/en/build-with-claude/vision (cost = ceil(width/28) x ceil(height/28) visual tokens per image; 1000x1000 = 1296; 1568-token ceiling on the standard tier). Note this implies a 12-tile contact sheet and a 768 px frame cost about the same only if the sheet is large; a small tile strip is cheaper, which the trailer exploits. This formula applies to the API vision docs; whether Claude Code's `Read` of an image uses exactly the same accounting I did not verify.
- **YouTube captions:** yt-dlp subtitle options discussed at https://github.com/yt-dlp/yt-dlp/issues/9371 and https://github.com/yt-dlp/yt-dlp/issues/7496 (auto-subs vs written subs, and that downloads can fail; the receipt must label which was used).

## What it costs to run

- **Infra $/month:** $0 by default (local ffmpeg, Whisper, llama.cpp started per command, no hosted service). Home GPU is already owned; it is used opportunistically. The one metered path is the optional ear valve (off by default; per-call cost printed; monthly cents budget in the sidecar header). Not quantified here because it depends on the API chosen.
- **Per-turn tokens:** 0 on non-video prompts. On a video prompt, the injected text is bounded by design at about 1.5k tokens (hard cap well under the 10,000-char hook limit), and the one strip image is only paid for when the agent reads it. Against the roughly 63 to 65k tokens of fixed session overhead, this is under about 3 percent. The bench showed equal total tokens between arms around 72k for a one-question session, so the claim to prove is better temporal/sound answers at the same total, not fewer tokens.
- **Disk:** the cache grows per video (frames, sheets, strip, audio features, ASR text, plus a YouTube download when T1 runs). Needs a size cap with LRU eviction and a one-line `framesift cache` report; unquantified until measured. Content-hash layers can be deleted and rebuilt, so eviction is safe.
- **Operational burden:** no daemon. Failure modes to watch: a hook that adds latency to every prompt (mitigated by silent exit on no match and a 10 s inline cap), a detached job that dies (mitigated by `status.json`, atomic rename, and a receipt line), a stale layer after a tool or model update (mitigated by version stamps), and the GPU box being off (mitigated by labelled pending state). What pages Sam: nothing; what he sees: a wrong or `sensor failed` receipt line.
- **Maintenance:** knobs to keep up: the content-type profile table (3 rows), the drop-order table, the hook regex, the layer version strings, the doctor clips. Surface deliberately not added: no config file for tuning, no per-user thresholds, no MCP server, no database. The hook becomes a new moving part tied to Claude Code's hook contract (timeout and 10k-char cap came from the current docs and can change), so pin a check for them in `doctor`.
- **Development:** lowest weight; the first move above is about a day.

**Runs:** one `UserPromptSubmit` hook entry in settings, short-lived detached jobs it starts (ASR, optional rsync to the GPU box over ssh), and a cache directory. No daemon, no server, no hosted service, no new metered API unless Sam turns the ear valve on.
