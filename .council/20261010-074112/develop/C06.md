## C06 Event-boundary pairs and the foveated look

## The concept

**Who it is for.** Claude Code (reads text and stills, cannot hear, cannot take video) on Sam's repros, tutorials, lectures and podcasts. Sam runs it; the agent consumes it.

**What it is.** Stop shipping frames. Ship *events*. An event is a boundary where the picture changed, drawn as one image: `before | after | changed-region crop` (or an outline on the after frame), plus the words spoken in that window and one measured line: `still changing at the after frame: yes/no`. A video becomes a text timeline of 5-15 such pairs (not 80 keyframes). Cause and effect is two adjacent pairs. The timeline is the wide, cheap periphery. The `look --at T --span S` call is the fovea: it always returns a pair for that span, and escalates to a burst or chronophoto only when the measured flag says the picture is still moving. Burst size follows audio redundancy: 2 frames under speech (the transcript carries the span), 6-8 frames plus a difference mask in silence, music or typing.

**What stays surprising (the core to keep).**
1. The unit is the comparison, pre-drawn, not the frame. The model is not asked to find the difference across two separate images (m03.7, m05.4, m04.7).
2. The agent never trusts a classifier. `look` does not guess "discrete vs continuous" (m04.r2.3 killed that). It reports one measured fact, and tokens are spent on a burst only when that fact says so.
3. Image budget follows what sound already carries (m05.r1.2, from audio-description craft): the same command costs about 1k tokens on a lecture and about 1.5k on a silent UI step.

**What this is not.** Not a new storyboard, not a card/ledger/layer store. It replaces "pick keyframes by drift" with "pick boundaries, show the delta". The existing pixel and codec signals already compute the boundaries; the new part is the pair renderer and the flag.

**Details recovered from the parents the pitch dropped.**
- Boundary = last frame of the previous state plus first *stable* frame of the next (m05.4). framesift already has `_stable_pick` in `keyframes.py`; reuse it for the "after" frame. The "before" frame is the last stable frame before the boundary.
- Audio onset within ~80 ms of a visual change marks a cause candidate (m05.5): print `+300 ms` lag lines like `click 0:03.2 -> modal 0:03.5`. Run a tagger only on windows around coincidences, not the whole file.
- Slow-drift channel (cross2/m05): a second detector for changes that never crossed the event threshold (progress bar, fade, 2 px/s slide). A "nothing happened" line is written only when both detectors were quiet. Add only if the synthetic test below shows the main detector misses these.
- Lazy and stateless (m01.r1.3): a pair can be computed cold for any range, so `look --span` needs no whole-file segmentation. Whole-file pass is only the timeline.
- Camera footage has no discrete events, so the pair design is weakest there (m03.7 admits it). The measured flag is the fallback: flag = yes escalates to the burst, which replaces evenly spaced frames.
- Honest wording (cross2/m05): every line is a measured fact with a handle (timestamp, frame path) or a labelled gap. Never "saw".

## How it works

1. **Boundaries.** From the existing `signals.npz` (128x72 pixel stats, packet sizes, log-mel novelty) take frame-difference peaks that follow a quiet period. Merge peaks within about 0.5 s. This is what `segment.py` already fuses; output boundary times instead of segments.
2. **Pair.** For each boundary at t: before = last stable frame before t, after = first stable frame after t. Decode only these frames at 768 px.
3. **Delta.** Per-pixel absolute difference, thresholded, dilated, largest connected region(s). Draw a box on the after frame, and crop it at higher zoom as third panel. If more than about 40 percent of the frame changed (cut, page load), skip the crop and mark `full-frame change`.
4. **Still-changing flag.** Mean difference between frame at t_after and t_after + 0.3 s (from the 128x72 signal, no decode). Over a threshold, `still changing: yes`.
5. **Words.** Transcript cues overlapping `[t_before, t_after + 1 s]`, deduplicated (also fixes the known repeated-cue flaw).
6. **Timeline text.** One line per pair: `3 | 0:03.5 | pair 03.jpg | region right-top | still: no | "now open settings" | sound: speech`. About 40-60 tokens per line; 15 pairs is under 1k tokens of text plus images only on demand. Pairs live as files; the agent reads the ones it needs.
7. **`look --at T --span S`.** Always returns the pair(s) in the span. Count of burst frames: 2 if sound class is speech for more than 70 percent of the span, else 6-8 with neighbour difference masks, and only if the still-changing flag is yes or the span has more than one boundary.
8. **Sound tag.** Cheap first version: energy plus the existing novelty plus voice-activity (speech / non-speech / silence). A YAMNet-class CPU tagger is a later, separately tested add.
9. **Zero-flag default.** `framesift pairs VIDEO` prints the timeline and writes files next to the video (or a cache dir). No flags for the common case.

## What must be true, and the cheapest test

**Must be true**
1. Boundary detection recall on screen recordings is high (it finds the step the question is about), with 5-15 pairs, not 40.
2. A model answers "what changed" and ordering questions better from a pre-drawn pair than from two plain frames (m04.7, untested; see prior art, I found no direct measurement for current models).
3. Keeping the burst only for flag=yes does not hide motion that matters (a slow scroll flagged "no" because the last 0.3 s is still).
4. Speech redundancy holds: when 2 frames plus transcript are shown under speech, answers do not drop against 6-8 frames.
5. On camera footage the design degrades gracefully (flag leads to burst) rather than inventing events.

**Cheapest tests (all on the existing QA bench harness, nothing new to run)**
- *Detector test, free, minutes:* on the synthetic clips, score boundary recall and false positives against the JSON truth. The empty clip must give zero pairs; the decoy must not be reported as the main event; the 20 s fade and 2 px/s slide show whether the slow channel is needed. Kill rule: recall under 90 percent on UI clips means rework the detector before anything else.
- *Arms test, small:* about 30 temporal and 10 audio questions (order of UI steps, what changed between A and B, what happened after the click, count of repeats, when did the beep or music change) on 15 synthetic plus 6 real clips. Arms: (A) keyframes + transcript, (B) uniform contact sheets (the strongest current baseline at 93 percent), (C) pairs timeline + `look`, (D) C without the diff crop (plain before|after), (E) C with the burst always on. Score accuracy and total session tokens. Controls: reversed and shuffled pair order (a design that carries time must drop). Claim to prove: C beats A and B on temporal questions at equal or fewer tokens; D versus C isolates whether the drawn difference matters. If D equals C, delete the crop.
- *Baseline guard (cross2/m01 r2.5):* the existing contact sheets plus a single sound-score line may already match C. If so, ship that and stop.
- Cost to run the arms: Claude Code sessions on a subscription, no new infra.

**Honest limits.** Tone of voice, laughter and music mood are not covered by this concept, only energy, speech and silence classes. Fine motion (what moved where, direction) beyond a burst with masks is a separate problem. Two adjacent pairs is a hypothesis for cause and effect, not a proof.

## Prior art (with URLs)

Close, but different. I found nothing that makes the before|after pair at an event boundary the unit, with a measured escalation flag.
- Frame-extraction MCP servers for Claude: https://github.com/jordanrendric/claude-video-vision (frames plus audio transcription for Claude Code, YouTube via yt-dlp), https://github.com/ethnn-b/vidmcp (keyframes plus transcript), https://github.com/maryfellowes/video-watch-mcp (cloud-hosted via Modal, frames plus Whisper; this one has a hosted cost and a service to watch, which the brief rejects).
- Closest in spirit: https://github.com/littler00t/mcp-deep-video, 14 tools including motion detection, scene cuts, heatmaps, **frame diffing**, Whisper and annotated frame export. It exposes the primitives (the agent has to pick and orchestrate them over many calls) and has no audio-redundancy rule or measured escalation flag. Worth reading before writing the diff code. Not verified beyond its README.
- Local scene and loudness detection with clip export: https://github.com/azhu97/video_mcp (ffmpeg filters plus faster-whisper).
- Temporal benchmarks show why this matters and how to test it: TVBench (https://arxiv.org/html/2410.07752v1, https://daniel-cores.github.io/tvbench/) finds that older benchmarks like MVBench can be solved from a single frame, and that accuracy on real temporal tasks drops when frames are shuffled or reversed. That supports the shuffle and reverse controls above. Also V-STaR (http://arxiv.org/abs/2503.11495v1) on "when / where / what" sequential reasoning, and https://doi.org/10.48550/arxiv.2505.14321 on whether video benchmarks measure temporal understanding at all. I read only the snippets and abstracts, not the papers.
- Image cost facts used here: Claude image tokens are about width x height / 750 (https://platform.claude.com/docs/en/build-with-claude/vision), with a visual budget of 1568 tokens on the standard tier (https://platform.claude.com/docs/en/build-with-claude/vision-coordinates). A Reddit measurement says the formula holds at 1568 px but is off by up to 36 percent at 2576 px on Opus 4.7 (https://www.reddit.com/r/ClaudeCode/comments/1sqw8at/images_cost_3x_more_tokens_in_claude_opus_47/). So keep pairs at 768 px per panel or lower and measure the real token cost on the target model before quoting it.
- Not found: any published test of whether current multimodal models do better with a drawn difference crop than with two raw frames (searched for it, results were unrelated). This is the main thing the arms test must settle, so do not treat it as established.

## What it costs to run

- **Infra:** $0 per month. CPU only, local, ffmpeg and numpy already in the stack. No daemon, no API, no model download for the first version (no embedding server is needed for pairs; `find` stays optional and separate).
- **Per-turn tokens:** timeline under about 1k text tokens for a short video; roughly 3-5 pairs viewed per question at about 1-1.5k tokens each is 3-7k, against an 80-keyframe read. Burst only on flag=yes. Image tokens will be measured, not assumed (see Reddit note above).
- **Compute time:** pair step adds seconds on top of the existing decode pass (the 128x72 signals are already computed; only boundary frames are decoded at full size). A 1h45m podcast has few visual events, so its pair timeline is mostly sound lines; the cost there is the existing ASR.
- **Operational:** nothing to watch. Failure modes are loud: no boundaries found prints "no visual events, N s static" rather than an empty file; undecodable frame raises.
- **Maintenance:** one new module and two thresholds (boundary peak, still-changing level) that must be set once from the synthetic bench, not exposed as flags. The synthetic generator becomes a regression test, which lowers long-term cost. A tagger (if added later) is a new dependency and a version to pin; defer it until the arms test shows non-speech questions need it.
- **Risk to keep honest:** every added line type (slow channel, lag lines, tags) is maintenance surface. Rule from cross2/m01: any line type that does not beat the baseline on the bench is deleted.

**Runs:** nothing new (no service, no schedule, no metered API); one Python module and a test generator inside framesift.
