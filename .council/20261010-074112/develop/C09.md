## C09 Synthetic ground-truth bench with arrow-of-time controls, doubling as install self-test

## The concept

A clip generator whose script is the answer key. Every clip is rendered five ways (forward, reversed, shuffled, muted, and a "nothing happened" or loud-decoy sibling). One harness then asks of any packet format (today's storyboard, uniform sheets, a future motion still, a sound score) four numbers: correct answers per 1,000 tokens, **carries time**, **carries sound**, and **false-claim rate**. The same clips, shrunk to a few seconds, become `framesift doctor`. Doctor tests that the installed tool still perceives, not that ffmpeg exists. The generator also writes the expected card next to each clip, so regression is a text diff of produced card against scripted card, with no agent and no tokens.

What makes it surprising, and what to keep: the controls turn "does this packet help?" into a flip test. A packet that gives the same answer on the forward and the reversed clip has proved it carries no time. Nobody has to label anything. The tool can also run that flip on Sam's real files and print `order: not carried` in the card header, so an invisible failure becomes a printed one.

Who it is for: Sam, as operator, first. He needs a number to decide which of the council's packet ideas (chronophoto, event pairs, sound score, spectrogram strip) deserve to be built at all. The agent is the second consumer, because the header tells it what it cannot trust. It is deliberately not a product feature.

**Where the repo already is (read, not assumed).**
- `bench/sense/make_synth.py` (414 lines) already renders five clips (`ui_flow`, `motion`, `count`, `audio_scene`, `deixis`) with `<clip>.key.json` holding questions, accepted answers and evidence spans. Speech comes from macOS `say`; the rest is PIL and numpy.
- `bench/sense/runs/v02/` holds framesift outputs for those clips. They were never scored.
- The `count` clip (8 lamp flashes, 5 beeps, 12 s) comes out of `analyze` as 2 segments and **1 keyframe**, 0 transcript cues. Nothing in that card can answer "how many flashes" (`bench/sense/runs/v02/count/storyboard.md`). So the bench already has a first failing case. The packet fails and the bench has a known-bad result to show it.
- Missing today: reverse, shuffle, mute, empty and decoy variants. Missing too: a scorer, a card-versus-script diff, and a stable way to run any of it.

So this concept is mostly an extension, not a new build. The brief's "60-line generator" is already 414 lines.

## How it works

**1. Script as a data structure.** Each clip is a list of timed events: `{t, kind: flash|beep|clap|step|move|silence, attrs}`. Today the events live inside drawing code and the key is written by hand. Refactor so the event list is the single source. Frames, audio, `key.json` and the expected card are all derived from it.

**2. Variants, derived by transform of the event list (not by editing video).**

| Variant | How | What it tests |
|---|---|---|
| `fwd` | as scripted | baseline |
| `rev` | reverse video and audio (`ffmpeg -vf reverse -af areverse`); expected events mirrored in time, A to B to C becomes C to B to A, a counter that rose now falls | arrow of time |
| `shuf` | shuffle one-second blocks of picture (and audio) with a recorded permutation | order vs content |
| `mute` | drop the audio track | what the audio layer adds |
| `empty` | same set and duration, no events | invented facts |
| `decoy` | a loud irrelevant event (flash, jingle) while the asked-about event is quiet | wrong "main event" |

Speech is the exception: reversed speech is noise, so the reverse control uses non-speech clips only. A speech clip is covered by mute and shuffle.

**3. Questions that flip.** Each clip carries typed questions (count, order, direction, "what sound, when", "did X precede Y") with the answer computed from the event list. For `rev` the answers are computed from the mirrored list. For `empty` the right answer is "none / cannot tell", and "cannot tell" is a first-class accepted answer. Grading is exact string or number, so nothing needs an LLM judge.

**4. Two scoring tiers.**
- *Tier A, no agent, deterministic, seconds.* Run the real pipeline. Parse `manifest.json`, which is structured, not the markdown storyboard. Extract event-like claims (segment boundaries, keyframe times, transcript cues and, later, any sound-score or event lines) and diff against the expected sidecar with a tolerance (about 0.3 s, to be tuned). This catches regressions in what the card states. It cannot grade images, so it says nothing about whether a sheet "carries time".
- *Tier B, agent, cents.* A fresh `claude -p` call per (packet, variant, question) gets only the packet and the question. Record the answer and the tokens read (the packet's own tokens plus the question; the 63-65k fixed session overhead is excluded and stated once). Compute:
  - correct per 1,000 packet tokens, over `fwd`;
  - **carries time** = accuracy(fwd) minus accuracy(shuf), plus whether answers flip on `rev`. A packet earns "yes" only if it is correct on `fwd`, flips correctly on `rev`, and drops on `shuf`;
  - **carries sound** = accuracy(fwd) minus accuracy(mute) on audio questions;
  - **false-claim rate** = share of `empty`/`decoy` answers that assert something false.
  Use a text-only floor (transcript alone) so a result is always read against the guessing baseline. TVBench found text-only and single-frame models near chance once benchmarks were rebuilt to need time, so the floor matters (see prior art).

**5. Doctor.** `framesift doctor` renders 3 or 4 short clips (about 6 s each, cached by hash after the first generation), runs the real `analyze` with the real installed ASR and, if configured, the embedder, then runs Tier A only. It prints a pass/fail line per capability (`decode`, `visual events`, `audio onset`, `asr`, `index`) and one line each for `carries time` and `carries sound` where Tier A can decide it. A missing dependency or a wrong llama.cpp pin gives a non-zero exit with the one line to run, never a degraded silent run. Tier B stays a dev-only command, not part of doctor, so doctor never spends tokens.

**6. Weekly and per-file checks.**
- Weekly: the doctor result is appended as one line to a stats log (a local JSONL; whether the log lives in the sidecar or `~/.local/state` is open). A scheduled run could be launchd or cron. That is a new thing to keep alive; see costs for the cheaper option.
- Per real file: build the packet for the reversed decode (the tool already decodes everything; reversing the analysis arrays is cheap) and compare event lines. Identical means the header gets `order: not carried`. Caveat below.

**Detail picked up from parents that the pitch dropped.**
- Make the sidecar schema the contract: the generator writes the same `clip.mp4.fs/` layout a real run writes (m03.r1.4), so the schema gets a real consumer before any hook is built.
- Include the dumb-baseline arm (m01.r2.5): existing contact sheets alone and a sound-score line from an off-the-shelf tagger. If that arm ties on temporal and audio questions at similar tokens, new packet formats are maintenance cost with no gain. The bench must be able to kill ideas, not only bless them.
- Include the synchresis clip (m05.5, m04.r1.2): beep and flash 50 ms apart, versus 400 ms apart, versus chance. It tests "did the sound come before the dialog".
- Stable idempotency: seed the RNG, fix the `say` voice. Pin the clips by the SHA-256 of the script, so a changed script is a visible diff.
- Ask for "cannot tell" explicitly in the prompt, otherwise the false-claim rate measures the prompt, not the packet (m04.r2.5).

## What must be true, and the cheapest test

| Must be true | Cheapest test | Fails if |
|---|---|---|
| Synthetic clips predict real-video behaviour. This is the biggest risk. A packet tuned to flat-colour PIL shapes could win on lamps and lose on a screen recording. | Add 2 or 3 real, hand-keyed clips (one screen recording of a repro, one podcast cut with a known laugh or silence). Check the packet ranking on synthetic equals the ranking on real. | Rankings disagree: synthetic stays a regression check only, not a design selector. |
| Reversal is a valid control for the packet, not only for the model. Sheets are laid out in time order, so a reversed clip gives a reversed sheet, and the agent can pass "rev" by reading tile labels (timestamps), not by perceiving motion. | Include a variant with timestamps stripped from tile labels, and compare. | Accuracy on `rev` is high only with labels: the packet carries time only through its own captions. That is a fair result, but state it. |
| The agent's answer variance is small enough to read differences. | Run each cell 3 times at the first pass and report spread. With about 30 questions, a gap under roughly 10 points is noise. | Variance eats the signal: raise question counts per type before trusting any "yes". |
| Tier A can parse the card for events. | Check `manifest.json` carries enough (segments, keyframe times, transcript cues). Today it has no sound-event or counted-event fields. | Tier A can only diff boundaries and cues until a packet format emits event lines; it then has little to say about visuals. |
| "order: not carried" on real files is not a false alarm. | Run reverse-compare on the 5 clips with known order and 3 real files. Count false alarms. | Real footage has symmetric events (a talking head reversed yields the same cues): header warns on files where nothing is wrong. Gate it to files with at least N segment events, or drop it and keep the check in doctor only. |
| The doctor is fast and stable. | Time it on the M1 Pro, repeated 5 times. Target under 15 s and deterministic. | ASR on a 6 s clip plus model load dominates and the result flaps near thresholds. Drop ASR from doctor's default and test it behind `--deep`. |

Honest limits. The bench measures the packet plus the agent, not the packet alone, so results are tied to the agent model; rerun when it changes. Synthetic audio from numpy tones is easier than real music or laughter. A generated applause or phone ring may not stand in for the real thing, so "carries sound: yes" on synthetic audio does not mean yes on a podcast. The reverse-on-real-files header is a heuristic, and the weakest piece of the concept; ship it last.

## Prior art (with URLs)

Close in spirit, different in target:

- **Seeing the Arrow of Time in Large Multimodal Models** (Xue, Luo, Grauman, NeurIPS 2025). Shows LMMs struggle with temporal direction, uses forward-vs-reversed frames as the training signal and introduces AoTBench. Same control, but it evaluates and trains models; it does not score an input packet for an agent, and has no audio. https://arxiv.org/abs/2506.03340
- **TVBench: Redesigning Video-Language Evaluation** (Cores et al.). Finds that text-only, single-image and shuffled-video inputs score near chance on a benchmark designed to need time, while older benchmarks let them pass. Supports the shuffle control and the text-only floor. https://github.com/daniel-cores/tvbench and https://arxiv.org/html/2410.07752v1
- **TimeBlind** (2026). Diagnostic benchmark for compositional spatio-temporal understanding, reporting frontier models lean on static semantics. Same family: diagnoses models, not packets. http://arxiv.org/abs/2602.00288v4
- **CaST-Bench** (2026), causal-chain video QA, and **V-STaR** (2025), spatio-temporal reasoning. Real or curated video, no packet-format scoring. http://arxiv.org/abs/2605.23216v2 and http://arxiv.org/abs/2503.11495v1
- Synthetic ground-truth video is a known approach (CLEVRER is the usual cited example). I did not verify CLEVRER's details in this session, so I rely on the above for the claims here.

What exists nearby, said plainly: reversed and shuffled controls, text-only floors, and synthetic clips with known answers are all established in video-LLM evaluation. Not found in my searches (limited to a few queries; not exhaustive): a harness that (1) scores the **text-and-image packet** a tool hands to a harness agent rather than a model, (2) reports it per 1,000 tokens, (3) includes a non-speech-audio and a false-claim axis, and (4) ships as the install self-test of the tool itself. Treat that as a gap I did not find a filler for, not as a proven absence.

Cost context for the "native video model" alternative the council also raised (m01.6): Gemini bills video at about 263 tokens per second and audio at 32 per second (a third-party calculator) and Google Cloud's page lists 258 and 25 for the 2.0 Flash Live API, so a one-hour video is on the order of 0.9M video tokens. The bench is how to test whether paying that beats a local packet on specific questions. https://www.tokencalc.org/video-audio-token-calculator and https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing. Per-model dollar prices I saw were from a third-party site and not checked against Google's page, so check before relying.

## What it costs to run

- **Infra ($/month):** nothing recurring. Tier A and doctor are local. Tier B spends agent tokens only when run by hand (estimate: tens of thousands of tokens per full pass of about 30 questions over 4 or 5 packet types, a few times per design change; measure on the first run). No hosted service, no daemon, no database.
- **Operational:** doctor can fail loudly, which is the point. A weekly schedule is the only thing that could page: prefer running doctor opportunistically (once per N days on the first `analyze` call, as a one-line header) over adding a launchd or cron job. No scheduler to watch, and `stats` is one JSONL file.
- **Maintenance (the real cost):**
  - the generator depends on macOS `say`, PIL, numpy and ffmpeg: speech clips break on Linux and on the home GPU box;
  - every new packet format needs a Tier A adapter (what events does it claim?) and a Tier B packet builder: two small functions per format;
  - question key and expected sidecar must stay in sync with the event list (single source of truth avoids this; do the refactor);
  - Tier B results go stale when the agent model changes; record the model ID in each result line;
  - the reverse-on-real-files header adds a code path in every analyze; keep it optional and cut it if false alarms appear.
- **Development:** small, about 1 to 2 days for the refactor, variants, scorer and doctor. Lowest weight, not a reason to skip or defer.

**Runs:** nothing new running. It adds a `doctor` command, a generator and scorer in `bench/sense/`, and one local log file. No daemon, service or paid API.
