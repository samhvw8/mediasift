## Baseline (the obvious answers)
- Keep keyframes + transcript, but add OCR text for screen recordings and cut the stat lines and repeated cues from the storyboard.
- Wrap the CLI as an MCP server (or one-command skill) with card/find/look verbs so the agent can query on demand.
- Add a VLM caption per segment so the storyboard is all text and fewer images are needed.

## Assumptions I broke
- "The sensor's job is to deliver the best frames and words": from the model's seat, frames are the worst way to receive change. I get a still and have to subtract it from the next still in my head. The packet should say what changed, how much, and in what order, and use pictures only as proof or as a close look.
- "A packet is complete when it is a good summary": I cannot tell from inside a packet what it left out. Today I grep a storyboard and assume the silent parts were uneventful. A packet that does not declare its blind spots makes me confidently wrong. Completeness has to be stated, not implied.
- "Audio means speech, so transcribe it": for a model with no ears, the non-speech half (music shift, laugh, alarm, silence, a voice rising) is invisible unless something writes it as text. That is a few bytes per minute, not a model problem.
- "Everything is a one-shot file the agent reads": the agent can ask follow-ups, but only if the first reply gives it handles to ask with. The first packet should be small and built to be questioned.

## Ideas
### m04.1 Blind-spot ledger: the packet states what I did NOT perceive
Every packet ends with a short coverage block: stretches with no kept frames, stretches where motion was high but frames were thinned, audio spans that were speech-free and unclassified, spans where ASR confidence was low. Each line carries a time range and a ready command to look at it (`look 14:02-14:40`). The agent stops treating silence in the storyboard as "nothing happened", and the answer to "what happened between A and B" gets a visible hole instead of a guess. This is cheap (we already hold the signals) and it is the only part of the packet that tells me where to distrust it.

### m04.2 The retina subagent: images never enter the main context
The harness can spawn a fresh subagent. Let the sensor emit a packet of images and instruct the main agent to hand the viewing to a subagent (named in the skill, with the image paths and the question), which returns about 300 tokens of text. The 63k fixed overhead is paid once; frames cost 1-1.5k each inside a throwaway context, so a 30-frame temporal look costs the main session roughly zero image tokens. Bench finding to exploit: totals were equal between arms because text output ate image savings; this moves the images out of the ledger entirely. Risk to test: the subagent adds its own ~60k overhead per call, so it only wins above about 40 images or when several questions batch into one call.

### m04.3 Perception arithmetic: return numbers, not frames to count
Models are bad at counting across a strip, ordering many steps, and judging durations or speeds. Make the tool do it in code: repetitions of a periodic motion (autocorrelation of the pixel signal), "scene changed 7 times", "spinner visible 41 s", "cursor idle 12 s then click", "loudness peaked at 03:12, three times". The packet carries a small facts table (count, period, duration, order) with the frame handle that backs each fact. Counting and temporal-order questions become lookups, and the images that remain are evidence for the agent to verify a fact, not raw material to derive it.

### m04.4 Foveated vision: wide cheap text, narrow rich burst on demand
Peripheral vision everywhere is text: a 1-2 KB timeline of events. The fovea is a call: `look --at 5:12 --span 3s` returns 6-8 frames at the native rate for that span, laid out as one sheet with a numbered grid and a difference mask between neighbours, so the agent sees what moved where and in which direction. The agent chooses where to spend the 1-1.5k tokens, based on the timeline and its question. It is not obvious because every earlier design chose the frames in advance. Here the model chooses, because only the model knows the question.

### m04.5 Audio as a text strip: sparkline plus event tags, one line per minute
A model with no ears needs a cheap proxy for everything that is not words. Per minute: an energy sparkline (`▁▂▂▅█▃▁`), a tag per second span from a small CPU audio classifier (speech / music / laughter / applause / alarm / silence / typing / keyboard), speaker-turn changes, and a flag when a speaker's loudness or pace departs from their own baseline ("raised, fast"). A 1-hour podcast costs about 60 short lines and answers "when did the music change", "where did they laugh", "who interrupted". The honest limit: tone of voice is approximated by loudness and pace, which should be stated as such.

### m04.6 Screen recordings become an action script, not a storyboard
For bug repros and UI walkthroughs the real content is the action sequence. Detect cursor position and clicks from pixels (a cursor template plus the click ripple), scroll events, window or page changes (large frame difference after a pause), typed text (OCR on the changed region only), and emit a numbered script: `1. 0:03 click "Settings" 2. 0:05 page changes to Account 3. 0:09 type "samh…" 4. 0:11 red banner appears`. Order of UI steps and cause-then-effect become reading, with a frame attached to each step. This is the highest-value target for the daily case (Sam's repros) and it is mostly deterministic code, not a model.

### m04.7 Before/after pair with diff overlay for cause and effect
For any step the agent flags, return one image: the frame before, the frame after, and a third panel that outlines the changed region. Models are much better at "what is different between these two" when it is drawn than when asked to find it across two separate images (this is testable, see m04.8). One image costs about the same as one frame, and it answers cause and effect directly: "click at (x,y) in panel A, banner in panel C".

### m04.8 A synthetic ground-truth bench: scripted videos with known answers
Prove every claim cheaply by generating videos from a script with ffmpeg and a few tone generators: a box that moves left then right, a button that gets clicked N times, a beep at 12.3 s, music that changes key at 40 s, a 4 s silence. The ground truth is the script, so there is no labelling cost and questions about order, count, direction and audio events have exact answers. Run the same questions against transcript-only, keyframes + transcript, and each new packet, and report correct answers per 1,000 tokens. It is a few dozen small videos, run in CI, and it is the only way to show the temporal and non-speech claims the current bench never covered.

## The provocation I would put to the group
Stop asking which frames the agent should see and start asking what the agent would have to ask a person sitting next to it who watched the video, then build that person's answers as the product.
