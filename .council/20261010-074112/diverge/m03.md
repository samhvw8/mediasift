## Baseline (the obvious answers)
- Collapse `analyze` to one zero-flag command with an auto-chosen output folder and sane defaults.
- Wrap find/look/card in an MCP server so the harness calls it as a tool.
- Add OCR for screen recordings and a non-speech audio tagger, then keep emitting storyboard + contact sheets.

## Assumptions I broke
- "The agent must perceive video as a sequence of frames": the facts are that the agent reads text and stills, and that motion is only a difference between moments. Frames are one way to carry a difference, and the weakest, because the model has to do the comparing. The tool can do the comparing and hand over the result as a still or as a sentence.
- "The user runs a command": the real requirement is that the agent has the sensing when a video shows up. Who types the command was never a requirement. A hook, or a file the agent opens, removes the daily-use problem rather than shrinking it.
- "Analyse the whole video first, then answer": preprocessing exists only because sensing was slow. The agent already knows the question; the question should set the sensing and the token spend.

## The facts nobody can argue with, and the answer rebuilt from them
1. The agent consumes only text and stills, and each still costs about 1-1.5k tokens. So every sense must be encoded as text or as a still, and a still is worth buying only if it carries more than words can.
2. Audio cannot be heard, so every sound must become text (words, labels, durations) or a picture of sound. Silence, music and laughter are facts about time, so they fit in a few words.
3. Motion and cause-and-effect are differences between moments, and differences are computable. The model need not infer them from a pile of frames; the tool can state them.
Rebuilt from these three: the output is a small, fixed-budget text digest of what changed and what was heard, plus a few stills chosen because words cannot carry them (before/after pairs, a motion image). It is produced when asked for, not up front.

## Ideas
### m03.1 Record the events, not the pixels (source-side sensing)
For bug repros and UI walkthroughs, which the user makes himself, stop reconstructing the story from pixels. A tiny recorder (`framesift rec`) wraps the screen recording and writes a sidecar of clicks, keys, window titles and accessibility-tree diffs with timestamps. The agent then gets exact cause-and-effect as text (click "Save" at 0:12.4, dialog appears 0:12.6, error toast 0:12.9), and the video is only for spot checks. Not obvious because it makes the "video sensor" partly not about video, and it works only for videos you record. Even so, the repro case is the most daily one.

### m03.2 Time as a spatial axis: the slit-scan strip
Take a thin slice of every frame (a row, a column, or the region that changes) and lay the slices side by side so that the x-axis is time. One still, about 1.2k tokens, then shows the order of UI steps, scrolling, loops and repetition counts, which a 12-tile sheet only hints at. Add a tick ruler with the timestamps and the transcript words below it. Strange, but this is how scientists have read video for decades (kymographs, spatiotemporal slices), and a vision model reads a stripe pattern for "how many times" better than it counts across 12 tiles.

### m03.3 The motion still: one image that says what moved where
For a segment, compute dense optical flow or the min/max difference of the frames, then draw it onto the last frame: arrows, ghosted earlier positions, a heat tint on the changed region. The agent reads "the cursor moved from A to B and the panel slid in from the left" in one image instead of inferring it from two. It is not obvious because every other design adds frames, and this one adds a frame whose pixels are the derivative of the others.

### m03.4 Ask first, sense second (the question sets the budget)
Drop the up-front analysis. The agent hands over the question and a token budget (`framesift ask VIDEO "why did the build fail" --tokens 3000`). A cheap coarse pass (a cached, hash-keyed 1 fps change curve plus ASR) finds candidate moments, and the tool spends the budget on those: dense frames and diffs near the events, one line elsewhere. Nothing is precomputed in a way you have to babysit, the second ask on the same file is free, and the flag count is zero because the budget is the only knob and the agent sets it.

### m03.5 Zero invocation: a hook that fires when a video path appears
Run the sensor from a UserPromptSubmit hook (or from the file-read path): a prompt that contains a video path or a YouTube URL gets a short digest injected before the agent starts (title, length, a one-paragraph timeline, a pointer to the longer layers). No daemon, since the hook is a process that exits, and the cache makes the second prompt instant. This is "one command or none" taken literally, and it moves the cost to the one place the user will certainly be: the prompt.

### m03.6 A sound score instead of a transcript
Audio becomes a timeline in plain text: speech turns with who/length, non-speech tags from a small audio tagger (music starts, laughter, alarm, typing, silence of 4 s), loudness and pace changes written as words ("voice rises, speaker interrupts"), and optionally one mel-spectrogram still aligned under the frame strip from m03.2 so that sound and picture share a time axis. Transcript-only answers 49% on the bench because words are half of the signal; this fills the half the bench has never measured. The spectrogram still is the part to test and drop if it does not pay.

### m03.7 The unit is the event pair, not the frame
Segment by change events and emit each as a before|after pair with a diff mask and the words spoken in that window, so "what happened between A and B" and "what caused X" are answered by one image plus two lines. The agent never sees 80 keyframes, only 5-15 pairs ordered in time. Cheaper than keyframes for temporal questions because the comparison is pre-drawn; weaker for camera footage with no discrete events, where it should fall back to evenly spaced frames.

### m03.8 Prove it on synthetic video with known answers
Do not wait for real videos to test a temporal claim. A 60-line generator renders clips with exact ground truth (a ball bouncing 7 times, a UI that goes A to B to C, a beep at 3.2 s, a 5 s silence, a laugh track). The agent QA bench then asks counting, order, direction and audio questions with a known key, in seconds and for free, and every design above (strip, motion still, sound score, pairs) can be scored against "keyframes + transcript" before any of it ships. This is the cheap proof of each claim the brief asks for.

## The provocation I would put to the group
The agent does not need to see the video; it needs the answers to the questions only a video could answer, so what is the smallest text and the fewest stills that carry a difference, and why are we still shipping frames?
