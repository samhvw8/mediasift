## Builds
### m03.r2.1 The purpose ladder: three whys decide what a video is for, and the card is cut to the top rung
Builds on: m03.r1.2 + m05.r1.2 + m01.r1.4
Ask it up three levels. Why a sensor? So the agent can answer a question. Why answer? So Sam can act (fix the bug, take the note, decide). Why act? So Sam spends attention on the 10 seconds that need a human. The card's first line therefore names a purpose class, not a tier: REPRO (end state is a failing test), TALK (end state is an answer or note), FILM (end state is a description). Each class fixes the zone budgets of the four-zone card and the density rule, so m05.r1.2's audio-redundancy default becomes a per-class table and the recorder sidecar (m01.r1.4) is simply the REPRO class's preferred source. What this adds is a reason for every zone, which the parents had only as a layout.

### m03.r2.2 Repro to failing test: the action script with lag compiles to a test skeleton
Builds on: m05.r1.5 + m01.r1.4 + m03.r1.3
Walk the REPRO purpose to its end: Sam does not want a perceived video, he wants a test that fails. The action script with lag (click, modal at +300 ms, source named on each line) and the numbered slit-scan markers become the steps of a Playwright or bsk script, with the lag column becoming an expected-wait assertion and the final "late / unrelated" tags becoming the assertion that fails. The agent checks the skeleton by running it against the slit-scan strip's marker order. What this adds: the sensor's output is no longer read once and thrown away, it is code that proves the perception was right when it fails the same way the video did.

### m03.r2.3 Question routing by purpose: one table maps speech, look, motion and sound questions to the cheapest rung
Builds on: m03.r1.6 + m05.r1.2 + m01.r1.2
Ask-first (m03.r1.6) picks a rung per question; give it the audio-redundancy rule as its router. Four question kinds, four default routes: speech (T2 transcript only, 0 images), static look (T3 vectors then one grid), motion or order (event-boundary pair plus a chronophoto), sound (spectrogram strip, with the ear escape valve only after the strip fails). Because the lazy ledger (m01.r1.2) records which route each question took and whether it was enough, the router table is learned from the ledger rather than tuned by Sam. What this adds: the cost model is derived from the question's purpose, and every miss is logged as a row that can change the table.

### m03.r2.4 The ear valve with a doubt budget, spent only when the purpose needs sound
Builds on: m01.r1.6 + m03.r1.5 + m05.r1.3
Ten times larger than the footer line: the ear call is gated twice. First, the question's purpose class must be one where sound is the answer (laughter, alarm, tone of voice), which is read off the SDH-style ledger line (`[music, then silence 31:05]`) the hook already wrote. Second, a monthly doubt budget in cents sits in the sidecar header and every `ear:` call prints its cost and the remaining budget, so the metered API cannot drift into a habit. What this adds: the cost of the one paid path is a visible number that scales with real doubt, and the SDH tag decides eligibility before any money is spent.

### m03.r2.5 Reverse and shuffle as a sidecar diff: the arrow-of-time check needs no agent and no tokens
Builds on: m05.r1.4 + m01.r1.5 + m03.r1.4
The generator knows the script, so it also knows the reversed script: write a second expected sidecar where event order is flipped and counters run backwards. The test runs the pipeline on the forward clip and on the reversed clip and asserts two things by diff alone: the produced card matches the forward script, and the reversed card matches the reversed script, never the forward one. A packet format that returns the same card for both has shown it carries no time. What the parents lacked: the arrow-of-time control runs in CI in seconds as a deterministic test, with the agent QA run kept only for the last mile.

### m03.r2.6 Fresh: the handoff line, the packet's last row is a clip for Sam, not the agent
Builds on: m03 first principles + m03.r1.1 + m03.r2.1
The top of the ladder is Sam's attention, so when the ledger shows low backing (few facts with a before|after pair, or a hole right where the question points), the packet ends with one line: `watch: 14:02-14:12 (10 s) <clip path>`, cut with the existing `split`. The agent says "I could not settle this, here are the 10 seconds" instead of guessing, and the first-line perceived-fraction number from the ledger decides when that line appears. What this adds: the sensor can admit the limit of the whole approach, and the failure is a short clip to watch, not a confident wrong answer.
