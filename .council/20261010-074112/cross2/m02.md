## Builds
### m02.r2.1 The boring hook, made exciting: a receipt that proves every daily run
Builds on: m02.r1.2 + m04.r1.1 + m05.r1.3
The quietly-working idea is the prompt hook plus sidecar with a fixed token budget. Make it exciting by having the hook print a single SDH-style receipt line at the top of what it injects: `[clip.mp4 · 1h45 · sound score ready · 3 frames kept · ledger: 4 holes · tier 1 of 3 · 1.4k tokens]`. The ledger holes (m04.r1.1) and the bracket captions (m05.r1.3) already share one format, so the receipt is just their summary line. The user sees every day that the tool ran, how deep it went and what it did not perceive, with no flag and no folder; "crashing beats corrupting" becomes a visible one-liner instead of a silent default.

### m02.r2.2 Two-speed trailer as the T0 rung, with the question steering only the second speed
Builds on: m05.r1.7 + m02.r1.1 + m02.r1.2
m05.r1.7's constant-size trailer becomes the T0 rung of the sidecar ladder: it needs only the 128x72 pass and the audio novelty framesift already computes, so it exists within seconds and is cached by content hash. The hook's question (m02.r1.2) never touches T0, which stays question-free and shared across prompts; it only chooses where the "slow lane" `look` spans get pre-listed in the digest. That split adds a cache rule neither parent had: the fast lane is a pure function of the file, the slow lane is a pure function of file plus question, so a second prompt on the same video costs near zero.

### m02.r2.3 Doctor with reversed clips: the self-test that proves the installed tool carries time
Builds on: m02.r1.4 + m05.r1.4 + m04.r1.5
`framesift doctor` renders the synthetic clips forward, reversed, shuffled and muted (the controls from m05.r1.4 and m04.r1.5), runs the real pipeline, and passes only if the card's answers flip with the clip. It prints one table of correct answers per 1,000 tokens, plus two lines: "carries time: yes" and "carries sound: yes". Run on install and weekly from the stats log, it means a model or llama.cpp pin change that quietly drops the arrow of time shows up as a failed check on the daily machine, not in a one-off research bench.

### m02.r2.4 Retina subagent as the default behind the hook, with a crossover guard
Builds on: m04.r1.4 + m02.r1.2 + m02.r1.6
Take m04.r1.4's "main context never holds a pixel" and make it the daily default: the hook injects only the receipt and text trailer, and any question that needs images is routed by a one-line instruction to a viewing subagent. Push it ten times further: the GPU box (m02.r1.6) writes a VLM shot-list as a hash-named layer when awake, so the subagent often needs no images at all and just reads the layer. The guard is the crossover count (about 40 images, per m04.2): below it the sidecar tells the main agent to look inline, above it to delegate, so the user never decides and never pays the subagent's overhead for a three-frame question.

### m02.r2.5 Per-video question log that feeds the receipt, not a database
Builds on: m04.r1.6 + m02.r1.1 + m05.r1.3
m04.r1.6's question log lives as one hash-keyed text file next to the sidecar, and the receipt line carries its trace: `[last asked: 3:10-3:40, 8:02 · open: 14:02-14:40]`. The ladder uses it as its schedule: spans that were asked about get promoted to the next tier (word timestamps, motion stills) in the background on the next run, while untouched spans stay at T0. The tool therefore spends compute where the user actually returns, a policy no parent had, and still keeps no daemon, no DB and no knob.

### m02.r2.6 Fresh: the "yesterday" digest, so the daily video habit starts without a path
Builds on: m02.r1.3 + m05.r1.2 + m02.r1.5
Reading the receipts made me see that the daily friction is also finding the file. A hook listing the three newest videos in the Downloads and screen-recording folders with their T0 receipts (sound-score line, silence count, recorder-event status from m02.r1.3) lets the user say "the repro from this morning" without typing a path. For a screen recording the receipt chooses the density rule from m05.r1.2: speech-heavy lecture gets text, silent repro gets images. It costs one directory listing and the cached T0 files, nothing running between prompts.
