### m01.r2.1 Scoring the leading idea: a 6, and the missing 4 is a falsifier
Builds on: m03.r1.1 + m04.1 + m03.2
The leading idea is the card (header, timeline, facts table, ledger) with foveated `look` behind it. It scores 6 because every part of it is a claim that nothing has yet tested. A 10 needs one thing: a pre-registered kill test. For each fact type (count, order, lag, sound tag) the card must beat "keyframes + transcript" on the synthetic bench by a stated margin, and any fact type that misses is deleted from the card by rule. The parents added facts and gaps; this adds a rule that removes them, so the card can only shrink toward what is proven.
### m01.r2.2 Verified facts only: the facts table prints a check, not a confidence
Builds on: m03.r1.1 + m04.3 + m04.r1.5
A confidence number on a fact is itself something the agent cannot check. Replace it with a replay result: the generator-built clips (m04.r1.5) give each detector (autocorrelation count, onset lag) a measured error on known truth, and the row prints the detector's error on its own class of clip ("count: exact on 40 of 40 synthetic clips, off by 1 on real footage"). The agent weighs a fact by its track record. The parents had confidence and a bench separately; here the bench output is printed inside the packet.
### m01.r2.3 The control that argues against us: a "nothing happened" clip and a decoy clip
Builds on: m04.r1.5 + m03.8 + m04.1
The bench controls (reverse, shuffle, mute) test whether a packet carries time. Add the opposite pair: a clip with no events at all, and a decoy with a loud, busy, irrelevant event (a flash, a jingle) while the real event is quiet. If the card reports the decoy as the main event, or invents facts on the empty clip, the ledger is lying about completeness. This tests the claim m04.1 rests on (the ledger tells the agent where to distrust the packet) and neither parent tested false positives.
### m01.r2.4 The 10x larger version of the hook: sense nothing until the question exists
Builds on: m03.5 + m03.4 + m04.r1.6
The hook (m03.5) injects a digest at prompt time, but the contrarian read is that even that is eager. Inject only one line: "video: 41:20, speech, 3 layers cached, ask via `framesift ask`". Everything else waits for the agent's question (m03.4), and the question log (m04.r1.6) sets the cache priority for the next visit. The per-video cost drops to ~40 tokens until a question exists, and the hook measures how often the agent ever asks, which is the number that decides whether the card was worth building at all.
### m01.r2.5 Fresh: price the plain alternative first, a "dumb baseline" arm that costs nothing to build
Builds on: m04.2 + m03.5 + m04.r1.4
Before building the card, run a baseline the council has not named: the existing contact sheets handed to a retina subagent (m04.2) with the question, and a 2 s sound-score line from one off-the-shelf tagger. If that arm already matches the card on temporal and audio questions at similar tokens, the card is a maintenance cost with no gain, and the stronger design is to ship the baseline and stop. It turns "everyone is building a richer packet" into a testable bet, and the arm needs only code that already exists.
