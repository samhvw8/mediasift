## Builds
### m04.r2.1 One packet, one budget: the stacked parts get a token meter and a drop order
Builds on: m04.r1.1 + m04.r1.2 + m02.7 + m02.r1.5
My mistake last round: I added a ledger strip, a facts table, a trailer and a question echo, each priced alone and never summed, so the packet could grow past the 1.5k-token card m02.7 asks for. Fix: the packet is assembled against one constant budget (m02.7), and every part carries a drop rank (facts table and sound score last to go, ledger strips and echo first). The card's footer prints "dropped: ledger strip, echo (budget)" so a cut is labelled, not hidden. Neither m02.7 (fixed size, no ranking of parts) nor my r1 builds (parts, no ceiling) had both.
### m04.r2.2 Subagent trailer, repriced: the crossover is measured, and the default is the plain card
Builds on: m04.r1.4 + m02.r1.2 + m01.r1.2
My mistake: I called the main context "never holding a pixel" and ignored that a viewing subagent starts with its own ~60k fixed overhead, so for one question it likely costs more than looking directly. Rebuild: the hook injects only the m02.r1.2 question-aimed card, and a `look` answer is appended to the sidecar ledger (m01.r1.2) as text. The subagent route turns on only once the ledger shows a session asking more than a threshold number of look questions about one file, and the threshold is measured by the doctor bench, not guessed. Adds the part r1.4 lacked: a cost test that can say "do not delegate".
### m04.r2.3 Don't classify the event, let the pair carry a burst flag: dual-mode look without a mode guess
Builds on: m04.r1.3 + m01.r1.3 + m01.r1.1
My mistake: r1.3 assumed the timeline can label an event "discrete" or "continuous" reliably, and a wrong label returns the wrong layout with no sign of it. Instead `look` always returns the m01.r1.3 before|after pair, plus a one-line flag computed from frame-to-frame difference between the pair ("still changing at the after frame: yes"). Only when the flag is yes does the agent get the chronophoto-with-spectrogram image (m01.r1.1) for the span. The agent never trusts a classifier, only a measured fact, and the burst costs tokens only when the picture is still moving.
### m04.r2.4 The facts table, taken ten times further: a record-time sidecar emits the same rows, labelled "exact"
Builds on: m04.r1.2 + m01.r1.4 + m02.r1.3
The facts table of audio-visual coincidences was built by guessing from pixels. m01.r1.4 and m02.r1.3 note that agent-driven repros (Playwright, bsk, cua-driver) can emit the real events. Make the table one schema with a `source` column: "exact" rows come from the tool log (click at 12.41 s, modal at 12.46 s), "inferred" rows from pixels and audio onsets. A third-party tutorial gets only inferred rows; the user's own repros get exact ones, and the agent counts "7 clicks" the same way for both. What the parents lacked: one row format that stays stable when the sensing gets better, so skills and benches written today do not change later.
### m04.r2.5 Bench the packet, then bench the mistakes: a "wrong-label" control in the synthetic suite
Builds on: m04.r1.5 + m02.r1.4 + m01.r1.5
My mistake: my r1.5 scored packets only when they were correct, but my own builds can print wrong claims (a mislabelled event kind, a coincidence that is chance). Add to the doctor suite clips where the right answer is "no sound", "no cause", or "cannot tell", and score whether the packet lets the agent say so. Together with the reverse, shuffle and mute controls this gives one table: correct per 1,000 tokens, carries time, carries sound, and false-claim rate. Parents measured when the packet is right; this measures how often it misleads, which is the failure that costs a user the most trust.
### m04.r2.6 Fresh: an expiry on every claim in the sidecar, so a stale card cannot outlive its tool
Builds on: m02.r1.6 + m04.r1.6
Reading the cache and echo ideas back, my r1.6 question log would keep advice alive forever, even after the segmenter or ASR model changes. Each layer and each echo line stores the tool version and model id that made it; on read, a mismatch re-labels the line "made by an older version, re-run tier N" or recomputes it, and the GPU-box tier (m02.r1.6) is filled the same way. It adds one version string per file and no job to watch, and a model update stops silently mixing old and new evidence in one card.
