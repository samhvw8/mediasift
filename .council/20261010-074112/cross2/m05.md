## Builds
### m05.r2.1 The counterview: the agent should be handed a verdict, not a percept, and we should stop calling it sensing
Builds on: m03.7 + m03.3 + m02.r1.2 + m05.r1.5
The view we least want to accept is that no pile of stills, strip or ghost image restores perception, because perception is an observer's judgement and the agent has no observer. What the sensor can honestly ship is testimony: a measured claim ("click 0:03.2, modal 0:03.5, +300 ms, reacted") with a handle to its evidence, which the agent may check or distrust. In film terms this is the court exhibit, not the screening. Build it as the packet's one stated contract: every line is either a measured fact with a handle, or a labelled gap, and the word "saw" never appears. It adds what m03.7 and m02.r1.2 lacked, a rule that decides what stays out (anything the tool cannot back with a number or a frame), and it lets the bench score testimony accuracy instead of agent vibes.

### m05.r2.2 Change-blindness audit: the sensor reports what its own difference threshold cannot see
Builds on: m03.3 + m03.7 + m02.r1.3
Humans miss large changes that happen during a blink, a cut or a pan (change blindness), and a pixel-difference detector has the mirror flaw: it misses slow drifts (a progress bar creeping, a colour fade, a cursor that is a few pixels) and fires on camera shake. For each event pair, the tool also computes the slowest change over the whole span, the one that never crossed the event threshold, and prints it as a "slow channel" line beneath the pair. This adds a second detector with the opposite blindness to m03.3's motion still and m03.7's pairs, and the card header says which detector produced each line, so "nothing happened" is only written when both were quiet. Test it on synthetic clips with a 20-second fade and a 2-pixel-per-second slide.

### m05.r2.3 Pre-attentive pop-out as the pointer: the card tells the agent where a viewer's eye would have been dragged
Builds on: m02.7 + m02.r1.5 + m05.r1.2
A human viewer does not read a film evenly; sudden onsets, loud transients, a face turning, and a cut grab attention first, and everything else is context. Rank each second by a cheap saliency sum (visual onset, audio onset, speech-rate jump, silence break) and let that, not a fixed cap alone, set which seconds get a line, a frame, or nothing in m02.7's budgeted card. Chapters for the podcast case (m02.r1.5) fall out as the saliency peaks. The addition is that the budget follows what attracts a person rather than what is evenly spaced, and the footer names the quietest minutes so the agent knows they were skipped on purpose.

### m05.r2.4 Priming guard: the hook injects the digest, so the digest must be split into the part that cannot bias and the part that can
Builds on: m02.r1.2 + m03.r1.5 + m05.r1.3
Perception research shows that what a viewer is told before watching changes what they report seeing, and a hook that injects an interpreted summary before the agent starts will do the same to the agent. Split the injection into two blocks: a plain-fact block (duration, language, sound events, ledger counts, no adjectives, no cause words) that is always injected, and an interpretive block (the shot list, "reacted", chapter titles) that is available as a file and never pushed. m03.r1.5's token meter then logs which block the agent used before answering. This adds a defence against the agent echoing the digest's story, and the log gives a number for how often it did.

### m05.r2.5 Blind re-watch: a second observer who is not told the digest answers the same question, and disagreement is the confidence
Builds on: m03.r1.6 + m05.r1.6 + m02.r1.4
Film scholars check a reading by having someone who has not seen the first reading watch again. Run the retina subagent (m05.r1.6) twice on the same span, once with the sidecar card and once with only the raw pair and no card. If the two shot-list lines agree, the card line is marked firm; if they differ, it is marked "contested" with both lines kept. m03.r1.6's ask-first answers then carry a confidence that comes from independent agreement, and m02.r1.4's doctor can run the same check on the synthetic clips, where the key is known, to find which card layouts cause the disagreement. It costs throwaway-context tokens only, never main-session tokens.

### m05.r2.6 Fresh idea: the reversed-clip test as the daily health light
Builds on: m05.r1.4 + m02.r1.4 + m03.r1.4
Reading the doctor and the sidecar-as-answer-file builds made me see the reverse-and-shuffle control is cheaper than any bench: on every real file the tool already decodes, it can build the packet for the clip run backwards and compare. If the forward and reversed cards are identical in their event lines, the packet has no arrow of time for that video, and the card header says "order: not carried" instead of letting the agent assume it. This needs no labels, no agent and no ground truth, so it can run on Sam's real videos daily and turn an invisible failure into a printed one.
