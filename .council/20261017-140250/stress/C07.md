## C07 stress test: the cache as a citable library

Checked on disk today: `~/.cache/anydub/` holds 20 ids; `tong-hop.vi.md` has 147 `[CODE h:mm:ss]` citations (193 lines);
`content_key()` in `src/mediasift/see.py` does hash `CARD_VERSION` (now `see-12`); stdlib SQLite is 3.53.1 and accepts
`unicode61 remove_diacritics 2`. Two facts the concept did not weigh: (a) `~/workspace/tools/anydub/notes/transcripts/*.txt`
already holds the cited talks as `[0:00:07] line` text with the title and `youtube.com/watch?v=ID` in a header, so a plain
`rg -n` already returns a citable line today; (b) the whole 16-talk synthesis was written Sep 29 - Oct 2 inside anydub,
from those files, and anydub's repo has one commit plus uncommitted format work (`git status` shows modified docs and
loose `*.summary.vi.md` / `*.transcript.en.txt` at its root). Its file layout is still moving.

## Fragile assumptions

Ranked from most to least fragile.

1. **Untested: a new `grep` beats what the agent already does, often enough to pay for itself.** The token claim
   (about 200k tokens to re-read 16 transcripts, cut ≥3x) compares the library against reading every transcript in
   full. That is the wrong baseline. The agent can already run `rg` over `notes/transcripts/` and gets timestamped,
   URL-headed lines. On the English side, FTS5 adds diacritic folding, bm25 ranking and one query across both caches.
   All of that matters for Vietnamese queries, and the transcripts are English (only 3 of the 16 cited talks have
   `text_vi`). The linking job also ran **once** at this scale. "Asked many times" in the brief means the same session
   asked repeatedly, not many independent jobs. If the next synthesis is months away, the saving is one cached
   200k-token read, which prompt caching already makes cheap. Meanwhile 4-5 commands, their skill lines and their bench
   rows have to be kept alive the whole time.
2. **Shaky: a deterministic `cite-check` can tell a wrong time from a right one across languages.** Its test is "a
   content word, name or number of the claim within ±10 s". The claims are Vietnamese paraphrases and the transcripts
   are English, so for 13 of 16 talks only names and numbers can match. Talk guests repeat their names and numbers for
   minutes (Seyfried says "mitochondria" and "glucose" all through his talk), so a citation moved 30-120 s will often
   still overlap: catches stay low. A correct citation that paraphrases a point with no name or number will show no
   overlap: false alarms stay high. The bar of ≥80% caught and ≤10% false alarms looks unlikely on the 13 untranslated
   talks. The prior art points the same way. GroundedVQA found that LLM verifiers caught 0% of 40 claims, or swung
   between 0% and 100% with the prompt's wording; only a purpose-trained NLI model reached a stable 79% catch rate
   (https://arxiv.org/html/2608.15574). The robust fix that builders reach for removes the failure at write time
   instead: "The LLM never writes times itself: chunks are labelled [S0], [S1] ... labels that match no chunk are
   dropped" (https://github.com/Himanshiarora05/secondbrain-ai/pull/1). C07's `grep` and `quote` handles are already
   that pattern. `cite-check` checks after the fact what the handles already prevent.
3. **Shaky: excerpts of cached sources reach the owner often enough for `align` and the automatic card line.** The
   one real pair (`tDmjz6HB-yw` cut from `6pxmdmlJCG0`) exists because the owner downloaded both on purpose for the
   same project. His real short-video jobs are TikToks and Facebook reels, often Vietnamese re-voicings of English or
   Chinese sources. Shingles and character n-grams cannot align across languages, and the source is rarely cached.
   "One web search away" really means downloading and transcribing a 47-minute source: minutes of MLX ASR at about
   3.3 GB. The cost table does not count that, and it is the hard constraint on "lightweight". The fix-on-fail column
   already admits this ("align stays an explicit command"), so the automatic card line should not be planned in yet.

Lesser points: the stable media id has to stay frozen forever once summaries embed handles; the "match voxtract's
convention" claim is not met (voxtract uses `{id}@{start}-{end}` in seconds, C07 uses `yt:ID@41:10`); and the anydub
adapter couples mediasift to a sibling's file format that is still changing.

## Pre-mortem

October 2027, and it failed quietly. `grep` and `quote` shipped after step 3 cleared 70% on the 3 translated talks
and was waved through on the 13 untranslated ones with `--meaning`. `cite-check` shipped in its fallback form.
The skill grew six lines, and every agent that loads it pays for them.

The owner's next synthesis jobs ran where the first one ran: in anydub sessions, started from a YouTube link. The
mediasift prompt hook did not fire, because nothing about the request said "video I can't watch". The agent opened
`notes/transcripts/*.txt` and used `rg`, as before. The library was only rebuilt at the end of `see`, so the
transcripts anydub added were missing until the next unrelated `see` run. Twice, anydub changed `translation.vi.json`.
The adapter did what it promised and crashed with one clear line, but the crash sat at the end of `see`, so a bug-repro
screen recording failed for a reason that had nothing to do with it. The owner moved indexing behind a flag and never
turned it back on. The `also in:` card line fired three times in a year, all on bench copies that slipped past the
filter. Nobody removed the commands, because nothing was visibly broken. The 147-citation bench row kept running in
`mise run test` and kept passing against a frozen index that no real job used anymore.

Most probable root cause: the feature lived in the tool that senses media, while the job lived in the tool that holds
transcripts. The agent followed the files.

## Who loses

- **anydub (the same owner, another hat).** Its cache becomes a public format for mediasift. Every anydub change
  then needs a mediasift fix, or it breaks something. Likely response: freeze the anydub layout (which slows anydub
  down), or quietly stop caring and let the adapter crash. Both are maintenance taxes the cost rules weigh heavily.
- **The agent's per-turn budget.** About 6 skill lines and a larger command surface are read by every session that
  loads the mediasift skill, most of which (bug repros, TikTok checks) never touch the library. That is small but
  permanent.
- **voxtract's convention.** A second handle syntax splits what agents learn, against the concept's own goal.
- **The status quo (`rg` over `.txt`) loses nothing**, and that is the problem. Nothing forces the switch, so agents
  keep using it.

## Fixes

| weakness | smallest fix |
|---|---|
| Wrong token baseline (assumption 1) | Add a third arm to step 6: the agent with `rg` over the existing `notes/transcripts/*.txt` and `transcript.txt`. The bar becomes ≥3x fewer tokens **than rg**, with the same citations passing. If FTS5 does not beat rg, ship nothing for search. |
| Rare job (assumption 1) | Count real multi-video jobs in session logs since 2026-09-17 before building, and state the expected runs per month in the decision record. Below about 1 per month, keep only the offline bench script and stop there. |
| cite-check cannot judge across languages (assumption 2) | Score step 4 separately for the 3 translated and 13 untranslated talks. Make the shipped default the fallback: `quote` at each citation, no verdict. Put the write-time rule in the skill: "cite only handles returned by grep or quote". That one line does what the secondbrain-ai PR does, and the check becomes optional. |
| Excerpts rarely cached (assumption 3) | Keep `align CLIP SOURCE` as an explicit command with both files required. Drop the automatic `also in:` card line and the shingle lookup in `see` until the owner's reel/TikTok count clears ≥1 in 5. |
| Indexing inside `see` couples a sibling's format to every sensing run (pre-mortem) | Build the index lazily on the first `grep`/`quote`/`align` call, by checking file mtimes. `see` never touches the library, so an anydub format change only fails library commands. |
| anydub adapter on a moving format | Read one neutral contract instead of anydub's internal files: a `segments.jsonl` (`media_id, start, end, voice, text, lang`) that both tools write next to their transcript. A format change in anydub then breaks its own writer test, not mediasift. |
| The job lives in anydub (pre-mortem) | Put one line in anydub's agent file pointing at `mediasift grep` (or ship the library as a tiny shared tool both call). Without this, no agent working in anydub ever reaches it. |
| Handle syntax differs from voxtract | Use voxtract's form, `ID@start-end` in seconds, and render `mm:ss` only for display. |
| Media id frozen forever | No fix: this is the price. Write the id scheme down as a decision with a unit test, and never version it. |

## Verdict

**Survives with changes.** Its core insight holds and comes from real data: handles a program can look up, the media id
split from `CARD_VERSION`, and the found Altman excerpt with the dropped question. Its offline first move is cheap and
correctly gated. What has to change:

1. Measure against `rg` over the existing `.txt` files, not against full reads, and count how often the job really
   recurs.
2. Index lazily, never inside `see`.
3. Read a neutral `segments.jsonl` contract instead of anydub's internals, and point anydub's agent file at the
   commands.
4. Ship `cite-check` as quote-only, and put the "cite only returned handles" rule in the skill.
5. Drop the automatic card line until the excerpt-frequency number clears its bar.
6. Use voxtract's handle syntax.
