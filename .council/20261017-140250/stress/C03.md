## Fragile assumptions

Ranked from most fragile to least.

1. **Untested: an agent treats `~words~` and `say?` as "do not quote or search".** Everything the owner gets depends on this, and the concept says so itself. Two things make it worse than the concept admits.
   - `~x~` is GFM strikethrough. A model trained on markdown reads it as "deleted or wrong", not "unsure". It may drop the word from a summary, which is a silent loss. Or it may copy the tildes into a Vietnamese translation or an SRT.
   - The only evidence on hedge marks is against them. Highlighting doubtful words did not change how much human editors improved the transcript (https://arxiv.org/abs/2503.15124).
   - Nobody has measured whether an LLM fact-checker skips marked tokens. My social search found no reports either way, which is no evidence at all.

2. **Shaky: the marks land where the owner's jobs read the text.** For talks longer than a few minutes, the card summarises speech one line per minute. The words live in `transcript.txt`, which agents grep and translate (`skills/mediasift/SKILL.md` lines 76-80). Summarising and linking long talks with timestamps is the owner's most frequent job, and the concept only changes the card. The budget is also tightest there. `max(5 s, 10%)` of ~70 s of sensing on the 47-minute talk is ~7 s, enough for a handful of warm re-hearings. Parakeet's drops are worst on exactly these long files. So the files that most need fixing would mostly end up with unresolved `say?` rows.

3. **Shaky, with real outside support: CED speech-seconds minus ASR words is a low-noise detector of dropped speech.** The mechanism is real and well documented. mediasift ships `mlx-community/parakeet-tdt-0.6b-v3` with `chunk_duration=120` (`src/mediasift/asr.py:34,162`). That value was picked to keep memory flat, not tuned for accuracy. Independent tests show parakeet v3 silently loses whole contiguous blocks at every chunk length, and short 20-30 s chunks lose more (https://github.com/scagood/parakeet-tdt-0.6b-v3-fastapi-openai/issues/38). On v2, how much is lost depends on where the chunk boundaries fall, with WER from 0.75% to 12.45% (…/issues/36). NVIDIA's own thread reports long deletions as right context shrinks (https://huggingface.co/nvidia/parakeet-tdt-0.6b-v2/discussions/60). Two consequences:
   - **Good:** no chunk size makes the problem go away, so a coverage check is justified and not gold-plating.
   - **Bad:** rung R1 (the same parakeet v3 on a short span) is the regime where v3 drops more. Issue #38 has a window that returned `''` at 110.0 s and the full transcript at 110.5 s. "R1 recovered 3 of 3" on Tears is one film with n=3.

   The false-alarm rate on clean talk is also unmeasured, because the CED speech track is not saved yet. Two-system agreement as an error signal is old and sound, but it assumes the systems make different errors (ROVER, https://www.nist.gov/publications/post-processing-system-yield-reduced-word-error-rates-recognizer-output-voting-error). The concept already shows a correlated error: "bắt tự" from both QUAN and whisper.

The loop and stock-phrase alarms are **solid**. They are cheap and backed by published work (https://arxiv.org/abs/2501.11378), and the owner's own cache has two cases.

## Pre-mortem

It is October 2027. The cheap parts shipped and still run: end times clamped to CED speech runs, loops collapsed, the stock-phrase alarm. They work, and nobody notices them. The ladder shipped too.

The obedience test never ran. It needed 30 fresh-agent runs plus logging of search queries, and it kept losing to feature work. So the footer went out on faith.

In use, the owner's jobs mostly went through `transcript.txt` on long talks and through 30-90 s Vietnamese reels on QUAN. The talks got a few `say?` rows each, and summaries skipped them. A dropped 40 s block in a talk was now marked but still never transcribed. The reels hardly fired at all, because QUAN does not loop or hallucinate the way the box's whisper does.

The agent kept quoting "bắt tự", which both hearings agreed on. Once it handed a Vietnamese dub script with `~...~` in it to anydub's TTS.

Meanwhile parakeet-mlx changed its chunking in an update, the drops moved, and the three thresholds tuned on Tears plus one reel drifted with nobody watching. The integrity bench went quietly stale, because Blender's SRT is its only English ground truth.

The net result was a modest, real gain from the clamp and the loop collapse, which needed none of the ladder. The rest was a maintained subsystem that no number showed was paying for itself.

## Who loses

- **The owner's token budget on clean cards.** Small. It costs +0 when nothing fires, but every false alarm adds a `say?` line and the footer, and invites a `look` costing ~1.8k tokens. If false alarms are frequent, the agent learns to ignore the marks, and the true ones are lost with them. The concept caps marked tokens below 3% but does not cap alarm rate.
- **Downstream tools that consume the text** (anydub dubbing, SRT output, translation). They inherit `~` and `say?` syntax unless they strip it. They "respond" by breaking, or by stripping the marks, which deletes the signal.
- **Sensing time on the Mac.** Re-hearing adds up to 10% of sensing time and a second model load (mlx-whisper 4.9 s cold). On a busy machine the owner feels it.
- **The parakeet-first default.** If the CED-gap rule fires often on v3, the measured fix is to change chunking or the model, not to re-hear. The ladder would hide that root cause behind a working patch.

## Fixes

| Weakness | Smallest fix |
|---|---|
| Obedience unproven; `~` means strikethrough | Run the obedience test **before** the marks, not just before the footer. Test a non-markdown mark such as `⟨?luck⟩` or `[?luck]` against `~luck~`. Ship only the variant that measurably cuts searches on marked tokens. |
| Marks miss `transcript.txt` | Write the same marks and `say?` rows into `transcript.txt`. Add one line to `SKILL.md`: strip marks before TTS or SRT, and never quote a marked token. |
| Long talks exceed the budget | Re-hear long files on the box when `--on` is up (60 s budget). Otherwise print the unresolved count and the spans in one line (`say? 7 spans, see sensed.json`), not one line each. |
| R1 is the same failing model | Measure R1 on long-file drops before keeping it. If parakeet v3 on short spans also drops, go straight to R2 (mlx-whisper or the box) for parakeet-sourced alarms. |
| The root cause may be chunking | Before building the ladder, sweep `chunk_duration` and `overlap` (and parakeet-mlx's local-attention option, if 0.5.2 has one) on the long-talk bench. Count CED-gap windows per hour. If one setting cuts the alarms by most of the way, ship that and keep the ladder small. |
| False-alarm rate unknown | Save the CED speech track first, then run the sweep the concept already names: under 1 alarm per 10 minutes of clean talk. Make this a gate, not a "not run". |
| Correlated errors such as "bắt tự" | No fix in this concept: this is the price. Say it in the docs, as the concept proposes. An OCR or caption witness is a separate concept. |
| Thresholds drift after model updates | Add a second English ground truth with a real long talk and official captions, so the bench is not one film. Re-run it on any ASR model or library bump. Models are pinned, so this is a cheap check. |

## Verdict

**Survives with changes.**

1. Ship the clamp, loop collapse and stock-phrase alarm now. They are zero-risk and make the card shorter.
2. Run the obedience test, with a non-strikethrough mark as one of the arms, before any marks go on the card.
3. Carry the marks into `transcript.txt` and tell `SKILL.md` users to strip them for TTS and SRT.
4. Gate the ladder on two things: the clean-talk false-alarm sweep, and a chunking sweep that first tries to remove parakeet v3's drops at the source.
5. Drop R1-as-same-model for parakeet unless it is measured to work on long-file drops.
