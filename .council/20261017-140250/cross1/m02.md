## Builds
### m02.r1.1 One caption alignment, three outputs: speech judge, spelling fix, graphics list
Builds on: m02.1 + m01.5 + m08.3
Align every OCR text run to the ASR line it overlaps once, then sort each pair three ways: close match = an `echoes speech` caption (drop it from the card, and score it as a free WER/names-and-numbers reference on real Vietnamese social video); partial match that differs on a name or number = an ASR error the creator already corrected (print the caption spelling, e.g. "bát tự" for the misheard "bắt tự", tagged `caption says`); no match = a `standalone` graphic to translate and to fact-check. Neither parent had the middle bucket, which turns the disagreement itself into a correction instead of a number nobody acts on. Cheapest settling test: run the alignment over the ~7 real cached cards and count pairs per bucket; if the middle bucket is non-empty and a human check agrees with the caption side in 8 of 10, the spelling fix has earned its line.

### m02.r1.2 Speech health: loops and gaps are one defect, measured as words-per-second against what CED heard
Builds on: m08.3 + m02.2
A decoding loop (44x "bắt tự") is too many words for the speech heard; an untranscribed span (6 words in 15 s) is too few. One check covers both: per 5 s window, compare ASR words-per-second and n-gram repetition against CED's Speech score, and print a single hedged `say?` line only where they disagree, never altering the speech itself. What this adds is a prevalence number before any build: sweep all 734 cached cards with the rule and report how many windows fire per hour of audio. If it fires on more than a few percent of plain talks, the threshold is wrong; if it fires on the 3 known loops and on Tears of Steel's under-written spans (checked against Blender's official SRT), it is a measured sensor.

### m02.r1.3 The deletion gate needs statistical power too, so the burden of proof flips
Builds on: m08.2 + m02.6 + m02.3
m08.2's rent audit and my mood ablation both hit the same wall: bench noise is 1-3 questions in 32, so "removing this line cost 0 questions" and "adding this line gained 0" are both unreadable. Push it ten times further: run every ablation as paired per-question flips over k repeated runs (McNemar-style), report the smallest effect the bench could have seen, and adopt an asymmetric rule: a line kind that cannot show a gain at the bench's detectable effect size is deleted by default, because tokens are a certain cost and the gain is unproven. Keys must come from an independent transcript (m02.3) or speech lines will look free to delete for the wrong reason. Cheapest test: re-grade the kept r15/r17 answers with the header, voice tags and mood words stripped from the card the grader sees; that costs zero new arm runs and says whether any line kind has measurable rent at all.

### m02.r1.4 Dub QC with a calibrated detector: first prove the tagger can hear a bed at -20 dB
Builds on: m01.1 + m02.7
Both of us proposed diffing the original and the dub, but the diff is only as good as CED's ability to hear a music bed under a loud voice, and that was never measured. Add the calibration step that settles it: mix 20 known beds under speech at 0, -10, -20 and -30 dB, find the level where CED's music score falls below its stated threshold, and print that floor in the QC report (`bed not detectable below -22 dB; dub bed is below the floor at 01:10-03:40`). anydub's own `--orig-voice 0` vs `0.3` history is the natural before/after on real footage, and the owner's complained-about file must reproduce "background lost" or the check is not ready. This makes the QC claim falsifiable instead of reading silence as loss.

### m02.r1.5 The owner's follow-up searches are free labels for the card's names and numbers
Builds on: m02.5 + m08.8
Session logs show more than pushback: in the fact-check job the agent copies a term from the card into a web search, and the search engine's "did you mean" or the result titles reveal the right spelling (exactly the "bắt tự" / "bát tự" case). Joining usage.jsonl with the next N tool calls in each session gives, per card, which images and files were opened (m08.8), which turns the owner corrected (m02.5), and which card terms a search rewrote, all from files already on disk. Cheapest settling test: one script counting, across all non-bench sessions, web searches whose query shares a token with the preceding card; if fewer than 5 exist, say the real-use sample is too thin and stop, rather than tuning to it.

### m02.r1.6 An invariant test over the whole cache: every command a card prints must run
Builds on: m08.1 + m02.8
Both of us found the dead `framesift look` hint; the defect behind it is that nothing checks cached cards against the current binary and model pins. Add one unit test that walks `~/.cache/mediasift/see/*/card.md` (or a fixture copy in CI), extracts every printed command, and asserts its first word resolves on PATH and its subcommand parses; plus fold the tool name, `QUAN_REV`, `CED_REV` and the ASR model id into the cache key so a pin change invalidates instead of serving old speech. Today the test fails on 733 of 734 cards, which is the failing-test-first the house rules want, and it keeps failing loudly at the next rename instead of costing an agent a wasted turn.
