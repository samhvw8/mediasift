## Builds
### m05.r1.1 Read-time header that also carries known defects of the version that sensed the card
Builds on: m05.3 + m08.1 + m08.3
m05.3 and m08.1 both render the header at read time to remove the dead `framesift look` command. The quieter failure a year out is a stale *body*: the 2 cards that already hold ASR loops ("bắt tự" x44) will keep serving the loop after m08.3's guard ships, because a cache hit never re-senses. So the read-time header also checks a small `KNOWN_DEFECTS` table in the code, keyed by the `CARD_VERSION` that sensed the card (e.g. `see-12: no ASR loop guard`), and prints one line: `sensed by see-12; known issue fixed since: ASR loops; re-run with --fresh`. Judge: a test that caches a see-12 card with a loop, bumps the version, and asserts the warning appears on a cache hit and disappears after `--fresh`.

### m05.r1.2 One speech-integrity footer instead of three kinds of inline warnings
Builds on: m08.3 + m05.6 + m05.2
Loop collapse, "speech heard, not transcribed" and caption-vs-ASR disagreement are all the same message: do not quote this span verbatim. Shipped as three separate inline hint styles, they appear on most real cards and a year later agents treat "(check with look)" as noise and quote around it. Instead, mark the affected words with one short tag (`~`) and print one footer line: `do not quote verbatim: 00:12-00:31 (ASR loop), 02:18-02:31 (speech not transcribed), 01:05 "15%" (caption says 50%)`. The pieces also check each other: a burned-in caption can fix the loop's mishearing ("bát tự" on screen against "bắt tự" in speech). Judge: on the fact-check bench, count the flagged tokens that the agent passes into a web search. The target is zero.

### m05.r1.3 Harvest every free judge a real URL brings, on every real run
Builds on: m07.1 + m07.8 + m05.1 (pushed ten times further)
m07.1 uses describer tracks as a judge and m07.8 uses creator chapters. The pre-mortem failure is that someone has to go and build these benches, nobody does, and real use never feeds them, just as `fix` was never called. The larger version: whenever `see` gets a URL that is not a bench clip, it saves the platform's side data next to `sensed.json`. That means creator chapters, platform subtitles, a descriptive audio track if one exists, the uploader handle, and timestamped viewer comments ("2:13 he lied here"), which are a crowd's free label for which moments matter. Then a monthly offline scorer measures every line type against them, so the owner's own TikToks, reels and talks become the real-footage bench without anyone doing anything. Running cost: a few KB per real URL and zero CPU at sense time.

### m05.r1.4 Claims ledger with provenance: said, shown, or only in the post text
Builds on: m07.6 + m05.7 + m05.2
The likely fact-check failure is quiet. The agent checks the post's description or the yt-dlp title, because those are easy text, and reports that "the video claims X" when nobody in the video said X. Build on m07.6's `text-only` marks with a small `claims.tsv`: each number, name, date or @handle, its time, and where it came from (`said`, `shown`, `said+shown agree`, `said/shown disagree`, `description only`). The card gets one pointer line with the count. The agent can then cite a claim to a source track and a timestamp, and it can see when it is about to verify something the video never contains. Judge: on `tiktok_vi` and `reel_en`, script the claims and score how well each claim's source is attributed.

### m05.r1.5 Line leases: every line kind expires unless the bench renews it
Builds on: m08.2 + m05.5 + m08.8
m08.2's rent audit is the right deletion gate, but the pre-mortem is that it runs once, the card is lean in November, and by next autumn it has grown back, because nothing re-runs the audit. Remove the assumption that a line kind, once earned, stays earned. Each line kind (CUTS, camera moves, OCR, voice tags, mood words) gets a lease in code: the bench round and question ids that last justified it, plus an expiry date. A unit test fails when a lease has expired without a newer bench run renewing it. When the real-use log from m08.8 shows that agents never open what a line points to, its renewal needs a stronger case. Cost: one test, no runtime.

### m05.r1.6 Three witnesses for a speaker's name: vocative, lower-third, and the uploader
Builds on: m07.2 + m07.3 + m07.6
Vocative binding (m07.2) on its own will eventually misname someone: "thanks, Lex" said *about* Lex and not *to* him, and the owner's summary cites the wrong person with confidence. Talks and news reels usually show a lower-third name caption ("Sam Altman, CEO OpenAI") while that person speaks on screen. OCR already reads it, and m07.3's voice-to-shot join says who is on camera at that moment. So bind a name to a voice letter only when two of three witnesses agree: the vocative, the lower-third shown while that voice speaks on its own shot, and the uploader or handle for a solo talking-head reel. A single witness keeps the letter and adds `(maybe Lex)`. Judge: name precision on podcast intros and the talk bench, where a wrong name scores worse than no name.
