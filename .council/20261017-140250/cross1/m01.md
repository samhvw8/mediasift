## Builds

### m01.r1.1 Card invariance: a dub must change the words and nothing else
Builds on: m01.1 + m04.3 + m02.7
All three of us diff the source card against the dub card. This turns the diff into one rule a studio's QC uses, written as a property: after re-voicing, every card field except speech text and language must stay the same (cuts, OCR, every `snd` event and its level within ±3 dB, music mood, speaker letters and their times), and speech must land inside the source line's slot. `mediasift check DUB --against SOURCE` prints only the broken invariants with times, so a clean dub costs one line. The same property judges every other transform the owner runs on media (the re-encode that was "too heavy to share", a crop for a reel): each one states which fields it must keep, and the checker needs no new judge, because the source card is the answer key.

### m01.r1.2 One caption alignment, three outputs: speech judge, graphics inserts, dub caption conflicts
Builds on: m02.1 + m01.5
m02.1 aligns burned-in captions to ASR to grade real Vietnamese speech; m01.5 uses the same match to split OCR text into `echoes speech` and `standalone`. Doing it once gives three outputs: a WER on real social video (the echoes), a list of on-screen claims for fact-checking and subtitling (the standalones), and something a dubbing engineer checks first. A reel dubbed into Vietnamese still carries the creator's English captions burned into the picture, so viewers read one language and hear another. The echo spans become a `captions conflict` cue for anydub (cover them, or keep the original voice there), and the creator's caption chunking is a ready-made line split for re-voicing, because the creator already cut the speech into units that fit on screen.

### m01.r1.3 The bed survives re-voicing: provenance by M&E fingerprint, with anydub making the test set
Builds on: m04.2 + m01.8 + m04.3
m04.2 found an uncredited copy by comparing picture hashes, but TikTok copies flip, crop and zoom the picture. A re-voiced copy is a dub, and in a dub the music-and-effects bed is the part that is kept. So each card stores a fingerprint of its non-speech sound: the CED window embeddings it already computes, taken from the speech-free windows. A new `see` then reports `same bed as card X 00:03-01:10, voice differs` even when the picture hash fails. This goes ten times further than one reverse search: the same index also finds the trending sound reused across many reels. The judge costs nothing, because anydub produces labelled re-voiced copies of any bench clip on demand: dub it, crop it, mirror it, and check that the match still fires.

### m01.r1.4 Separate only where the alarm fires, and let the alarm also catch untranslated speech
Builds on: m02.2 + m01.8
m01.8 separates speech from music wherever they overlap, which can be a whole reel. m02.2's alarm (CED hears speech but ASR wrote few words) narrows that to the spans where ASR has been shown to fail. Only those spans go to the separator on the GPU box, and ASR runs again on the vocal stem. Separation then costs seconds per card instead of minutes, and on a clean talk it costs nothing. For dubbing, a line that was never transcribed is a line that is never dubbed, so the original English stays audible under the Vietnamese. The dub check reports that alarm as `untranslated speech left 02:18-02:31`. Judge: the Tears of Steel official subtitles give the alarm's precision and recall, and WER on the stem against the mix is measured on the same alarmed spans.

### m01.r1.5 A native-pace reference built from the owner's own Vietnamese reels
Builds on: m01.7 + m04.3 + m04.4
"It sounds like a Vietnamese person reading Vietnamese as if it were English" (09-23) is a pacing and pause failure, not an emotion. A studio fixes it by casting and directing the voice actor, never with an emotion label. The cached cards of real Vietnamese reels already hold ASR word times. From them mediasift can build a reference distribution of how fast native speakers talk and where they pause: syllables per second, pause length and pause position within a clause. `check` then scores each dub line against it, and against the casting sheet's rate for the source speaker. A line paced like translated English falls outside the reference and gets flagged. The owner's complaints, harvested as in m04.4, are the labels: the 09-23 dub must fail this check, and a dub he accepted must pass.

### m01.r1.6 cues.json earns its fields by a downstream metric, not by card tokens
Builds on: m01.6 + m02.6 + m02.8
m02.6 cuts a card line when removing it changes no answer. The same ablation works on the machine-read spotting list, with anydub's own numbers as the test: lines over slot, mean lag, and the count of broken invariants from m01.r1.1. A field such as on/off camera, the futz tag or the keep-list stays in `cues.json` only if removing it makes those numbers worse on the reference dubs. m02.8 adds the safety half. Every `cues.json` carries the schema version and the model revisions that produced it (`QUAN_REV`, `CED_REV`), and anydub refuses a stale file with one clear line instead of reusing it silently. So the file cannot pile up unused fields or pass along a stale transcript.
