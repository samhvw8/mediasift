## Builds
### m05.r2.1 The boring cache test, made into a lazy per-sensor re-sense (answer to the provocation)
Builds on: m02.r1.6 + m05.3 + m05.r1.1
m02.r1.6's invariant test is the boring idea that would quietly work. Its probable failure a year out: once `QUAN_REV` and `CED_REV` are folded into the cache key, every pin bump invalidates the whole cache, the 47-min talks and the 1h45 podcast re-run from scratch, and the owner starts passing `--no-fresh` or pinning old revs to avoid the wait. The exciting version stores, in `sensed.json`, which sensor revision made each track (picture, CED, ASR, OCR, mood). On a cache hit, only the stale tracks re-sense, the header and commands always re-render from the current binary, and m05.r1.1's known-defects line covers anything that cannot re-run. A pin bump then costs one ASR pass, not a full `see`, and the invariant test walks the real cache, not only a CI fixture: it asserts that no card names a dead command or a stale track without saying so.

### m05.r2.2 One schema for every free judge, so the self-grading bench does not rot into five files
Builds on: m04.r1.3 + m02.r1.1 + m04.1 + m04.r1.1 + m05.r1.3 + m05.r1.5
Five members each proposed a judge that harvests itself: YouTube chapters, burned-in captions, the owner's screenshots, the dub script and platform side data. In the pre-mortem each ships with its own jsonl and its own scorer, two of them break when yt-dlp changes a field name, and nobody notices because nothing reads the files. Push it further: one `selfgrade.jsonl` row schema (card key, line kind, judge kind, span, hit/miss, sensor revision) with one writer in `see`, and the line leases from m05.r1.5 renew only from these rows. A judge kind that has written no rows in 60 days fails its own lease test, so a broken harvester stops the build loudly instead of going quiet.

### m05.r2.3 A caption disagreement is evidence, never an automatic correction
Builds on: m02.r1.1 + m03.r1.2 + m05.r1.2 + m05.r1.4
m02.r1.1's middle bucket prints the caption spelling as the fix ("bát tự" for "bắt tự"). That is right for spelling, but the quiet failure is on numbers: on a misleading reel the voice says 15% and the caption says 50% *on purpose*, the card "corrects" to 50%, and the agent fact-checks a claim the speaker never made. Build the version without that flaw. Auto-correct only proper-noun spelling within a small edit distance, and only when m03.r1.2's second ASR hearing agrees with the caption. Numbers, negations and dates are never corrected: they go into m05.r1.4's claims ledger as `said/shown disagree`, with both values. m05.r1.2's single footer then lists them as "do not quote either side without saying which". Judge: TTS reels where some mismatches are deliberate (the caption is the claim) and some are ASR errors, scored separately on wrong-claim-attributed.

### m05.r2.4 A sensing ladder: when the full download fails, say exactly how much was sensed
Builds on: m04.5 + m05.7 + m05.r1.3
m04.5's `peek` (storyboard sprite plus auto-captions) is pitched as a pre-filter. Its larger role is the floor of a ladder for the failure my pre-mortem expects most: TikTok or Facebook extraction breaks, or YouTube rate-limits, and the agent fact-checks the post text instead. `see URL` steps down from the full sense, to peek (storyboard plus platform captions), to the info JSON only. The first card line states the rung reached, e.g. `sensed: storyboard + auto-captions only; audio NOT heard; no sounds, no speakers`, and lists the lines that are therefore missing. The agent can still answer "does it show X", and it cannot mistake a partial card for a full one. Judge: one test per rung that forces the failure and asserts the rung line, plus peek-vs-see agreement on bench URLs.

### m05.r2.5 Sense once, render per job: the card shows only the lines this job pays for
Builds on: m04.6 + m05.3 + m02.r1.3 + m05.5
Every member's footer, ledger, credit line and cue block is right for one job and pure token cost for the others. A year out, the card has quietly grown back to the size m02.r1.3's deletion gate was meant to prevent. Delete the constraint that there is one card. `sensed.json` stays the single cache, and the prompt hook already sees the owner's words ("verify", "dub", "summarise", "bug"), so it passes `--for factcheck|dub|summary|bug` and the card renders at read time. Fact-check gets the claims ledger and credit, dub gets the cue and bed levels, summary gets chapters and `also in:` links, and bug repro gets OCR text and cuts. The meter is m05.5's tokens per answered job, measured per job kind, so each line kind earns its place in one job's view and pays no rent in the others.

### m05.r2.6 (fresh) The silent-success audit: the jobs where nobody complained
Builds on: m04.r1.6 + m02.r1.5 + m05.1
Every learning loop proposed so far (complaints, owner follow-up checks, search rewrites, `fix`) learns only from jobs where someone pushed back. The pre-mortem failure is the opposite: a wrong number went into a summary that the owner shared and never re-read, so no complaint exists, and every loop scores that job as a success. Once a month, pick 3 real jobs with no complaint, re-sense them with the strongest path the hardware allows (whisper-large via `--on`, both ASR backends, every free judge from m05.r2.2), and diff that result against what the agent actually told the owner. The bench and the ledger cannot see that error rate any other way. Cost: about 3 GPU-box runs a month, scheduled for when the box is up.
