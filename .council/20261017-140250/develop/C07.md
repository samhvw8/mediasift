## C07 The cache as a citable library: grep, quote, link and restore context

## The concept

**Who it is for.** The owner's agent on the job he asks for most: "transcribe, summarise in Vietnamese with
timestamps, then link several videos together". It also serves the TikTok fact-check ("check the content,
then verify it").

**What it is.** mediasift stops treating each card as a dead end. Every transcript it has ever produced,
plus the ones its sibling anydub produced, becomes one local, read-only **library**. The agent queries the
library instead of re-reading transcripts. Every answer comes back as a **cite handle** (`yt:kBm8Ho-_RXM@41:10`)
that can later be checked, expanded into a quote, or followed from a clip back to its source. That is the
surprising core: a citation becomes something a program can look up and check.

**What the evidence on disk changed (measured today, not guessed):**

- The owner's real linking work already exists, and it is in anydub, not in mediasift.
  `~/workspace/tools/anydub/notes/tong-hop.vi.md` is a Vietnamese synthesis of 16 English talks. It has
  **147** citations of the form `[TS 0:30:08]`, and 16 per-video notes add 13-175 timestamps each.
  `~/.cache/anydub/` holds the 20 source transcripts, keyed by YouTube id: 1.13 M characters in all,
  0.80 M for the 16 cited talks (roughly 200k tokens to re-read). This is both the job and its judge.
  mediasift's own cache has 734 cards, but only 209 have speech and about 730 are bench runs.
- **Verbatim shingles do not link different talks.** I indexed both caches with 8-word shingles
  (229 transcripts, 242k shingles, 1.4 s in plain Python). Among the 16 talks the owner linked by topic,
  no pair shares more than 4 shingles, and every hit is boilerplate: Diary of a CEO's closing question,
  "see you in the next one". The pitch's free `also said in:` line would therefore almost never fire on
  the linking job. Topic links need lexical search (and, if that is not enough, the embedding model
  mediasift already pins), not shingles.
- **Shingles are excellent at identity and excerpts.** The same Seyfried talk sensed by mediasift
  (`samples/long/cancer.mp4`) and by anydub (`kBm8Ho-_RXM`) shares 4,011 shingles. Better still, the owner's
  cache already contains a real excerpt: `tDmjz6HB-yw` (5:15) is cut from `6pxmdmlJCG0` (47:18, the Sam
  Altman writing talk). Aligning them took a 4-gram lookup. Clip `0:00` maps to source `43:04`, and clip
  `0:55.7` maps to `44:11`. The clip **opens on an answer** ("I'm a huge note taker") and drops the
  interviewer's question 3 s earlier ("Do you take notes during the week, or is it just on your head?").
  That is exactly the "what the clip left out" verdict, found in his own data on the first try.
- **Cache keys are not stable handles.** `content_key()` in `see.py` hashes `CARD_VERSION`, so every card
  bump re-keys a video (the Seyfried talk has 5 keys). Handles must use a media id: the YouTube id when
  known, otherwise size plus the first and last MiB *without* the card version.

So the developed concept keeps the pitch but gives each layer the job the evidence says it can do.
Lexical search plus handles serves linking and summarising. Shingles serve identity, excerpts and
re-uploads. The card gains a line only when a shingle match is real.

## How it works

One derived file, `~/.cache/mediasift/library.sqlite`. It is never the source of truth and can always be
rebuilt with `mediasift lib --rebuild`. It holds one row per speech line, OCR text and sound label:
`(media_id, start, end, kind, voice, text, text_vi, folded)`. There are two readers:

- **mediasift cards:** the newest `sensed.json` per media id. Sources under `samples/` or `bench/` are
  left out by default (`--bench` includes them), so bench copies do not drown real hits.
- **anydub cache (read-only adapter):** `transcript.json` segments, `translation.vi.json`'s `tr` field
  as `text_vi` (3 of the 16 cited talks have it today, 7 of 20 overall), and `info.json` title and
  duration. The adapter checks the shape it expects and **crashes with one line** if anydub's format
  changes, rather than indexing nothing.

Search uses SQLite FTS5, which the stdlib `sqlite3` already has (3.53.1 here, trigram tokenizer verified).
It uses `unicode61` with diacritics kept for exact Vietnamese, plus a `folded` column with diacritics
removed for recall, so a search for "bát tự" also finds the mishearing "bắt tự". A separate table holds
hashed 8-word shingles `(hash, media_id, t)` for identity and excerpt matching.

Commands, all deterministic, no model in the default path:

| command | returns |
|---|---|
| `mediasift grep "term" [--in IDS] [--voice B] [--meaning]` | at most 20 hits grouped by video, each `yt:kBm8Ho-_RXM@41:10 [B] "...line..."` plus `(on screen)` OCR hits and a per-video count. `--meaning` re-ranks with the EmbeddingGemma 2 setup `find` already pins (~2 s per call), for Vietnamese queries against English talks. |
| `mediasift quote HANDLE [-w 5]` | ±5 s of speech, the voice letter, OCR and shot letter at that moment, one frame path (when the media was sensed), `URL&t=`, and `same words also in:` from the shingle table |
| `mediasift align CLIP [SOURCE]` | a clip-to-source time map, the source lines inside and ±30 s around the window that the clip did not keep (`dropped 43:01 [B] "Do you take notes...?" (question before the clip's first line)`), and seams where the clip joins non-adjacent source moments. Without SOURCE it looks for one in the shingle table. Alignment is fuzzy (character n-grams, as passim does), because the two ASR runs disagree: the clip's ASR heard "not taker" where the source has "note taker". |
| `mediasift cite-check FILE [--codes TABLE]` | parses `@mm:ss`, `&t=`, `[CODE h:mm:ss]` (the code map is read from the summary's own table or from `--codes`). For each citation it prints `ok`, `no overlap` (no content word, name or number of the claim within ±10 s), `beyond end`, or `unknown video`. `--rewrite` maps clip citations to source time: `clip @0:14 = source @41:23`, plus a warning when a dropped source line sits within 5 s of the cited one. |
| card line (in `see`) | `also in: yt:6pxmdmlJCG0 @43:04-47:47 (this clip is cut from it; 2 lines dropped, see align)`. It is printed only when at least 20 shingles agree in time order, so it appears for duplicates and excerpts and never for topic overlap. |

**Later, only if the first three earn their place:** a series term base (`mediasift terms NAME`). It lists
every way a recurring name was heard, shown or subtitled across the library, by majority over OCR and ASR
witnesses (from m01.r2.4), so a summary cites, and anydub speaks, one spelling. Vocative names on voice
letters (m07.2, "called Tom by C") can label `quote` output once that rule has its own judge. Shot hashes
for reused footage (m03.5) stay out until a picture judge exists.

**How the agent uses it** (a skill change of about 6 lines): before writing a multi-video summary, run
`grep` per theme instead of opening `transcript.txt`. Cite only handles that `grep` or `quote` returned.
Run `cite-check` on the finished file before replying. For a short social clip whose source is cached or
found by web search, run `align` before stating what the speaker "said".

## First move

This week, with no product code: write `bench/library/cite_eval.py`, an offline script over the files that
already exist.

1. Build an in-memory FTS5 index over the 20 anydub transcripts (EN, plus `text_vi` where present).
2. Parse `tong-hop.vi.md`'s 147 citations and map codes to YouTube ids through the per-video notes'
   source URLs (all 16 resolve).
3. **Grep recall:** for each citation, query its claim (Vietnamese words, plus the names and numbers it
   contains) and score whether a top-5 hit falls within ±30 s of the cited time. Report two groups
   separately: the 3 talks with Vietnamese translations and the 13 without.
4. **cite-check:** shift 20 of the 147 citations by 30-120 s and measure catches against false alarms on
   the 127 untouched ones.
5. **Excerpt:** score `align` on the real pair (`tDmjz6HB-yw` in `6pxmdmlJCG0`: time map within 2 s, and
   the dropped question found), then on 10 synthetic excerpts cut from bench talks with planted omissions.
6. **Token meter:** replay one linking job both ways, reading the transcripts against grep and quote,
   and count the tokens each uses (m05.5's meter).

Product code follows only where a number clears its bar. The build order would be `grep` and `quote`,
then `cite-check`, then `align` with the card line, then terms.

## What must be true, and the cheapest test

| must be true | cheapest test | bar to pass | if it fails |
|---|---|---|---|
| The owner's jobs go through a cache the library can read | done today: both caches read in 1.4 s, and all 16 cited talks are in anydub's cache | - | - |
| Lexical search finds the moments a Vietnamese summary cites in English talks | step 3 above | top-5 within ±30 s on ≥70% of citations | add `--meaning` (EmbeddingGemma 2 is multilingual and already pinned) and re-score; if that also fails, `grep` stays a same-language tool |
| cite-check catches wrong times without crying wolf | step 4 | ≥80% of shifted citations caught, ≤10% false alarms | ship cite-check as "fetch the quote at each citation" with no verdict; the agent judges. This still saves re-reading. |
| Excerpts of cached sources really reach the owner | one real pair already found; count how many of his reels and TikToks have a findable source | ≥1 in 5 real short videos has a source that is cached or one web search away | `align` stays an explicit command, and the automatic card line is dropped |
| grep and quote actually save tokens | step 6, one replayed job | ≥3x fewer tokens for the same citations, all passing cite-check | drop the concept; summaries keep reading transcripts |
| Handles survive card-version bumps and re-downloads | unit test: re-key a card and resolve an old handle | 100% | it is a bug, fixed with a test first |
| The term base never changes a correct term | owner's Vietnamese reels with a hand-corrected term list | 0 wrong changes | it stays a suggestion list, never rewritten into a summary or dub script |

## Prior art (with URLs)

- **The owner's own voxtract MCP** (its tool docs appear in this session) already does the core move for
  meeting audio: `query_corpus` returns moments across all transcripts with `{id}@{start}-{end}` cite
  handles, and `get_audio_clip` turns a handle into audio. This is the closest prior art, and the
  handle format should match it so agents learn one convention. What it lacks: video, OCR, the anydub and
  mediasift caches, excerpt alignment and citation checking. It is also a hosted service, while this is
  a local file.
- **Cross-video transcript search products:** ChannelScout's saved transcript library with timestamped
  quote search (https://channelscout.app/blog/find-quotes-across-youtube-channels), CiteClip
  (https://citeclip.com/free-tools/youtube-transcript-search), and a Chrome extension that searches a whole
  channel's transcripts
  (https://chrome.google.com/webstore/detail/youtube-transcript-search/eeebipnojmgobognppffkenhdoidendi).
  The `grep` part is ordinary and already exists in many forms. What is still different here: it runs
  locally over the owner's own ASR (not YouTube captions), covers Vietnamese and OCR, returns handles
  that `quote`, `align` and `cite-check` consume, and works on TikTok and Facebook videos with no
  captions.
- **Text reuse detection** is a solved problem. passim indexes character n-grams and aligns candidate
  passages, defaults `-n 25`, `--min-match 5`, `--min-align 50`, and runs on Spark
  (https://github.com/dasmiq/passim). rOpenSci textreuse offers shingles, minhash/LSH and Smith-Waterman
  (https://docs.ropensci.org/textreuse/). mediasift needs only a small slice of this: hundreds of
  transcripts, not millions of pages, so SQLite plus a 4-8-gram lookup is enough. passim's
  character-n-gram choice is the right answer to the "not taker" / "note taker" mismatch.
- **Citation verification of LLM reports** is active research. "Cited but Not Verified" parses inline
  citations from generated Markdown and checks them against the cited source
  (https://arxiv.org/abs/2605.06635), and CiteAudit benchmarks fabricated and unfaithful references
  (https://arxiv.org/abs/2602.23452). Both target web or paper citations and use LLM judges. cite-check
  works at timestamp level, locally and deterministically first, and leaves the semantic call to the
  agent that wrote the claim.
- **Out-of-context clips:** verification guides stress that "removing the question or half of the answer
  may change everything" (https://detectvideo.ai/ai-video-analysis/). That is the very case found in the
  owner's Altman excerpt. I found no local tool that aligns a clip's transcript back onto its source to
  list what was dropped.
- **SQLite FTS5** (https://www.sqlite.org/fts5.html) provides unicode61 with a diacritics option, the
  trigram tokenizer and bm25(). It is in Python's stdlib, so there is no new dependency.

## What it costs to run

- **Infra:** nothing new. No service, no daemon, no metered API, no model in the default path. Disk use
  is one SQLite file. The two caches hold about 1.9 M characters of text and 243k shingles today, so
  the file should be a few MB (estimated, not measured). It grows with real use, not with bench runs,
  because those are excluded. `--meaning` reuses the llama.cpp embedding model `find` already ships
  (0.46 GB RSS, about 2 s per call, on demand only).
- **Per-turn tokens:** the card gains nothing on most videos, and one line when a video duplicates or
  excerpts a cached one. The intended effect is a large *drop* on the linking job: about 200k tokens
  to re-read the 16 cited transcripts, against a few dozen grep and quote calls of 20 lines each. Step 6
  measures this before any claim is made.
- **Operational:** indexing runs at the end of `see` and is incremental, roughly 1 s for the whole cache
  in my plain-Python prototype. It needs no watching. A corrupt or stale index is rebuilt from the
  caches, never patched.
- **Maintenance, the real cost:** (1) the anydub adapter couples mediasift to a sibling's file format,
  which is one sync point; its schema check makes a format change loud instead of silent. (2) The media
  id scheme must stay stable forever, because summaries embed handles. (3) Each command needs its bench
  row kept alive: 147 real citations, the real excerpt pair, and synthetic excerpts. (4) The term base is
  deliberately last, because it is the one piece that could rewrite text, and it must earn a 0-wrong-change
  score first.

**Runs:** one derived SQLite file in `~/.cache/mediasift/`, updated at the end of `see`, plus a read-only
dependency on anydub's cache format. No services, no models in the default path.
