## Fragile assumptions

Ranked most fragile first.

1. **A cross-modal cosine between a frame and a nearby sentence measures "the speech already covers this frame" (untested, most fragile).**
   The concept itself says it found no published number for this. Image-text cosines measure topical association, not information coverage. A frame of a slide titled "Loops" and the sentence "now let's talk about loops" will score high, yet the slide body (code, numbers) is the part the agent needs. That is the detail-collapse failure, and it hits exactly the content the feature targets (lectures, slides). The guard rail ("never demote a frame the pixel pipeline marks text-dense") leans on a flag that does not exist: `grep` in `src/framesift/` finds no text-dense classifier. There are per-block edge-density arrays in `visual.py`, but no per-frame "carries text" decision. So guard rail 4 is new, tuned surface, not reuse.
   The modality gap is real and well documented (https://arxiv.org/html/2406.17639v1, https://arxiv.org/pdf/2609.01103), which supports the choice of ranks over absolute cutoffs. But a z-score inside one video is also fragile. In a 100-second explainer with about 30 keyframes, the z-score pool is tiny, and in a one-topic lecture every sentence matches every slide about equally. The "locality" test then decides everything, and locality is also true of any talking head.

2. **The QA bench can validate it (shaky).**
   The concept's cheapest test needs condition A (transcript only) and C results per question. `bench/prep_qa.py` builds the A/B/C/D folders, but `bench/results/` holds only scored manifests and run logs: there are no stored per-question answer outcomes. So the "free" A-correct set does not exist yet. It needs an agent run per question, and the concept's own caveat applies: a few dozen questions over 4 videos. Only two of the videos have continuous speech plus slides (`cs50_lecture`, `python_100s`), and those are the only ones where the feature is on. The AUC over a handful of segments will have a confidence interval that spans both the 0.7 pass line and chance. Also, questions written by an oracle who saw frames skew toward visual questions, so A-correct is a small, biased class, and a separating AUC can be an artifact of which segments have long speech.

3. **Demotion saves enough tokens to matter, and "visible extra pull" is cheap for the harness (shaky).**
   Sheets are 12 frames per JPEG. Demoting some cells only saves tokens when it removes a whole sheet, or when `--max-frames` is binding. If a typical lecture yields 20-40 keyframes, that is 2-4 sheets, and demotion of a third of them may save one sheet. Against that, the harness must now read a tag, notice the missing cell, and decide to pull a file: more turns, and each turn carries the whole context again. The concept counts the failure as "visible", but a missing frame in a sheet the agent never pulls is a silent loss in practice (the agent answers from the quoted sentence, confidently, and wrong). The SKILL.md wording has to teach the agent to distrust the tag, which erodes the saving.

Solid: the storage and runtime cost (a few MB, local, no service) and the design choice of rank over absolute thresholds are sound. The "Vietnamese unknown, skip loudly" rule is the right shape.

## Pre-mortem

A year later the feature is behind a flag nobody sets. What most probably happened: the probe script ran, the top-15 and bottom-15 listings looked plausible on `cs50_lecture`, because title slides and "so let's look at X" moments do score high. The AUC on the bench came out near 0.6 with a wide interval, which was neither a pass nor a clean fail. Rather than drop the family as promised, the threshold was adjusted once ("0.65 is fine for a small set"), and demotion shipped as an opt-in. Real use then showed two things. First, on code and diagram slides the frames the agent most needed were sometimes the demoted ones, and a couple of wrong answers got traced back to the tag. Second, `--max-frames` plus the existing drift ranking already cut most of the sheets, so demotion removed one cell per sheet on average and almost never a whole sheet. Per-turn token savings were within noise. The model pin and the extra 440M download became a maintenance cost (a version bump changed scores; the manifest check fired and users re-ran everything), and the `meaning.py` VLM path was never retired because the fire-rate bar was never met on 3 of 4 videos. Nothing broke; the knobs (`z` cutoff, locality margin, text guard) are still there, undocumented, and SKILL.md carries a paragraph that explains a feature few runs use.

## Who loses

- **The agent harness and the end user** if it succeeds wrongly: a frame the agent needed is replaced by a quote, with a cosine that looks authoritative. Response: they would add a "never trust the tag" habit (pull all frames anyway), which cancels the saving. Sam is the one who notices, via accuracy dropping on slide-heavy talks.
- **The existing pixel pipeline's simplicity.** The "analyse dense and cheap, emit sparse and rich" story gets a second, learned judge that can overrule the cheap one. Anyone debugging "why is this frame not on the sheet" now has two systems to inspect. This is a maintenance loser, not a person.
- **The `meaning` VLM captioner path**, if the later stage lands. Its quality (descriptions of what is visible) is replaced by the nearest sentence, which describes what is said. Response: those who rely on `meaning.md` for scene description of silent or quiet stretches would see a regression in exactly the frames where speech does not describe the picture, so the VLM would have to stay as the fallback, which is the state it is in today.
- Existing similar efforts: the slide-lecture note tools (MIT Visual Transcripts https://people.csail.mit.edu/hishin/projects/visual_transcripts/paper.pdf, LectureLens https://github.com/r0mar1n/LectureLens, the multi-lecture KG paper https://arxiv.org/html/2608.03161) do not lose; they keep frames when the transcript keyword or relationship cue appears, and use change plus transcript cues to pick anchors (about 18% of frames) rather than demote. That is evidence the field selects frames *by* speech cues (keep what is mentioned), the opposite sign from this concept (drop what is narrated). It is not evidence against, but it means no one has validated the "narrated therefore redundant" direction.

## Fixes

| Weakness | Smallest fix |
|---|---|
| Cosine measures topic, not coverage | Add the check the concept already half-lists, but make it a hard gate before any pipeline code: on the probe, for every high-score frame on `cs50_lecture`, count frames containing code or numbers. If more than a few percent are high-score, the demotion half is dead. Keep only the retrieval-caption half (flag, never demote). |
| Text-dense guard does not exist | Either define it explicitly (edge-density threshold per frame from the existing `edges` array, one number, tested on the 2 speech videos) and count it as new surface, or drop the guard and restrict demotion to `camera`-type segments (talking heads), where `screen-vs-camera.md` already draws the line and detail collapse matters least. The second is smaller and removes a knob. |
| z-score pool is tiny per video | Score against a shuffled-time null instead: for each frame, compare the cosine of its true local sentence with the cosines of sentences from randomly chosen other times in the same video. The statistic is "local beats random", needs no pool size, and is directly the locality idea. |
| QA outcomes do not exist | Run condition A and C once for the speech videos before anything else, and store per-question results in `bench/results/`. This is a prerequisite cost, not a free reuse. Report wins and losses per question, as the concept says; do not pass on a mean. |
| Savings only when a sheet disappears | Measure first: from existing manifests, count how many sheets would vanish if the top-N scoring frames were dropped. If it is under one sheet per video, no fix: the feature is not worth shipping. |
| Silent failure in practice | Keep the quote and the file path in the storyboard line (already planned), and add a one-line rule to SKILL.md: tags only ever *reorder or defer*, never hide a frame the agent cannot see a thumbnail of. A 64 px thumbnail strip for demoted frames would keep them visible at a few tokens, at the price of a third render artifact (no fix is free). |
| Model pin and download | No fix: this is the price, shared with the other embedding proposals. Pin model id and dim in the manifest, as planned. |
| Vietnamese / non-English unknown | No fix: skip loudly, as planned. |

## Verdict

**Survives with changes.** The probe (about an hour, no pipeline change) is a good first move, and the rank-based, local-only design is cost-sound. But the central claim has no evidence, the text guard is missing, and the bench cannot give an AUC until A/C runs exist. Required changes: (1) make the probe's go/no-go the code-and-numbers frame count, with the kill rule stated in advance; (2) restrict v1 to tagging and retrieval caption, with no sheet demotion, until the matched-token comparison against random frames at equal image count passes; (3) replace the in-video z-score with the local-vs-random-time null; (4) run A and C and store outcomes before computing any AUC; (5) first count how many sheets would actually disappear. If (1) or (5) fails, drop demotion and keep only the retrieval caption.
