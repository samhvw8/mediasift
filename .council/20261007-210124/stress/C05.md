## Fragile assumptions

Ranked most to least fragile.

1. **Reordering sheets saves tokens (untested, and probably wrong as designed).** The concept keeps the same cell count and the same number of sheets, only reordering. `render.contact_sheets` still emits every sheet, and a harness that reads the output directory loads all of them. Image tokens fall only if the agent stops after sheet 1, and nothing makes it do so. The bench metric "correct answers per 1k image tokens" at equal image count is rigged to be flat: same images, same tokens, so the only possible gain is accuracy, and the true-question arm is an oracle the real agent never has. Fix the framing: either `--ask` emits fewer sheets (a hard cap, e.g. top-N cells only), or the claim is "accuracy at equal tokens" and nothing about savings. Status: untested, leaning false.
2. **Text-to-frame retrieval and menu phrases work on this content (untested; the model is one day old).** I found no text-to-frame benchmark for screen recordings or slides. The card gives MIEB lite 64.64 and MMEB v2 Image 57.28 at 768d, which are generic scores, not "find the slide with the loss curve" (https://huggingface.co/google/embeddinggemma-2). The prior research already says semantic embedders collapse layout and instance detail. The menu is weaker still. It prints transcript phrases nearest a visual cluster centre, which is image-to-text across the modality gap. In lectures and talking heads the speech rarely names what is on screen. The concept's own example, `"the loss curve slide"`, is a caption, not a transcript phrase, so it quietly assumes the VLM `meaning` step has run. Without speech or `meaning` there is no menu. Status: untested; the menu is the shakiest part.
3. **The bench can prove it (shaky).** `bench/prep_qa.py` has four samples, and its questions were written by someone looking at oracle dense sheets. Evidence-frame labels may not exist as ground truth, so "does the evidence frame land on sheet 1" needs a hand-labelled frame set first. With four videos, 12-cell sheets and few questions, hit@1-sheet is a noisy small-n number. Sheet 1 holding 12 of maybe 40 keyframes also means random already hits about 30%, so "clearly above random" is a thin margin. Status: shaky.
4. **256d is enough (mostly solid).** Verified on the card: MMEB v2 59.01 / 56.24 / 45.65 at 768 / 256 / 128d, re-normalise after truncation, and "128d... should be validated against your own workload". The card's text says 128d "is best suited to text-only workloads", which the concept does not mention. The point it misses is that a 2.8-point drop in aggregate says nothing about fine ranking inside one video, where candidates are near-duplicates. Storage is 3 MB per video at 256d, so just store 768d and cut the dimension at query time. Status: solid on the card, untested for this use.
5. **Local cost is small (shaky, unmeasured).** The checkpoint is 1.49 GB in BF16 (card metadata: 744M params). The vision tower costs 280 tokens per image by default. A 100-second video has hundreds of keyframes, plus transcript windows. The concept admits throughput on Apple Silicon is unknown. If embedding takes minutes per video, "analyse dense and cheap" is broken for the default path.
6. **Prior art (checked, solid).** AKS does exist, CVPR 2025, with relevance plus coverage: https://arxiv.org/abs/2502.21271 . The concept's novelty claims (hard floor, floor-only reporting) are fair but small. The "nobody ships a menu" claim is unverified, and I did not find a counterexample.

## Pre-mortem

The most probable quiet failure is not a crash. It shipped, `--ask` worked in the demo, and nobody used it. The agent's first pass runs `analyze` with no question, as SKILL.md says. It reads all the sheets because they are all there, so reordering changed nothing it saw. The menu footer lines were mostly speech fragments ("so now let's look at this") that said nothing about the visuals, so the agent never copied one. On the two videos that were mostly speech the menu was empty or generic. The `signals.npz` vector block pinned a model and dimension. Six months later a new sentence-transformers or transformers release changed the Gemma 2 pooling or prefix handling, the stored vectors mismatched, and the loud-failure rule fired as designed. That meant a forced re-embed (slow on a Mac) every time, so the vectors were made optional, and then `--ask` was off by default and rotted. The 1.5 GB download and the heavy dependency were the visible cost, and the benefit stayed invisible because no run logged whether `--ask` was used or whether it beat chronological order. Failure was gradual disuse plus one more optional extra to keep compatible.

## Who loses

- **The `find` command (proposal 3).** C05 absorbs it as a layout mode. If `--ask` shows its relevant-first ordering is awkward to read, the agent wants a plain ranked top-k grid back, and the two end up coexisting. Response: keep `find` as the thin path and let `--ask` call it, or drop `--ask`.
- **Chronological reading.** Today the sheets read as a timeline. Relevance-first reordering breaks "sheet 3 is the middle of the video", and the storyboard.md references would need to track the new order. The agent loses temporal orientation exactly when the question is wrong. The floor helps coverage but not order. Response: keep time order inside each sheet and only reorder which frames are selected.
- **Pixel-drift keyframing and the meaning step.** If MMR dedupe uses embeddings, it competes with the existing drift logic and the keyframe-drift decision. The maintainers of those heuristics would defend them by pointing at layout collapse.
- **Nobody else is harmed.** There is no competing product to displace.

## Fixes

| Weakness | Smallest fix |
|---|---|
| Savings claim is not real (1) | Make `--ask` change the count, not just the order: cap to the top N cells and the floor, or emit sheet 1 plus a one-line index of the rest. Otherwise drop the token-savings claim and test accuracy at equal tokens only. |
| Retrieval unproven (2) | Run the first-move probe, but add a ground-truth step first: hand-label 5-10 evidence frames per sample, record the true question, and report hit@k at 768, 256 and 128d against random and chronological. Keep the kill rule: not clearly above random on lecture and explainer means stop. |
| Menu is cross-modal and speech-bound (2) | Cut the menu from v1. If kept, build it from text-to-text neighbours only (transcript windows or VLM captions clustered in the text tower), never from image centres. The test is the one already specified: fraction of menu lines that put the evidence on sheet 1. |
| Bench is thin (3) | Add paraphrased and deliberately wrong questions, report counts, and refuse to claim a gain below a stated threshold. No fix for the small-n limit: this is the price of four samples. |
| 128d (4) | Store 768d (about 12 MB) or 256d. Use 128d only if the probe shows no loss. |
| Embedding cost (5) | Measure seconds per keyframe on the Mac in the first move; if over a stated budget, embed only selected keyframes, not all frames. |
| Model/version drift (pre-mortem) | Record model id, revision, dimension and prefix string in `signals.npz`. Make the vector block lazy: embed on first `--ask`, not at analyze time, so the default path pays nothing. |
| Dedupe collapses layout | Use pixel drift for the "different slide" decision and embeddings only for ranking, as the concept's own test 6 suggests. |

## Verdict

**Survives with changes.** The retrieval-plus-floor idea is sound and has precedent (AKS), but the headline benefit as written is not real: reordering at equal cell count does not cut tokens, the menu has no cross-modal evidence behind it, and nothing is measured yet. Required changes: make `--ask` reduce what is emitted or drop the savings claim; drop or text-only the menu for v1; make embedding lazy so the default path is unchanged; run the labelled probe before any CLI work.
