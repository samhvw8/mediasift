## Builds
### m02.r1.1 One bench harness with a random-frames control and a tokens-per-correct-answer meter
Builds on: m03.8 + m02.6 + m01.2
Precedent: Otani 2019 killed a decade of summarisation F1 because nobody ran a random arm. m03.8 gives the metric (image tokens per correct QA item); m02.6 gives the control; m01.2 gives the gate for the layout-collapse risk. Together: every config runs as three arms (feature, current heuristic, uniform random at equal count and token cost) and the printed row is tokens per correct answer, plus a "beats random: yes/no" column. The addition is a rule from constraint removal: delete the human-labelled pair sheet by deriving same/different pairs from the QA items themselves (two frames are "different" if a question needs both), so the whole gate needs no new labelling.

### m02.r1.2 Cluster sheets whose cell size comes from codec-calibrated spread
Builds on: m03.3 + m01.5 + m02.4
Precedent: video "storyboard by shot clustering" (Yeung and Yeo 1990s) died because cluster count and merge thresholds were hand-set per corpus. Here m03.3 makes a sheet per meaning cluster, m01.5 sizes each by spread, and m02.4 sets the cluster-merge threshold per video from the codec's I-frame cuts (cut distances versus within-shot distances). What none had alone: the only number that touches the layout is derived from free evidence the video already carries, so the sheet builder has zero new knobs; with no codec cuts it falls back to chronological 12-cell sheets and prints that it did.

### m02.r1.3 The question-and-summary loop as a closed audit: `--ask` in, `check` out, caption tripwire in the middle
Builds on: m03.2 + m03.4 + m02.1
Precedent: Informedia's query-driven skims and later "query-focused summarisation" worked for the asker but never told the asker what was left out. m03.2 orders sheets around the question; m03.4 returns the segments the harness summary did not cover; m02.1 flags captions that disagree with their frame. Joined, the harness gets a closed loop: first pass is goal-conditioned, the second pass is a coverage-hole sheet, and every text claim that rests on a VLM caption carries a faithfulness flag. Added: the coverage score from `check` doubles as the bench's label-free accuracy proxy, so m03.8 can run without hand-written QA on new videos.

### m02.r1.4 Delete `meaning` in stages, with the embedder as the replacement's referee (ten times larger version of m03.1)
Builds on: m03.1 + m02.1 + m01.6
Precedent: pipelines that removed a captioner (retrieval-based captioning, 2019 onward) lived when they kept a fallback and died when retrieved text was trusted blindly. Instead of one yes/no on deleting the VLM, run three stages on the bench: (1) retrieved transcript sentence replaces the caption when cosine is high (m01.6); (2) the harness names chapters from sheets alone (m03.1); (3) the VLM runs only on frames that fail both the retrieval match and the caption tripwire (m02.1). The VLM becomes a rare fallback, then a deleted dependency if stage 3 fires on under a few percent of frames. Added: a measured fire-rate as the deletion criterion, so the config knobs are removed by a number, not a feeling.

### m02.r1.5 Audio tower earns its place on exactly one question: silence of speech plus change of picture
Builds on: m03.7 + m01.3 + m02.5
Precedent: AudioSet-style tagging died on closed vocabularies; m02.5 and m01.3 reopen it with text queries, and m03.7 argues the 300M tower is unwanted weight. Constraint removal on "the tower must run on every video": run it only on windows where VAD finds no speech AND the visual drift is above the video's median, which on the animation and short film are exactly the stretches the transcript cannot explain. Added: a single admission test for the tower (does it change any storyboard row on those windows on the bench?), and if not, m03.7's deletion is recorded as the answer with evidence instead of by assertion. Lazy load means no RAM cost on speech videos.

### m02.r1.6 Fresh: a "what the corpus remembers" file so the next video starts calibrated
Builds on: m01.1 + m02.3 + m02.4
Precedent: the framesift cut-threshold sweep (0.25 got 0/22 on CS50) is a graveyard of per-corpus constants. Having per-video statistics (embedding-per-pixel-drift ratio from m01.1, zero-shot content type from m02.3, codec-calibrated threshold from m02.4) written into manifest.json, the bench can compare them across videos and flag the day a new video lands outside every earlier one. Added: not a new threshold, but an out-of-distribution warning, "this video's ratio is beyond everything seen", printed loudly so a silently wrong default never ships.
