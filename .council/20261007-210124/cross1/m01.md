## Builds
### m01.r1.1 One redundancy probe that settles four claims at once
Builds on: m01.4 + m03.5 + m02.2 + m01.6
Three of us propose the same signal (transcript sentence vs nearest keyframe cosine) for three different jobs: demote frames from sheets, skip VLM captions, and label segments redundant or adds. Treat it as one measurement with one test: on lecture and explainer, take the 60 frames with the highest and lowest cosine, hand-label "does the speech already say what the frame shows" (yes/no), and report AUC. If AUC is under about 0.7, all four ideas die together. If it holds, one threshold feeds the sheet demotion, the VLM skip and the storyboard tag, and the local-quality rule is that it runs only on speech-bearing segments (animation and silent film get no score, loudly).
### m01.r1.2 A free ground-truth ladder: random, uniform, current, embedding arm
Builds on: m02.6 + m03.8 + m01.2
m02.6 adds a random control and m03.8 adds tokens per correct answer, but a QA set of a few dozen items on 4 videos has wide error bars. Add a paired design: every config answers the same questions, report per-question wins and losses against the random arm with a sign test, and reuse the 40 same/different slide pairs from m01.2 as a second, QA-free gate for the veto. This tells the council which differences are real before anyone builds, and the 40-pair sheet is also the instance-detail probe, so one hand-labelling session serves both gates.
### m01.r1.3 Calibrate the threshold on codec cuts, then audit it on the instance pairs
Builds on: m02.4 + m01.2 + m01.1
m02.4 sets the veto threshold per video from codec cuts versus within-shot distances. Add the held-out check: compare the self-calibrated threshold with the one that best separates the labelled pairs from m01.2, and publish the gap per video. A small gap means the zero-knob threshold is trustworthy; a large gap on screen-heavy videos is the exact evidence that the screen path must stay pixel-only. The same per-video embedding-to-pixel ratio from m01.1 is the third column, so one table shows screen-vs-camera, threshold and trust.
### m01.r1.4 Cluster sheets with a measured repeat tax
Builds on: m03.3 + m01.5
m03.3 gives each cluster its own sheet; m01.5 sizes cells by within-segment spread. Combine them: clusters across the whole video give the sheets, and cell count per cluster follows its spread, so a returning host appears once and a diagram-heavy cluster gets more cells. Add the proof neither had: count how many QA items need a second timestamp of the same cluster (the repeat tax) under chronological sheets, and the cluster layout must cut that count to be kept. Local quality here means the layout only switches on for videos where clusters recur (lecture, explainer), and falls back to chronological for one-shot footage like the short film.
### m01.r1.5 Ten times larger: a standing audit of every heuristic against the embedding space
Builds on: m02.1 + m01.8 + m02.3
m02.1 audits VLM captions, m01.8 alarms on bench drift, m02.3 replaces a classifier. Push them into one offline `bench/audit` run that scores every decision framesift makes (each dropped frame, each kept frame, each caption, each boundary, each screen/camera call) with a single embedding statistic and lists the top 20 most suspicious decisions per video as a contact sheet for a human to look at. Nothing ships per run and the running cost is zero; the output is a ranked list of where the heuristics are most likely wrong, which turns "which of the five proposals" into data.
### m01.r1.6 Fresh: a cheapest-first experiment order with kill criteria
Builds on: m01.1 + m01.7 + m02.5 + m03.7
Reading all three, the unobserved claims share one bottleneck: we have never embedded a bench frame. Make step zero a single script that embeds 1 fps frames of the 4 videos at 768 dims and caches them, then order every test by what it needs: first the MRL recall table (m01.7), pixel-versus-embedding ratio (m01.1) and instance pairs, all from that cache; then text-tower tests; the audio tower last, because m03.7 argues to leave it out and m02.5 wants it, and only a silent-film test showing whisper and log-mel both failing would justify loading 300M weights. Each step gets a number that kills it, so the audio tower earns its place by evidence rather than by being in the box.
