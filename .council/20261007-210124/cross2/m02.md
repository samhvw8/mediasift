## Builds
### m02.r2.1 Delete keyframe selection: sample uniformly, let the embedder only order and fold (answers the provocation)
Builds on: m03 provocation + m03.3 + m01.5 + m02.r1.1
Precedent: uniform sampling plus a good consumer beat clever selection in video QA (the Otani 2019 random-arm result, and the later uniform-frame baselines in long-video VLM work), and shot detection died as a product while "sample every N seconds" lived. Constraint removal: delete "framesift decides which frames exist". Sample 1 frame per few seconds at fixed cost, embed all of them, and the model's only jobs are cluster sheets (m03.3), spread-sized cells (m01.5) and the random-arm meter. What is left is a tool with no drift threshold, no veto, no 0.6 s sharpness window; the bench row for it is just another config in the ledger, kept only if tokens per correct answer does not rise. The thing added that no parent had: the existing codec I-frame and pixel-drift path stays as the dense layer that decides sampling density, so selection is deleted but timing evidence is not.

### m02.r2.2 Delete the sheets instead: the storyboard becomes the product and images are fetched on request
Builds on: m03.4 + m03.2 + m01.4
Precedent: Informedia and later "video as text" captioning pipelines lived where the consumer could ask for more detail on demand, and died when they pre-rendered everything. Constraint removal: delete "images are sent by default". The default output is text only, each storyboard row carrying the redundancy tag (m01.4: redundant or adds) and a one-line retrieved speech sentence; `check` (m03.4) and `--ask` (m03.2) become the only ways an image leaves the machine, as a small sheet of the holes or the matches. What this adds: image tokens become a pull cost the agent pays by choice, and the bench meter is images requested per correct answer, with zero as a possible value on the lecture.

### m02.r2.3 Delete `find` as a command: every sheet carries its own query handles
Builds on: m03.2 + m01.7 + m02.r1.4
Precedent: search UIs for video (YouTube chapters, Vimeo search) survived by showing suggestions, not by waiting for a typed query. Constraint removal: delete "the agent must know what to ask". At 128 dims, cluster the stored vectors once and print, under each sheet, the three transcript phrases nearest each cluster centre as ready-made queries (`ask: "slide with the loss curve"`). The agent re-asks by copying one, and a re-ask is milliseconds from stored vectors. Added to the parents: it removes the cold-start problem of goal-conditioned sheets, since the first pass needs no question and the second pass starts from a menu.

### m02.r2.4 Delete the VLM, keep its slot as a bench-only referee (ten times larger m03.1)
Builds on: m03.1 + m01.r1.5 + m02.r1.4
Precedent: pipelines that dropped a captioner and trusted the replacement blindly died quietly; ones that kept the old component as an offline auditor lived. Remove `meaning` from the shipped path entirely (no config, no key, no metered call) and move the VLM into `bench/audit` as the referee that captions the 20 most suspicious decisions per video (m01.r1.5) to judge whether the retrieved sentence was right. Added: deletion is final in the product but the old component survives where it costs nothing per run, so the evidence for the deletion can be re-run each time the model changes.

### m02.r2.5 Delete the video: a bench of sheets against sheets, to find the floor of what the harness needs
Builds on: m03.r1.2 + m01.r1.2 + m02.r2.1
Precedent: ablation by removal is how summarisation finally got honest (random and first-N baselines). Constraint removal: delete "we have not run the harness on the sheets alone". Take the QA items and give the harness only three arms at equal tokens: uniform sheets, cluster sheets, and transcript only with no images. The gap between transcript only and best sheets is the ceiling on what any selection idea can earn on that video, per video. This adds a number the ledger lacks: a ceiling, so a feature chasing a gap that is already under noise is known dead before it is built.

### m02.r2.6 Fresh: the graveyard file, so a deleted feature leaves its epitaph
Builds on: m02.r2.1 + m02.r2.4 + m03.r1.7
Every deletion above is only safe if the reason survives it. Each time the ledger deletes a heuristic, the bench writes a dated entry (config, arm, tokens per correct answer, video, the model version) into `.okf/decisions/`, and a later model release re-runs just the deleted rows. The precedent is this repo's own keyframe-drift and cut-threshold history: constants were lost because their evidence was. Added: deletion becomes reversible by data, not by memory.
