## Builds
### m03.r2.1 The boring random arm, made a live "pull-it-out" runner: every shipped feature carries its own deletion test
Builds on: m02.r1.1 + m01.r1.2 + m03.r1.2 + m01.8
The random arm (m02.6) and the sign test (m01.r1.2) are the boring part that would quietly work. Make them exciting by turning the ledger into an automatic ablation: for each feature the bench re-runs the QA with that one feature removed and with random frames at equal tokens, and prints "pulled out: no loss" next to any row where the paired sign test sees nothing. A row with no loss gets a generated deletion diff, so the bench proposes code removal instead of only scoring additions. Added: the same run logs mean cosine and drop rate per video (m01.8), so the ablation baseline is pinned and a later commit that moves it fails loudly.

### m03.r2.2 A requirement trace the harness can read: every sheet states what the user's goal needs and what it left out
Builds on: m03.r1.7 + m02.r1.3 + m01.r1.4
My r1.7 kept the five-part goal as a bench checklist. Push it into the product: the storyboard header carries a four-line trace for this video (best frames: N of M kept, cells demoted and why; grids: tokens spent; analysis: segments with no cell; ask: segments covered only by the floor cell). The loop in m02.r1.3 (`--ask`, then `check`) fills the last two lines, and the repeat-tax count from m01.r1.4 says whether clusters or chronology was used. Added: the agent sees, in about five lines, what it was not shown, so a missing frame is a stated gap and not a silent one (crashing beats corrupting).

### m03.r2.3 One calibration ruler: the codec cuts label the data, the same labels grade the data
Builds on: m02.r1.2 + m01.r1.3 + m02.r1.6 + m03.r1.5
Three members each use codec cuts or pair labels to set a threshold (cluster merge, veto, return map). Use them as one ruler with one held-out split: half the codec cuts set the threshold, the other half score it, and the instance pairs from m01.2 are a third check on screen content. The result goes into manifest.json as a single record (threshold, held-out recall, gap to the pair-optimal value, out-of-distribution flag), and the return map in r1.5 reads that record instead of owning a cutoff. Added: the calibration is graded on cuts it never saw, so "zero knobs" is a measured claim, and a video with too few cuts says "uncalibrated" and uses chronological sheets.

### m03.r2.4 Ten times larger: the retrieved sentence is the caption, the VLM is the referee of last resort, and the fire-rate is a permanent bench column
Builds on: m02.r1.4 + m01.r1.1 + m03.r1.1
m02.r1.4 stages the deletion of `meaning`; m01.r1.1 says one probe with an AUC kills or keeps the whole family. Take it to the end: the bench tracks the VLM fire-rate (share of frames needing it) per video as a standing column, and the contract is that when the rate is at or below a stated level on three of four videos the VLM call path is removed, not set to off. Where it still fires, the VLM receives the frame and the best retrieved sentence together and answers only "does this sentence cover the frame", one token of output, which is the cheapest referee that exists. Added: the VLM's job shrinks from describing every keyframe to a yes/no on the doubtful few, so even the surviving metered dependency costs a fraction.

### m03.r2.5 Take-out of the take-out: the audio tower decided by one silent-film number, and the sound tag lives on the speech-gap window only
Builds on: m03.r1.6 + m02.r1.5 + m01.r1.6
Both r1 versions admit the tower with a test on non-speech windows with visual change above the median. Cut it down further: one number on the short film, the share of such windows where the storyboard row changes if a tag is added, taken from the cached embeddings in m01.r1.6 before any tower is wired in. Below a stated share, record "audio tower: not needed" in the bench and delete the audio idea; above it, ship only the tag line on those windows and nothing else (no curve, no `find --audio`). Added: the answer is written down either way, so the question is not reopened every time a new model release makes audio sound attractive.

### m03.r2.6 Fresh: the user's last sentence, "analyse the video", as the only acceptance test
Builds on: m03.r1.3 + m02.r1.3 + m01.r1.2
Reading all three, every score is about frames, but the user's goal ends at the agent's analysis of the video. Make the final bench question a whole-video one: the agent gets only the sheets plus storyboard and writes a summary; the summary is graded by `check` (holes and unsupported claims) and by the QA items answerable from it, paired against the random arm with the sign test. Added: the metric covers the full chain the user described (find, grid, send, analyse), and a feature that raises frame-level scores but not the summary score is, by this test, outside what was asked.
