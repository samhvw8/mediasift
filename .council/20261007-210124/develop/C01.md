## C01 Narration redundancy score per keyframe

## The concept

**Who it is for.** The agent harness that reads framesift output, and Sam, who pays for every image it looks at. A lecture or explainer has many frames where the speaker is simply saying what the slide shows. The agent pays image tokens for them anyway, 12 to a sheet.

**What it is.** For each keyframe, framesift asks one question: does the speech around this frame already say what the frame shows? It answers it with a single number from EmbeddingGemma 2, which puts text and images in one space. That number does three jobs.

1. **Sheet demotion.** A frame whose narration covers it stays in `frames/` but leaves the contact sheet. Promoted frames fill the freed cells.
2. **Caption by retrieval.** The matched transcript sentence becomes the frame's caption. The storyboard prints it as `says: "..." (cos)` under the frame, so the agent sees why an image is missing and can ask for it.
3. **Storyboard tag.** Each segment gets `visual: redundant | adds`. The `meaning` VLM captioner runs only on frames that fail the match (later stage, below).

**What stays surprising.** Today's pipeline spends tokens by how much the pixels changed. This spends them by how much the picture says that the words do not. The signal is "the image adds nothing beyond speech", which pixel statistics cannot see. The same score also names the frames the speaker points at without describing ("as you can see here"), and those are the frames to show first.

**Refinements taken from the parent ideas:**
- It runs only on speech-bearing segments. Animation and silent film get no score, and the storyboard says so (m01.r1.1).
- It is judged by outcome, not by hand labels. The test is whether it predicts the questions the agent answers correctly with text only (m01.r2.2).
- The VLM is retired by a measured fire-rate, not by a decision. The call path is removed only when the VLM would fire on a stated small share of frames on 3 of 4 bench videos (m02.r1.4, m03.r2.4).
- Default output becomes text-first. The rows carry the tag and the retrieved sentence, and images are what the agent pulls (m02.r2.1).

## How it works

Inputs already exist: keyframe files from `keyframes.py`, cues from `transcript.py`, segment boundaries from `segment.py`.

1. **Embed** (once, vectors cached in `signals.npz` as float16, 256 dims). Text and vision towers only: the 440M load per the developer guide. Embed each cue with `prompt_name="Document"`. Embed each keyframe as an image, no prompt. Cues are split to sentence or about 10 s windows, so one embedding does not mix topics.
2. **Candidates.** For a frame at time t, the candidate sentences are those within the frame's segment plus a margin of about 10 s. That is a handful of sentences, not the whole transcript.
3. **Score by rank, not raw cosine.** Cross-modal cosines are low and sit in a narrow band (the modality gap), so a fixed cutoff like 0.3 will not transfer between videos. Use two relative numbers:
   - `z`: the best candidate's cosine, z-scored against all frame-to-sentence cosines in this video.
   - `margin`: best minus second-best cosine, and whether the best sentence is the *temporally adjacent* one. If a frame matches a sentence from 2 minutes away better than the speech beside it, the speaker is not describing it (a recurring slide, or a talking head).
   - Redundant = `z` high and the best match is local. Adds = `z` low, or the best match is far in time. This is a rank test over this video's own vectors and needs no tuned absolute number.
4. **Guard rails against the known failure.** Semantic embedders collapse detail: SigLIP2-class models score about 20 on instance retrieval where DINOv2 scores about 51 (earlier research, `research/261001-models/en-embeddings.md`). A slide full of numbers and a speaker saying "the numbers on the slide" will look redundant. So:
   - Never demote a frame the pixel pipeline marks text-dense or changed (existing edge-block statistics).
   - Demotion only drops the cell from the sheet. The file stays in `frames/` and is named in the storyboard.
   - Flag it, do not delete it: the tag carries the cosine so the harness can overrule.
5. **Output.**
   - `render.contact_sheets` takes the keyframe list after demotion. Cell count falls, and `--max-frames` can then be spent on promoted frames.
   - `storyboard()` adds one line per demoted frame: `- 142.0s demoted, says: "…" (z=1.8)`, and a per-segment `visual:` tag.
   - `manifest.json` gets `redundancy` per keyframe (z, margin, matched cue id). Segments with no speech get `redundancy: null` and a storyboard note, never a silent default.
6. **Later stage (only if the numbers allow).** In `meaning.py`, skip the VLM describe call for frames with a strong local match and use the retrieved sentence as the description. If the fire-rate stays low, remove the VLM path. Until then it is a fallback.

## First move

This week, one script, no pipeline changes: `bench/redundancy_probe.py`.

1. Load EmbeddingGemma 2 (text + vision, 440M) through sentence-transformers on the Mac.
2. For `cs50_lecture.mp4` and `python_100s.mp4`, embed existing keyframes and cues. Write per-frame `z`, `margin`, locality and matched sentence to a CSV. Record seconds per image and per sentence, since throughput on Apple Silicon is not yet known.
3. Print the 15 highest-score and 15 lowest-score frames beside their matched sentences, and read them. This takes about an hour and answers whether the score is even sensible before any test is run.

## What must be true, and the cheapest test

**What must be true**
1. The score ranks "speech already covers this frame" above chance, on talking-head, lecture and slide content.
2. It survives the detail-collapse problem: it does not mark frames as redundant that carry facts the speech lacks (code, numbers, diagrams).
3. The text-only baseline actually answers some questions correctly. If the agent already needs every image, there is nothing to demote.
4. Embedding cost on a Mac is small next to the work saved.
5. Vietnamese and other non-English speech scores sensibly (unknown; English-first is acceptable, but the tag must be skipped, loudly, where it has not been checked).

**Cheapest test (judged by outcome, from m01.r2.2)**
1. Reuse `bench/prep_qa.py` conditions: A (transcript only) and C (storyboard plus sheets). For each existing question, find those answered correctly with A alone. That set is the "speech already says it" class. It costs nothing new and removes the hand-labelling session m01.r1.1 planned.
2. Compute AUC: does the segment-level redundancy score separate the A-correct questions' frames from the A-wrong ones? Under about 0.7, the whole family (demotion, caption skip, tag) is dropped together, as m01.r1.1 said.
3. If it passes, run the real arm: demoted sheets vs current sheets vs a random-frames arm at equal image count, comparing accuracy and tokens per correct answer, with a paired sign test (m01.r1.2, m03.r1.2). The feature stays only if it beats random at equal tokens.
4. Instance-detail probe: take the 40 same/different slide pairs idea (m01.r1.2) and check that no frame on a text-dense slide is demoted without the narration containing its key terms. A caveat on size: a QA set of a few dozen questions on 4 videos gives wide error bars, so report per-question wins and losses, not just means.
5. Kill test for the caption path (m01.6): have the VLM caption 30 high-score frames and judge whether the retrieved sentence agrees. Under about 70% agreement, the retrieval caption is dropped and only demotion remains.

**Expected honest outcome.** I expect it to work on lecture and explainer, where speech and slides track each other, and to do nothing on animation and film, where it is off by design. I have no measurement of any of this. I could not find a published number for how well a shared-space cosine predicts "the narration already covers the frame", so the AUC is the first evidence.

## Prior art (with URLs)

- **Closest in spirit, MIT "Visual Transcripts"** (Shin et al.): turns blackboard lecture video into notes that interleave visuals with text and "hides redundant information". It does the same job with hand-built pixel logic and OCR/speech alignment, not a shared embedding. https://people.csail.mit.edu/hishin/projects/visual_transcripts/paper.pdf
- **CLIPScore**: shows an image-text model can score image-caption agreement without references, which is the mechanism this uses (the frame is the image, the sentence is the caption). It scores captions against images for evaluation, not for choosing which frames to send. https://arxiv.org/abs/2104.08718
- **Query-conditioned frame selection**: Focus (https://arxiv.org/html/2510.27280v1) and Adaptive Keyframe Sampling (https://arxiv.org/html/2502.21271v1) pick frames by relevance to the question, with coverage. PruneVid (https://arxiv.org/abs/2412.16117) prunes tokens by question attention inside the model. All of them need a question and optimise for relevance. None compares frames to the video's own narration to *drop* frames the speech covers, and none produces the demotion tag for an agent that has not yet asked anything.
- **Redundancy in instruction** (educational psychology): the redundancy effect, where presenting the same content in two forms can hurt learning. It supports the premise that showing both is not free, but it concerns people, not model tokens. https://www.sciencedirect.com/science/article/pii/S0361476X06000294
- **Model facts**: EmbeddingGemma 2 loads as 270M text, 440M text plus vision, 570M text plus audio, 740M full; MRL to 128 dims with about 95% of image/video/speech retrieval quality kept at 256; text uses `SearchQuery` and `Document` prompts; images are embedded with no prompt. https://developers.googleblog.com/en/embeddinggemma-2-the-developer-guide/ and https://ollama.com/library/embeddinggemma-2

**What is still different.** I did not find an existing tool that scores keyframe-vs-own-transcript redundancy to shrink what an agent is sent. Not finding one is weak evidence, since the search was short. I recalled Informedia-style video skimming from the parent notes but did not verify it, so it is not cited.

## What it costs to run

- **Infra:** no metered service. Runs locally on the existing machine. The VLM call volume falls if the later stage lands, which is a saving on the one metered dependency.
- **Compute per video:** one vision embedding per kept keyframe (hundreds, not thousands, since keyframes are already sparse) plus one text embedding per cue. Throughput on Apple Silicon is unmeasured and is the first thing the probe records. Peak memory should be the 440M load. The audio tower is not loaded.
- **Storage:** a few thousand float16 vectors at 256 dims is under 3 MB in `signals.npz`. This is shared with other proposals that store vectors, so the cost is not additive.
- **Operational:** one more model download (about 440M parameters, size not checked) and a model-version pin. A wrong model version changes scores silently, so the manifest records the model id and dim, and a mismatch fails loudly instead of mixing vectors.
- **Maintenance:** adds a small set of knobs (local margin, `z` cutoff, text-dense guard). Only the `z` cutoff and the guard are tuned numbers. The rank design keeps them from needing per-video tuning. The tag and demotion rules must be kept in sync with the sheet code and the SKILL.md wording, so the agent knows a missing cell is not a missing scene.
- **Risk if wrong:** a demoted frame the agent needed. The cell is gone from the sheet but the file and the quoted sentence remain, so the failure is a visible extra pull, not a hidden loss.

**Runs:** nothing new as a service. It adds the EmbeddingGemma 2 text and vision encoders as a local dependency, shared with the other embedding proposals.
