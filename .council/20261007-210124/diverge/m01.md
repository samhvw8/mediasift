## Baseline (the obvious answers)
- Near-duplicate frame removal in the grids using embedding cosine (a variation of the proposed veto).
- Auto-title chapters / storyboard rows by nearest-text retrieval against the transcript.
- Use the audio tower for speaker/music/sound-event tagging.

## Assumptions I broke
- "Adding the model to the pipeline is the extension": the cheapest, highest-value use may be offline, on the bench only, to calibrate or audit existing pixel heuristics. Nothing ships per run; the running cost is zero. Lens: ask which claim is unobserved, run one 30-minute experiment on the 4 sample videos, and build only what survives.
- "One model applied uniformly to every video, frame and stage": the brief itself says semantic embedders collapse layout (SigLIP2 ~20 vs DINOv2 ~51 on instance retrieval). Local quality: screen recordings and slides get no embedding (pixels already win), camera footage gets full-frame semantics, text/audio towers run only where the other signals are blind, and MRL dims differ per stage.

## Ideas
### m01.1 Embedding-per-drift ratio as the screen-vs-camera detector (delete a heuristic knob)
Embed 1 fps frames from each bench video, then compute (embedding distance) / (pixel drift) over consecutive frames. A screen recording should show high pixel drift and low meaning shift (scrolling, typing); camera footage the opposite. If the ratio separates the 4 bench videos, it replaces the hand-tuned screen-vs-camera decision in screen-vs-camera.md with a measured per-video number, and the same number sets the veto threshold. Test: one scatter of 4 videos, about 3 minutes of embedding; if the clusters overlap, the idea dies cheaply.

### m01.2 Instance-detail probe before any build (settle the layout-collapse risk)
Take the lecture video's near-identical slides (same template, different text or diagram) and the animation's repeated shots, then compare embedding cosine to a pixel/DINO-style distance on labelled "same/different" pairs from keyframes the bench already marks. Verdict decides the local policy: if EmbeddingGemma 2 merges distinct slides (cosine above 0.95), it is banned from screen content and only the pixel path decides; if it separates them, the veto can extend to screens. This is a gating experiment: a hand-labelled sheet of about 40 pairs and an ROC number.

### m01.3 Audio tower only on the speech gaps (local quality for ASR blind spots)
Whisper and parakeet are blind or hallucinate on non-speech stretches (music, laughter, applause, silence with sound). Run the audio tower only on windows the VAD marks as non-speech, and zero-shot rank a short fixed label list ("music", "applause", "crowd", "typing", "silence") by cosine. The agent gets a one-line tag in the storyboard instead of nothing or a hallucinated transcript. Test: count whisper hallucinated words on the non-speech windows of the 4 bench videos, compare to label accuracy on 20 windows I listen to; cost is audio only where it is otherwise empty.

### m01.4 Text-picture agreement score: tell the agent when it can skip the image
For each segment, embed the transcript chunk and the keyframes, take their cosine, and put it in the storyboard as `visual: redundant | adds`. High agreement means the speech already describes the picture, so the grid cell can be dropped or shrunk for token cost; low agreement means the picture carries information the audio does not (a diagram, a demo). Test on bench/prep_qa.py: drop frames from high-agreement segments, re-run the QA questions, and see if accuracy holds while image tokens fall. This is a per-segment decision instead of a global --max-frames.

### m01.5 Variable-size cells by within-segment spread
Instead of 12 frames per sheet for every segment, size the grid per segment by the embedding spread of its keyframes (tight cluster: 1 or 4 cells; spread: up to 12). It differs from proposal 2 (a global k-center budget) because the budget is allocated per segment by how much meaning varies there. Cheapest proof: for each bench segment, plot spread vs number of QA questions that needed more than one frame; correlation must exist before any rendering is changed.

### m01.6 Retrieve a transcript sentence as the frame caption (shrink the VLM bill)
For each kept keyframe, caption it by the nearest transcript sentences in the shared space (text tower vs image tower) and let the VLM `meaning` step run only on frames whose best match is weak. Speech-heavy video (lecture, explainer) then pays for the VLM on a small fraction of frames. Test: on the lecture and explainer, measure what share of frames have cosine above a threshold, and have the VLM captions on a 30-frame sample judged against the retrieved sentence; kill it if agreement is under about 70%.

### m01.7 Per-stage MRL dimension chosen by recall, not taste
Use 128 dims for the veto and k-center (many comparisons, coarse meaning), 768 only for `find`. Do not argue it; run it: for the bench, compute recall@k of the top-10 frames per query at each of 128/256/512/768 and pick the smallest dimension within 1 point of full. Also shrinks signals.npz by 6x. Needs 20 queries written once, and the same sheet also validates proposal 3.

### m01.8 Embedding as a regression alarm in the bench
Log the mean pairwise cosine and veto-drop rate per bench video in bench/evaluate.py output, and fail the bench when it moves more than a set margin between commits. It does not change what the agent sees, but it turns the model into an operational check that a heuristic change did not quietly shift what is dropped. Cost: one embedding pass per CI run, no hosted service.
