## Baseline (the obvious answers)
- Embed every keyframe and search it with text (`find`), which is already proposed item 3.
- Use embedding distance to dedupe or veto near-duplicate keyframes, already items 1 and 2.
- Swap MiniLM for the EmbeddingGemma 2 text tower and keep one vector store, already items 4 and 5.

## Requirement trace (the lens deliverable)
The user's end goal has five parts: (a) extend use of the model, (b) find the best frames, (c) build image grids, (d) send them to the agent harness, (e) the agent analyses the video from them.

| Requirement | Status | Evidence |
|---|---|---|
| (a) extend model usage | met, over-met | five proposals, but two are only plumbing (4, 5) |
| (b) best frames | partly met | 1 and 2 define "best" as "distinct" and 3 as "matches a query". Nobody defined best for what task |
| (c) image grids | partly met | only 3 produces a grid, and only on demand. The default sheets stay chronological, 12 per JPEG |
| (d) send to the harness | missing | no proposal changes what the harness receives, in what order, or at what token cost |
| (e) analyse the video from it | missing | nothing checks whether the grids were enough. `meaning` still captions via a separate VLM |

Added that nobody asked for: item 4 (chapter segmentation was never mentioned), item 5 (storage is plumbing), and any use of the audio tower (not asked for, 300M of weights to load).
The goal was quietly redefined from "get the harness to understand the video" to "make keyframe selection better". Those are different: selection is an input, the grid and the analysis loop are the ask.

## Assumptions I broke
- The model's job is to improve selection (which frames survive): the ask ends at the harness, so the model's biggest lever is what the harness is shown and in what arrangement, not which frames pass a veto. Take the veto out and the grid is still the product.
- The VLM `meaning` step stays and the embedder sits beside it: the user wants the harness to analyse, and the harness already has a vision model. A second VLM that captions frames is a running cost that the harness duplicates. The lens removes the duplicate rather than adding to it.
- "Best frame" is a property of the video: it is a property of the video plus the question being asked. Nobody asked what the agent is trying to find out.

## Ideas
### m03.1 Delete the `meaning` VLM; the embedder plus the harness replace it
Technique: take out the part that causes the harm. `meaning.py` sends keyframes to an OpenAI-compatible VLM, which is a metered or hosted dependency and a second model to keep in sync, and the consumer is already a vision model. Keep only what the VLM added that the harness cannot do cheaply: chapter titles and "what changed" text. Get chapter boundaries from the text tower and let the harness name the chapters from the sheets. Bench proof: QA accuracy on the 4 sample videos with sheets only vs sheets plus VLM captions; if the gap is under noise, the VLM code and its config knobs go.

### m03.2 Goal-conditioned sheets: pass the question at analyze time
"Best" needs a referent. Add an optional `--ask "why does the build fail?"` that embeds the question once and reorders and budgets the sheets around it: cells most relevant to the question first, with a few coverage frames kept so the agent is not blinded. This turns `find` from a second command into the default behaviour, and the agent gets one set of sheets instead of two round trips. Not obvious because it makes the search query an input to the sheet layout, not a lookup afterwards.

### m03.3 Meaning-ordered grids: a sheet is a thought, not a time slice
Today a sheet is 12 consecutive keyframes. Instead cluster the keyframe vectors and give each cluster its own sheet, one cell per distinct meaning with timestamps in the labels, so a returning shot (host cutting back) appears once with all its times. The harness reads a sheet as "everything that looks like this" and spends fewer image tokens on repeats. Proof: tokens per correct QA answer, chronological sheets vs cluster sheets, on the lecture and explainer samples.

### m03.4 Close the loop: `framesift check` returns what the analysis did not cover
After the harness writes its summary of the video, it passes that text back. framesift embeds each summary sentence and each segment and returns the segments no sentence is near, as a small sheet. This is the missing requirement (e): it tells the agent where its analysis has a hole instead of trusting it. It also gives the bench an automatic score with no human labels: coverage of segments by summary text. Cost: one text-tower pass over a few paragraphs.

### m03.5 Drop frames the transcript already says
Embed each transcript window and the keyframes in the same space. A frame whose nearest text neighbour is the speech right beside it adds little for the harness and can be dropped from the sheets (kept in `frames/`). A frame far from its speech is the "as you can see here" moment and moves to the front. This cuts image tokens by deleting redundancy across modalities, which pixel statistics cannot see. Risk to test: the model may rate a talking head and a speech about it as aligned, so check it on the lecture sample before trusting it.

### m03.6 Medoid, not sharpest: let the vectors pick the representative frame
The keyframe pick today waits for "the most stable, sharpest frame in the next 0.6 s". Replace the pick inside each stable run with the frame nearest the run's mean vector. That deletes one knob (the 0.6 s sharpness window) if it matches, and costs embedding more frames. Prove it by ablation: same keyframe count, compare QA accuracy. If the semantic embedder collapses layout (SigLIP2-style ~20 instance retrieval), the medoid may pick a worse screen frame, so keep the old pick for screen recordings.

### m03.7 Vision and text towers only: leave the audio tower out of scope
The brief invites all of the modular encoders, but only picture and text serve the stated goal, and audio already has a cheap, adequate log-mel path at ~500x realtime. Loading the 300M audio tower adds RAM, a load step and a failure mode for a goal nobody stated. Ship the text and vision towers, record the audio tower as a rejected extension with the reason, and revisit only if a bench video fails on audio-only changes. This idea is a subtraction that protects the maintenance weight.

### m03.8 The bench gate: no idea ships without a tokens-per-correct-answer number
Every proposal above, and the five earlier ones, is currently justified by reasoning. Make `bench/evaluate.py` report one number per config: image tokens spent per correctly answered QA item, over the 4 sample videos. A change stays only if it lowers that number or deletes a knob at equal number. This is the requirement "make the agent understand better per token", measured instead of assumed, and it settles m03.1, .3, .5 and .6 cheaply.

## The provocation I would put to the group
The user asked for a better way to hand a video to an agent, and we are answering with a better way to pick frames: if the embedder never changed which frames survive but only how the grid is arranged and checked, would we have delivered more of what was asked?
